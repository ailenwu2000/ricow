> 名称与对外表述(2026-09-15 定): **ricow**(中文名 **富牛**);对外一句话 **从灵感，到规则，到实盘。** / *From idea, to rule, to live.*
> —— 该句用于描述产品流程(灵感 → 规则(过回测门禁) → 实盘), 仅作对外表述, **不另加称谓**(2026-09-15 用户明确)。

---

## 一、一句话定位

**完全本地运行的量化策略终端: 私钥不出本机, CLI 让策略跑起来; 提供回测、Dry Run、实盘三阶段全流程, 策略可审计、可追溯。**

## 二、目标用户

| 优先级 | 用户 | 核心诉求 | 主要入口 |
|:--|:-----|:-----|:-----|
| 主 | 有加密交易经验的散户/半专业交易者 | 不信任云端托管 API key; 不想折腾 VPS/Docker; 要现成策略一键跑 | CLI / AI / Web |
| 次 | 会写代码的进阶用户 | 快速把想法变成可回测、可运行的策略 | CLI / Lua |

> 与旧 product.md 的差异: 主用户不变; 入口 = 纯 CLI(`ricow`) + **内置 AI 助手**(`ricow ai`, 019-ai-assistant) + **本机网页**(`ricow web`, 025-web-ui —— 同一会话引擎的第二个前端, 浏览器里完成全部对话与操作)。
> AI 助手把"无开发能力的中文用户"纳入主用户面: 用自然语言完成策略生成/调试/回测/Dry Run/demo 运行, 写实动作仍由用户本人确认执行。
> GUI 不做; Telegram 后置; **MCP 不做**(2026-09-15 定案, 见 D12 修订 2): 单机程序, 用户已有的 AI agent 可直接调用本机 `ricow` 命令, 生态入口只做 `ricow agent-kit` 手册。

## 三、核心场景(用户旅程)

1. ~~**横截面选币**(`ricow scan`)~~ ⚪ **已删除(2026-09-15)**: 该场景从产品范围移除(020-platform-scope-trim) —— 平台聚焦"跑策略", 不做选币推荐
2. **开箱即跑**: 装好后选交易对 → 选策略预设(网格/DCA/TWAP)→ **默认 Dry Run** 观察虚拟成交 → 确认后切实盘
3. **自定义策略(Lua)**: 编写 Lua 策略 → 编译门禁 → 沙箱回测 → 报告 → 用户确认 → 部署运行 —— **已落地**(002-ai-quant-researcher: `ricow create` → `ricow approve` → `ricow deploy`; 代码可来自 AI 客户端(读 `specs/lua-api.md` 自行编写)或本地文件, 部署三步不可跳过, 部署后首次实盘还需 Dry Run 满 `min_dry_run_hours`)
4. **随时管理**: 多策略启停/查看盈亏; 成交通知 —— **已落地**(003-notifications: 策略 TOML `params.notify_webhook` 配置用户自选通道, 三类事件=成交/接近强平/停机残留(原"熔断"事件随平台亏损熔断于 2026-09-15 一并删除); 通道用通用 POST webhook 以守住"数据不出本机", 详见该档案)
5. **高级买卖**: 限价回调买/卖(激活价 + 回调幅度)、阶梯买/卖(档数 + 价格区间 + 分布)、时间分批(TWAP)
6. **本地复盘**: 成交、PnL、K 线全部落本地 SQLite, 数据不出本机

## 四、差异化支点(竞品数据支撑)

1. **"本地私钥 + 量化策略/回测 + 回测门禁 + Dry Run 默认" 无直接竞品**。竞品调研: 六家商业 MCP(Coinrule/WunderTrading/Katoshi/Pionex/Cryptohopper/Gainium)全是云端账号侧; 本地密钥阵营(Tealstreet/Dexari)是手动终端、无量化。→ 这是我们的护城河, 宣传时作为一级卖点。
2. **"AI 生成可回测代码 + 回测门禁 + 确认部署" 无人占位**。竞品 AI 三派: agent 自主构建(3Commas QuantPilot)/ agent 矩阵(Pionex.AI)/ 对话助手(Gainium Max Gain); LLM 直接决策下单派(NOFX/OctoBot)不可回测不可审计。我们 = 代码门禁 + 沙箱回测 + 安全确认(引擎能力已备, 对话式入口远期可选)。
3. **回测是行业普遍弱项**(调研事实: Jesse 对 Hyperliquid 关闭回测、Freqtrade 期货回测限 5000 根)→ 本地增量 K 线库 + 本地回测是明确卖点; 该结论是行业事实, 与本产品支持的交易所范围无关(2026-09-12 起仅支持币安)。
4. **竞品 MCP 行业标配化, 但形态与我们不同**(2026-08: Pionex 发 .mcpb、Cryptohopper 上线 MCP、Gainium "speaks MCP" 并整体开源)。
   实测: 六家商业 MCP **全是云端账号侧**(AI 在云、账号在云, MCP 是它们唯一通路); 唯一自托管型(Hummingbot MCP)59★、2026-03 后无提交。
   → 本机形态下**不做 MCP**(2026-09-15 定案): 用户已有的 agent(Claude Code / Codex / Cursor 均带终端)直接调用本机 `ricow` 命令即可, 生态入口 = `ricow agent-kit` 手册; Telegram 仍不做。

## 五、产品形态: 一个引擎, CLI + Web 入口

```
         ┌───────────── 用户 ─────────────┐
         │                               │
         └──►  ricow CLI     ricow web ◄─┘
         │    (clap, 技术用户)  (本机网页, 025) │
         └───────► 同一策略引擎 ◄─────────┘
                  (headless, 本地)
```

- **CLI `ricow`**: 服务器 7×24 部署, 技术用户管理; 回测 / 策略管理 / 下单。**裸 `ricow`(019 R4)即入口** —— 无子命令时直接进对话, 其余子命令保留
- **Web UI `ricow web`**(025): 本机 `127.0.0.1` 上起内置网页(axum + SSE, 一次性 token 鉴权, 无 token / 错 token 一律 `401`), 浏览器里完成全部对话与操作 —— **与 CLI 同一会话引擎**(会话缝 `ai/session.rs` 的第二个 sink, 不复制任何 LLM 路径), 原有 CLI 功能零改动。布局 = 左侧竖长会话历史(持久化, 可新建/切换/删除, 重开恢复最近 20 轮上下文)+ 右侧对话输出区与输入区; 关键字/警告/出错按宿主标注的 `Severity` 着色, 量化术语点击弹解释; 界面**中英双语**, 语言与 CLI 共用 `[ui].lang`。明文密钥走独立通道, 不落库、不进对话流、不进浏览器存储。**不做**: 公网访问 / 多用户 / 账号体系 / 图表可视化 / 会话导出 / 前端构建链。
- **内置 AI 助手 `ricow ai`**(019): 交互/单次提问 + 只读工具 + 虚拟工具(生成预览、Dry Run 起停); **写实动作不作工具注册**(结构性边界)
  - **R4(2026-09-16)**: 首次运行走引导向导(供应商选择 + 密钥静默录入), 对话内**七动作**逐字确认后由宿主执行(部署 / 启停测试网 / 启停实盘 / 平仓停止 / 风险确认), 实盘三判据原样保留; 详见 019 spec §七 R4
  - **R5(2026-09-18)**: 对话体验重构 —— 中英双语(`[ui].lang` + `/lang`, AI 回复语言跟随)、每轮分隔线与轮次号 + `/history`、去术语化(不出现 `ricow xxx` 命令)、宿主持有菜单的选项式交互(菜单 A 5 项 / B 4 项)、**写操作全确认**(由 7 类扩为 **13 类**, 唯一入口 `request_write_confirmation`)。确认词**分渠道**: 对话 = 当前语言**口语词**(`确认`/`确定`/`同意` · `confirm`/`confirmed`), 终端 = **逐字长短语一行不改**; 详见 023 spec
- **`ricow agent-kit`**(019): 生成 AGENTS.md / SKILL.md 操作手册(与内置 AI 系统提示同源), 供用户已有的 agent(Claude Code / Codex / Cursor)按手册直接驱动本机 CLI; **不做 MCP**(2026-09-15 定案)
- Telegram 后置为远期可选, 当前不考虑(2026-08-24 决策)

关键原则: **CLI 单入口直连同一引擎与下单路径, 安全模型一致**(confirm + 固定下单频率护栏 + Dry Run 默认; 平台不做投资判断, 见 D15/D17)。

## 六、功能范围(少而精)

### 内置参考实现(1 策略样板 + 1 执行组件库, 随版本发布)

- **策略样板**: `strategies/builtin/shannon_rebalance.lua` — 香农动态网格(实时计算 + 主动成交 + 自适应波动), 唯一完整策略参考
- **执行组件库**: exec — 用户 Lua 策略可直接调用的执行函数(引擎内置 Rust 实现, 加载时注册为全局 `exec` 表, 无需 require, 脚本内可覆盖): `exec.levels`(阶梯档位) / `exec.pullback_triggered`(回调触发) / `exec.ticks_per` + `exec.slice_due`(分批节奏) / `exec.detect_quote`(报价资产) / `exec.side_order`(对手价订单)
- **执行模式示例**: `strategies/builtin/executors/{dca,twap,vwap,pullback,ladder}.lua` — 上述组件的独立可运行薄壳(CLI 直跑/旧 TOML 兼容), 复制即自定义

> 定位: DCA/TWAP/限价回调/阶梯是**执行算法(怎么买/怎么卖)**, 不是独立策略; 策略编写 = 信号逻辑 + 调 exec.* 执行。
> 自定义 Lua 策略(沙箱脚本 + AI 生成)为**扩展机制**, 不属于内置参考实现。

## 七、商业模式(2026-08 调整, 个人开源项目, 返佣主线)

- 软件**永久免费、零费率**: 本地功能全免费(回测/Dry Run/实盘), 开源获客
- **收入主线: 交易所返佣**(平台无关, 按返佣率与门槛优先支持)
  - 用户用 ricow 推荐码注册交易所 → 用户享手续费折扣、开发者拿手续费分成; 返佣主力 = CEX 现货 + 合约(币安 40-50%); 当前仅支持币安(2026-09-12 移除 Hyperliquid), 后续按返佣率与门槛扩展平台
  - 落地: 每交易所一个平台无关的 referral/affiliate 码配置, 不写死单一平台
  - 预期: 覆盖运维成本 + 零花钱量级, 靠用户基数被动放大
- **次要收入: 定制技术开发/集成**(按项目/小时收费)
  - 接特定交易所/数据源适配、私有化部署、风控规则、加 feature —— 明确技术交付, 不承诺策略收益
  - 不做"定制能赚钱的策略"(回测好≠实盘好, 无法承诺收益, 个人无企业壳隔离责任)
- **builder code 不做**(需用户主动授权多付费, 与免费定位冲突)
- **Vault 资管降级为远期可选**(dogfood 业绩好再评估)
- 其他: GitHub Sponsors(开源标配); 获客 = GitHub + X/Discord

## 十二、香农动态网格(shannon_rebalance)策略规格与风险提示(来源: 原 requirements 4.3.1, v4 扩写 2026-09-05)

**机制**: 建仓 = 一次市价买入 `target_ratio`(默认 0.5)权益;之后每 tick 按最新价计算总价值,
目标 = `权益 × target_ratio`(一半币一半现金之外可调), 精确恢复"目标比例"——价格涨 → 卖出回平衡(锁利),
价格跌 → 买入回平衡(摊成本)。策略不判断趋势, 方向判断 = 用户的 target_ratio 设置。

**参数表(用户按标的与风险偏好自行设置)**:

| 参数 | 默认 | 语义 | 增收益方向 | 降风险方向 |
|:--|:--|:--|:--|:--|
| pair | — | 交易对 | 高波动主流币(波动红利大) | 拒绝 meme/新币/高退市风险 |
| target_ratio | 0.5 | 目标持币比例(凯利锚近似);看涨长期 g>0 → >0.5 | 提至 0.6~0.7(涨市多吃) | 降至 0.3~0.4(跌市少亏) |
| rebalance_band | 0.005 | band 下限(价格当量须 > 2×双边费 0.2%);想整体更密/更疏调它;换 interval 复查量级: 1m/5m 参考 0.1%~0.3%、1h 0.3%~0.5%、1d 1%~2% | 调小逼近保本线(成交更频) | 调大(少交易) |
| atr_period | 14 | ATR 平滑窗口(根数;跨度 = period×bar 周期;0 = 禁用 ATR) | 调小(对波动更敏感) | 调大(更平滑、少假触发) |
| atr_mult | 1.0 | ATR 缩放系数;0 = 禁用 ATR(band 恒 = rebalance_band);仅对 ATR 分支生效,低波标的被 rebalance_band 兜底 | 调小(更密收割) | 调大(高波动期更宽、防摩擦) |
| pause_pct/pause_bars | 0/6 | 极端行情暂停(单 bar 涨跌≥阈值停 N bar) | — | 启用(如 3%~5%) |
| order_size | 0.01 | 建仓单大小 | 与 target_ratio 联动 | 不单独放大 |

**机制要点**:
- **band 自适应波动率**: band_eff = max(rebalance_band, atr_mult × ATR(atr_period)/price)。ATR 用的 K 线周期 =
  引擎所选 interval(1m/5m/15m/1h/4h/1d), 无需单独设置; `atr_period` 按根数调跨度(跨度 = period × interval 时长,
  换 interval 需重设 period: 如 1h 想要 1 天跨度取 24, 5m 取 288)。ATR 数据不足(冷启动)或 atr_mult=0 → 回退固定 band。
  高波动交易对自动放宽 band(防每 bar 触发、手续费吃光波动收割), 低波动由 rebalance_band 保底。
- **保本约束(硬性)**: band_eff 下限须 > 2×双边手续费(现货 10bps×2 = 0.2%), 否则单次再平衡净亏。

**风险提示(选品约束为强制前提)**:
- **选品约束(强制)**: 本策略只适合长期上涨的主流资产(如 BTC/ETH/BNB 等大盘); **拒绝 meme 币、新币、高退市风险资产**——标的长期下跌/归零时, 再平衡差价收益无法覆盖标的跌幅, 将持续亏损; 策略无止损功能, 风险由选品约束承担。
- **target_ratio 越高越接近满仓持有, 跌市回撤越大**(0.8+ 尤其显著); 比例设置 = 用户对标的长期方向的主观判断, 策略不二次判断。
- **建仓 = 用户主观判断**: 只有用户自己认为标的长线看涨时才应启动。
- 单边行情存在回撤风险; 如需对冲, 用户可在交易所自行购买期权/永续空单(ricow 不内置对冲功能)。
- **建议使用交易所单独子账号运行**: 策略会使用账号内大部分现金, 子账号隔离风险、独立核算。
