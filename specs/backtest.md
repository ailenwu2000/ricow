## 一、时间与可见性(无前视)

1. 数据 = OHLCV bar(1m~1d)。每根 bar 驱动一次策略 tick。
2. `on_tick` 发生在 **bar 起始**:策略只见当前 bar 的 open;close/high/low 属未走完的 bar,不可见。
3. 指标与 `ctx:klines()` 只含**已收盘** bar。
4. 权益估值按**已收盘 bar 的 close**;最后一根未收盘 bar 由报告补齐。
5. 违反以上任何一条 = 前视 bug,回归测试必须覆盖。

> 现状已符合(含 4 组回归测试),重构保留不动。

## 二、订单撮合(现货/合约共用)

1. **市价单**: 当根 bar 按 `open × (1 ∓ 滑点)` 成交(买上滑、卖下滑;滑点默认 0,参数可配)。
2. **限价单(挂单)**: 自下根 bar 起每根判触及 —— 买单 `low ≤ limit`、卖单 `high ≥ limit`;触及即按 **limit 成交**(请求价成交)。
3. **保守触及**: 成交价不优于限价;跳空越过(open 已优于 limit)仍按 limit(保守,不高估)。
4. **每根 bar 顺序**(确定性): ① 撮合已有挂单(reduce_only 单先) ② `on_tick` ③ 新市价单即时成交 ④ 收盘估值。
5. 每根 bar 每单至多成交一次;成交记 fill(价格/数量/费用/时间)。
6. **下单前护栏(004 接入, 2026-09-16 019-R5 收窄为仅频率护栏)**: 每笔下单请求先过 `OrderGuard`(回测 / Dry Run / 实盘同一装配)—— **固定下单频率上限 100 单/秒**(滑动窗口 1s, 计数对全部 pair 共享)。
   **平台不做投资判断**(2026-09-15 020 + 2026-09-16 R5): 原"两级亏损熔断"与 `RiskEngine` 四条**静态限额**(最大持仓 / 单日亏损 / 最小订单 / 最大滑点)均已删除 —— 盈亏/仓位政策属于策略, 策略用 `ctx:net_pnl()` / `ctx:equity()` 自管回撤/止损。
   护栏为**固定常量、不读任何配置**(无配置面), 被拒 → 返回 `Rejected` ack(与资金不足同形)并计入报告"拒单次数", 日志 `target=order_guard`, 策略循环不中断。
   参数面已删除: `[risk]` TOML 段与 `risk_*` 参数(`risk_max_orders_per_sec` / `risk_max_position_notional` / `risk_max_daily_loss_usd` / `risk_min_order_notional` / `risk_max_slippage_bps` / `risk_consecutive_loss_periods` / `risk_loss_period` / `risk_peak_drawdown_pct` / `risk_level1_enabled` / `risk_level2_enabled`)不再被读取 —— 策略 TOML 里若仍写着它们, 装在不报错但**不再生效**(serde 忽略未知键), 不做迁移脚本。
   时间源 = `ctx:now_utc()`: 回测用本 tick 的 bar 时间(可复现), Dry Run / 实盘用真实 UTC —— 语义一致, 时间源按运行态取值。护栏状态仅驻内存, 重启清零; 按策略实例独立核算。默认值依据: 内置脚本单 tick 下单数 ≤1(1m 粒度, `limit=1` 零拒单), 100/s 覆盖网格类"一次挂多档"且远低于风暴量级(参照 NautilusTrader 默认)。

> 现状已基本符合(freqtrade 同款"请求价成交"口径);重构仅补余额校验(§四)。

## 四、现货规则

1. 初始余额 = 报价币(quote;默认 USDT,**quote 跟随交易对报价币**,如 bStocks 现货=USDT(2026-09-06 实测,早前 USDC 认知已推翻)),金额可配。
2. 买: 需 `quote ≥ 名义 + 手续费`,不足 → **拒单**(市价单丢弃并记录,限价单保持 pending)。
3. 卖: 需 `base ≥ size`,不足 → 同上拒单。
4. 禁止做空;持仓 = base 余额;无杠杆、无保证金、无强平。
5. 已实现盈亏按 LIFO 配对(网格/分批买入卖出口径,禁均价口径)。

> Bug A 修复点: 余额校验必须在成交前,不足即拒,禁止静默"免费成交"。

## 五、合约规则(USDT-M,新增)

1. **账户结构**: 现金(quote)+ 每个交易对一个**逐仓钱包**(isolated margin,隔离粒度 = 交易对/symbol,币安语义)。**双向模式下同一交易对的多头与空头仓位共享该钱包**,保证金与强平按交易对整体判定;单向模式 = 同对仅允许一个方向仓位的约束特例。
2. **开仓**: 从现金划入该对钱包 `M = 名义 / 杠杆L`(手续费实扣);平仓: 该仓已实现盈亏结算回钱包(持仓清零且钱包不再被占用时余额回现金)。实现可等价简化为"占用保证金记账 + 组合权益判定",但语义以钱包共享为准。
3. **持仓模式(TOML 声明)**: `one-way`(默认)= 同对单仓,开反向仓先平后开(兼容现有全部策略);`hedge`(双向)= 同对多空并存,多空各自加仓/平仓互不影响(中性网格/对冲类策略用)。
4. **强平(简化模型,按交易对整体)**: 该对组合权益 `E = 钱包占用保证金 + 多空未实现合计 − 该对累计费`;当 `E ≤ MMR × Σ名义(多+空)` 时触发强平 —— 先平**浮亏仓**(平后若恢复则另一仓保留),仍不足再平另一仓。MMR 取**内置首档表**(symbol→首档,leverageBracket 实测;表外回落 1.0%),`--mmr-pct` 可覆盖(2026-09-05 修正: 原取 exchangeInfo `maintMarginPercent`=2.5% 实为深档误导值, 见 §十一 T7; 单仓时本判定与标准逐仓强平价公式恒等)。
5. **资金费率**: 默认启用,按 `Σ各仓名义 × funding_rate` 每 8h 结算一次(结算点 = bar 覆盖时段 `[open, close)` 内的 UTC 00/08/16 边界, 与 interval 无关: 1m~4h 恰 1 次、1d 恰 3 次; 013 FR-004 修正);默认费率 0.01%/8h(参数化,可设 0 关闭)。盈亏计入权益曲线。**hedge 模式两侧钱包独立结算**(多头付、空头收, 不跨侧抵消; 013 FR-003)。
6. **权益曲线**: 现金(未占用)+ Σ各对钱包权益;每已收盘 bar 估值。未实现 = `(close − entry) × size × 方向`。
7. **一策略一市场**: 单个策略 TOML 声明市场类型(spot/futures),现货与合约账户隔离,不混用。
8. 合约报告额外输出: 杠杆 / 资金费净额 / 强平次数;hedge 模式多空分列。

## 六、报告与指标

1. 报告内容: K 线数 / 成交笔数 / 已实现盈亏 / 手续费(占比)/ 拒单次数(`rejected_count`, 资金不足或无仓可平, 如实计数)/ 最大回撤 / 净盈亏 / 胜率。
   合约另出: 杠杆 / 资金费净额 / 强平次数 / 名义敞口(`final_notional`)与变化%(`nominal_exposure_pct`)。
   组合口径另出: 净值曲线(`equity_curve`)/ 换手率(`turnover_ratio` = 单边成交额 / 平均权益)/ 组合持仓快照(`holdings_snapshots`)。
2. 指标全集(口径不变, 沿用 2026-08-31 实现与回测指标实测教训): 年化收益(几何)/ 年化波动 / 夏普(rf 默认 3.8% 可配)/ 索提诺 / Calmar / 盈亏比 / 平均盈亏。
3. 资产变化 4 指标(建仓后为基准): 标的涨跌% / 持仓币数变化%(合约以名义敞口变化替代, K8)/ 现金变化% / 总价值变化%(含未实现)。
4. 年化因子按每 bar 时长精确折算(`bar_span_sec = span/n_bars`),禁天数近似。
5. 指标口径文档 = 本规范 + 实现注释;grid-trading-strategy skill references/backtest-metrics.md 为设计依据。

## 七、复杂度清单(默认不集成,逐项需讨论拍板)

| # | 复杂规则 | 为何不默认 | 集成条件 |
|:--|:--|:--|:--|
| 1 | 全仓(cross)保证金,跨交易对共享 | 状态耦合,逐仓(钱包按交易对)已覆盖主流网格/策略;双向下逐仓已天然"同对一起" | 有真实需求(多对组合高杠杆)再议 |
| 2 | 币安维持保证金率按名义规模分层 / 部分减仓 | 用**内置首档表**单层近似(首档对名义 <5万 USDT 的主流回测恒成立;深档只影响超大名义),误差仅在超大名义时显著 | 出现强平价临界失真案例 |
| 3 | 保险基金 / ADL 自动减仓 | 强平滑出价 = 破产价,需逐档建模 | 做市/高杠杆策略回测时 |
| 4 | 真实历史资金费率 | 需额外数据源与同步 | 合约策略上线前(费用精度敏感时) |
| 5 | intra-bar 价格路径(tick 重放/taker 深度) | 数据需求大,OHLC 撮合误差可接受 | 高频/做市策略 |
| 6 | bar 内 high/low 先后(先高后低 vs 先低后高) | 保守假设下影响小(止损用 low-before-high) | 需要精确止损/止盈同 bar 竞速时 |
| 7 | 部分成交 / 冰山 / 最小数量精度 | 整单成交 + 下单前参数校验已够 | 大单滑点敏感策略 |
| 8 | 标记价与指数价偏差 | 收盘价近似 | 合约强平价精确性要求高时 |
| 9 | 限价单 gap 成交(open 优于 limit 按 open) | 按 limit 更保守 | 用户要求更贴近真实时(易实现,可后加) |

> 默认策略: 一律不集成;§七 9 项中任何一项如要集成,单独讨论后决定,不进默认引擎。
