# 功能规格: 密钥管理页(多套 AI / 币安密钥, 别名可选用可删除)

**功能目录**: `specs/changes/033-key-manager`

**创建日期**: 2026-10-02

**状态**: 草稿

**输入**: 用户描述: "UI上面增加一个可以配置AI API-key的选项（页面的左侧，可以选择各家的API key）,API key用别名显示，这样用户假如有多个API key 可以选择使用。同时也增加一个币安的key选项，用户可以设置或者删除自己的币安key。"

**前置依赖**: 032-web-ui-console(Web 工作台五视图 / `/api/config/keys` / `[ai]`·`[exchange]` 段读写)。

## 一、问题与目标

032 的「设置」页把密钥写成**唯一一份**生效值: `[ai].api_key` 一把、`[exchange]` 主网+测试网各一套。
实际使用中这有三个痛点:

1. **换 key 要重新粘贴**: 用户同时持有 DeepSeek 与 Kimi 两把 key, 想按任务切换, 现在只能删一个填一个;
2. **看不见是哪一把**: 页面只显示"已配置 · 尾号 xxxx", 多把 key 并存时无法辨认谁是谁;
3. **删不掉**: 密钥框留空 = "本次不修改"(FR-008 的有意设计), 于是**没有任何入口能清除已保存的密钥**。

本变更给密钥加一层**密钥环(vault)**: 每套密钥是一个带**别名**的条目, 可保存多套、随时**选用**、随时**删除**;
左侧导航新增独立「密钥」页承载它。

**范围外(明确不做)**: 不做密钥加密存储(仍依赖 `ricow.toml` 的 0600 / icacls 收紧, 与 019/032 一致);
不做密钥轮转/到期提醒; 不做多交易所(项目当前只有币安)。

## 二、用户场景与测试 *(必填)*

### 用户故事 1 - 保存多套 AI 密钥并按别名选用 (优先级: P1)

小张有 DeepSeek 与 Kimi 两把 key。他打开左侧「密钥」页, 在「AI 通道」里点「+ 新增」, 别名填"工作号 DeepSeek"、
服务商选 DeepSeek、粘贴 key, 保存; 再新增一条"备用 Kimi", 服务商选 Kimi、粘贴另一把 key。
条目按别名列在左侧列表里, 他点"工作号 DeepSeek"那行的「选用」, 该条被标为"使用中";
此后对话与 AI 改策略走的就是 DeepSeek。想换成 Kimi 时点另一条的「选用」即可, 无需重填任何字段。

**优先级理由**: 这是本变更的全部价值 —— 多套密钥的存在意义就是"能切"。

**独立测试**: 打开密钥页 → 新增两条不同服务商的 AI 密钥 → 两条都出现在列表且尾号正确 → 选用其中一条 →
`ricow.toml` 的 `[ai]` 段 provider/model/base_url/api_key 与该条一致 → 页面上该条显示"使用中"、另一条不显示 →
重新打开页面 (重新拉取) 状态保持 → 切到另一条后 `[ai]` 段随之改变。

**验收场景**:

1. **给定** 空白的密钥环, **当** 用户新增别名"工作号 DeepSeek"(服务商 deepseek)并保存, **则** 条目落盘到 `ricow.toml`, 列表立即出现该别名, 密钥框只显示"已配置 · 尾号 xxxx"
2. **给定** 已有一条"工作号 DeepSeek", **当** 用户再新增别名重复的条目, **则** 保存被拒绝并明确说明"别名已存在", 磁盘不被改写
3. **给定** 多条 AI 条目, **当** 用户点某条「选用」, **则** 该条的 provider/model/base_url/api_key 写入 `[ai]` 段成为当前生效值, 其余字段(如 max_turns)不受影响
4. **给定** 某条正在"使用中", **当** 用户修改该条的模型名并保存, **则** 生效配置同步跟随(不留旧值), 页面仍旧显示"使用中"
5. **给定** 别名留空 / 含换行 / 超过长度上限, **当** 用户保存, **则** 被拒绝并给出具体原因
6. **给定** 服务商是内置预设(如 deepseek), **当** 用户不填接口地址, **则** 保存成功且选用后按预设默认地址生效(与 `[ai]` 的既有解析规则一致)

### 用户故事 2 - 保存多套币安密钥并选用 / 删除 (优先级: P1)

小张有币安主账户与测试网两套凭据。他在「币安凭据」里新增"主账户"(环境=实盘主网)与"测试网"(环境=测试网 demo),
分别粘贴 key/secret; 点"主账户"的「选用」后主网凭据立即生效(运行页可起 live/dry_run), 点"测试网"的「选用」则
demo 凭据生效。旧的凭据他点「删除」即可移除, 删除后选择该环境启动策略会如实报"未配置"。

**优先级理由**: "可以设置或者删除"是用户的明确要求; 现状**无删除入口**, 属功能缺口。

**独立测试**: 新增两条币安条目(一 live 一 demo) → 选用 live 条 → `[exchange].binance_key/secret` 等于该条 →
选用 demo 条 → `[exchange].demo_key/secret` 等于该条且主网字段不变 → 删除 live 条 → 条目消失且 `[exchange]` 主网字段被清空。

**验收场景**:

1. **给定** 币安密钥条目列表, **当** 用户新增条目并选择环境(实盘主网 / 测试网 demo), **则** 别名 + 环境 + key/secret 一并落盘, 列表显示别名与环境标签
2. **给定** 某条环境=实盘主网, **当** 用户点「选用」, **则** 其 key/secret 写入 `[exchange].binance_key/binance_secret`, 测试网字段不受影响
3. **给定** 某条环境=测试网 demo, **当** 用户点「选用」, **则** 其 key/secret 写入 `[exchange].demo_key/demo_secret`, 主网字段不受影响
4. **给定** 某条正是"使用中", **当** 用户点「删除」并确认, **则** 条目从密钥环移除, **且** 对应的生效字段被清空(不留"已删除却仍生效"的幽灵凭据)
5. **给定** 生效凭据不来自任何条目(用户在终端向导/终端编辑器里手工填的), **当** 用户在页面上点"清除当前生效", **则** 生效字段被清空且页面如实反映"未配置"
6. **给定** 只填了 key 没填 secret, **当** 用户保存, **则** 提示两者都需填写(或明确告知该条不完整), 不允许半截凭据静默落盘

### 用户故事 3 - 密钥不外泄 (优先级: P1)

小张担心页面把密钥读回来。他发现密钥页任何位置都只显示"已配置 · 尾号 xxxx"; 编辑时分不清的字段可以
**重新粘贴覆盖**或**留空表示不改**, 但页面永远拿不到全文; 浏览器本地存储里没有任何密钥痕迹。

**优先级理由**: 032 FR-007 / FR-008 已确立此契约, 新增入口不得破坏它。

**独立测试**: 保存密钥后抓取 `GET /api/keys` 与页面 HTML/JS 全文, 断言不含任一密钥明文; 检查 `localStorage`/`sessionStorage` 为空。

**验收场景**:

1. **给定** 已保存多套密钥, **当** 页面拉取 `GET /api/keys`, **则** 响应里每个密钥字段只有 `{configured, hint}`, 全文不出现
2. **给定** 编辑某条已有密钥, **当** 用户**留空**该密钥框并保存, **则** 原值保持不变(不被清空), 其余字段正常更新
3. **给定** 任意时刻, **当** 检查浏览器持久存储, **则** 不含任何密钥

## 三、功能需求

- **FR-001**: 左侧导航新增「密钥」一级视图(hash `#keys`), 位于「运行」与「设置」之间; 刷新可按 hash 恢复。
- **FR-002**: 「密钥」页分两组: **AI 通道** 与 **币安凭据**; 每组内左列为条目列表(按别名), 右列为选中条目的详情表单。
- **FR-003**: AI 条目字段 = 别名 + 服务商 + 模型 + 接口地址 + API Key; 服务商可选内置预设(下拉)或自定义名。
- **FR-004**: 币安条目字段 = 别名 + 环境(实盘主网 / 测试网 demo) + API Key + API Secret。
- **FR-005**: 条目**选用**(AI) = 把该条的 provider/model/base_url/api_key 写入 `[ai]` 段; **选用**(币安) = key/secret 写入
  对应环境的 `[exchange]` 字段(live → `binance_*`; demo → `demo_*`)。选用是**显式动作**, 不隐式发生。
- **FR-006**: 页面必须如实标出"使用中"的条目: 条目的四元组与 `[ai]` 当前生效值完全一致(AI) / key+secret 与对应环境一致(币安)。
  若生效值不来自任何条目(手工填写), 页面显示"当前生效(未来自密钥列表)"并提供「清除当前生效」。
- **FR-007**: 条目**删除**为持久删除; 若被删条目正是"使用中", 同时清空其对应的生效字段(FR-006 的幽灵凭据防护)。
- **FR-008**: 编辑正在"使用中"的条目并保存后, 生效值必须同步跟随(不留旧值)。
- **FR-009**: 别名在同类内唯一; 空/超长(>24 字符)/含控制字符被拒绝并给出中文原因。环境仅接受 `live` / `demo`。
- **FR-010**: `GET /api/keys` 只回 `{configured, hint}` 与预设表; 任何响应与页面静态资源都不得出现密钥全文。
- **FR-011**: 密钥框语义与 032 一致: **留空 = 不修改**; 想让某条不再持有密钥, 用「删除条目」或「清除当前生效」。
- **FR-012**: 密钥环与生效凭据同存**唯一配置文件** `ricow.toml`(宪法「完全本地化」+ 019「密钥与其设置同处一处」),
  不新建第二个密钥文件; 仍走原子写 + 0600 / icacls 收紧。
- **FR-013**: 上述写入属 **Web 渠道普通写操作**, 确认方式 = 页面显式交互(表单提交 / 按钮点击 / 删除二次确认),
  与 032 FR-027 一致; **不**放宽任何 live 逐字短语门禁。
- **FR-014**: 「设置」页不再重复承载密钥配置, 保留市场视野与语言; 并给出指向「密钥」页的入口, 避免两处配置漂移。

## 四、关键实体

| 实体 | 字段 | 落点 |
|:--|:--|:--|
| AI 密钥条目 | 别名 · 服务商 · 模型 · 接口地址 · API Key | `ricow.toml` 的 `[[ai_key]]` 数组表 |
| 币安密钥条目 | 别名 · 环境(live/demo) · Key · Secret | `ricow.toml` 的 `[[exchange_key]]` 数组表 |
| 生效凭据 | 与 019/032 相同, 字段一字未变 | `ricow.toml` 的 `[ai]` / `[exchange]` 段 |

**配置形态(示例)**:

```toml
[ai]                        # 当前生效(选用某条时写入这里)
provider = "deepseek"
model = "deepseek-flash"
api_key = ""

[[ai_key]]                  # 密钥环: 备用多套, 可按别名保存/选用/删除
alias = "工作号 DeepSeek"
provider = "deepseek"
model = "deepseek-flash"
base_url = ""
api_key = "sk-..."

[[exchange_key]]
alias = "测试网"
env = "demo"
key = "bn-demo-key"
secret = "bn-demo-secret"
```

## 五、验收标准 *(必填)*

- **SC-001**: 用户可在页面上保存 ≥2 套 AI 密钥, 并在两者之间切换生效, 全程无需手改配置文件、无需重启服务。
- **SC-002**: 用户可在页面上删除任一币安密钥条目, 删除后该凭据不再出现在任何脱敏视图且不再生效。
- **SC-003**: `GET /api/keys` 与页面资源中不含任何密钥全文(测试断言覆盖)。
- **SC-004**: 现有行为零回退: 终端向导、对话 `/keys`、`/api/config/keys`、`[ai]`/`[exchange]` 的解析与校验规则一行不改, 既有测试全绿。
- **SC-005**: 手工编辑 `ricow.toml` 增删 `[[ai_key]]` 段后, 页面刷新能正确读到(配置文件仍是唯一权威)。

## 六、假设

- 假定用户理解"选用"是显式动作: 编辑条目 ≠ 立即生效(会改成生效, 见 FR-008 只覆盖"正在使用中"的那条)。
- 假定密钥环条数规模小(几十条以内), 页面一次性全量拉取即可, 不做分页。
