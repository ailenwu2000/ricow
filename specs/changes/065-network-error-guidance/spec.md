# 065 回测网络失败要给可操作的指引

## 1. 问题（一手证据，2026-10-25）

### 1.1 现象

用户在 Web 上点「模拟回测」，作业失败，界面上只有一行裸错误：

```
network error: K 线第 0 片拉取失败: network error: ...
```

**这句话对用户没有任何帮助** —— 他不知道该查网络、查代理，还是自己代码写错了。

### 1.2 根因不是产品缺陷（先证伪环境）

本机实测（`curl`，直连与经代理两条都试）：

| 目标 | 直连 | 经代理 | 说明 |
| -- | -- | -- | -- |
| `api.binance.com` | HTTP 000 | **502 Bad Gateway** | 代理侧屏蔽；系统 DNS 还把它解析到随机 IP（`23.225.141.210` / `157.240.18.18` —— 两次不同，典型污染） |
| `data-api.binance.vision` | **HTTP 200** | **HTTP 200** | 币安官方公共行情镜像，**直连与经代理都通** |
| `testnet.binancefuture.com` | — | **HTTP 200** | 合约测试网 |
| `fapi.binance.com` | HTTP 000 | HTTP 000 | 合约主网同样不可达 |
| `github.com` / `google.com` | HTTP 000 | HTTP 000 | **本机整体网络不通**（代理只放行部分站点） |

**实证结论**：e2e 用 `RICOW_BN_BASE_URL=https://data-api.binance.vision` +
`RICOW_FAPI_BASE_URL=https://testnet.binancefuture.com` 起服务后重跑，
**460 PASS / 0 FAIL**（此前是 451/18，18 条全在回测段）。

⇒ 那 18 条红**不是产品缺陷**，是币安主网在本机不可达。这条已经**用实跑证明**，
不再是"假定是环境问题"。

### 1.3 但"环境问题"不等于"用户不用管"

产品**已经知道**这件事 —— `crates/ricow/src/ai/prompt.rs` 第 8 条写着：

> 网络: 全程需访问币安。国内直连 api.binance.com 常超时, CLI 认 HTTPS_PROXY/HTTP_PROXY/ALL_PROXY;
> RICOW_BN_BASE_URL/RICOW_FAPI_BASE_URL 是整体域名替换(公开数据+签名下单都变),
> 公开数据镜像域(如 data-api.binance.vision)只能看行情/回测, 下单会失败。
> 报 network error 先查网络与代理, 不要当成策略缺陷。

**但这段话是写给 AI 看的，用户看不到。** Web 界面上只有那行裸错误。

## 2. 做什么

### 2.1 判别"这是网络问题"

后端作业错误里已带 `network error:` 前缀（`CoreError::Network` 的 Display）。
前端按这个前缀判别 —— **不新增错误类型、不改后端错误契约**。

判据要**窄**：只有含 `network error`（或 `K 线…拉取失败`）的作业错误才提示，
参数错误、门禁错误**不提示**（提示了是噪音，且会把人引向错误的排查方向）。

### 2.2 给一条能照着做的提示

提示内容（要点，不写成教程）：

1. 这是**网络/代理**问题，不是策略写错了。
2. 三个可操作的动作：
   - 检查代理（`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`）。
   - 用备用数据域名：`RICOW_BN_BASE_URL=https://data-api.binance.vision`
     （**只影响行情与回测，下单仍走主网** —— 这一点必须说，否则用户会以为改完就能实盘）。
   - `RICOW_FAPI_BASE_URL=https://testnet.binancefuture.com` 同理（合约）。

### 2.3 刻意不做

| 项 | 理由 |
| -- | -- |
| 在 ricow.toml 里加 `base_url` 配置项 | 那是**新增配置面**，要过 `WRITABLE` 与安全审查（域名白名单已有，但配置面影响面更大）。本轮只把**已有的 env 覆盖口**告诉用户 |
| 自动探测并自动切换镜像 | 自动改数据源会让用户不知道自己在用哪个域；且镜像只覆盖公开数据，自动切过去后下单会失败 —— 那比报错更坏 |
| 给所有错误加提示 | 只有网络类错误给。参数/门禁错误提示网络方向是误导 |
| 前端改 DNS / 改代理 | 前端不能也不该做系统级网络配置 |

## 3. 验收判据

1. 回测作业错误含 `network error` 时，界面上出现**网络指引块**（含代理 env 名与两个 `RICOW_*_BASE_URL` 覆盖口）。
2. 指引里**明说镜像域只影响行情/回测**（下单走主网）—— 不说这句会误导用户拿它去实盘。
3. **非**网络类错误（参数错、门禁拦）**不出现**该指引块。
4. 指引文案中英双语都有（`R.TEXT` 两份字典都补齐，前端门会查键对齐）。
5. 指引不落浏览器存储、不含用户数据、不改变任何配置 —— **只读提示**。
6. 门禁六件全绿 + 真机两路全绿 + 065 专项走查全绿。
