# 066 市场视图部分降级 + 快速失败

## 1. 问题（一手证据，2026-10-25）

### 1.1 现象

`GET /api/markets` 在**合约端点不可达**时：

```
HTTP: 500
{"error":"network error: error sending request for url (https://fapi.binance.com/fapi/v1/exchangeInfo)"}
耗时: 42.43 秒
```

**现货明明是通的**（同一台机器上 `data-api.binance.vision` 的现货 K 线/exchangeInfo 都 200），
用户却连**现货交易对都看不到** —— 整个市场视图挂掉。

### 1.2 为什么 42 秒

`pairs::fetch()` 用 `tokio::try_join!` 并发拉三份数据：

```rust
let (spots, futures, equity_bases) = tokio::try_join!(
    spot.get_exchange_info(),      // 现货
    fapi.get_perp_markets(),        // 合约
    fapi.get_equity_pool()         // 合约(EQUITY 白名单)
)?;
```

- `try_join!` = **任一失败则整体失败** → 合约挂 ⇒ 现货也白拉 ⇒ 整个端点 500。
- 42 秒 = 币安客户端 30 秒超时 × 重试策略（`max_attempts: 4`）+ 退避。

### 1.3 这与项目自己的约定冲突

`crates/ricow/src/commands/pairs.rs` 里 `ensure_pair_in_scope` 明写：

> 视野快照拉取失败(网络抖动)→ **warn 后放行**: 范围校验是辅助检查,
> 不该把一次 exchangeInfo 抖动升级成主功能不可用 —— 主调用随后会如实报它自己的错。

**同一个文件、同一个数据源**，一处"抖动不升级"，另一处（`/api/markets`）直接 500 + 42 秒。
这不是设计取舍，是**漏了一处**。

064 已经在 `/api/overview` 上踩过同一个坑（把 `pairs::current_view` 放进聚合端点，
币安不通时整页 HTTP 000），当时用 `tokio::time::timeout(5s)` + 给 `scope = None` 修掉了。
**同一类问题在 `/api/markets` 上没修。**

## 2. 做什么

### 2.1 视野快照各半独立

`fetch()` 改成**三份各自成败**：

| 情况 | 现货 | 合约 |
| -- | -- | -- |
| 都通 | 有数据 | 有数据 |
| 现货通、合约挂 | **有数据** | 标记不可用 |
| 现货挂、合约通 | 标记不可用 | 有数据 |
| 都挂 | 都标记不可用 | 都标记不可用 |

**为什么能这样**：现货 exchangeInfo 与合约 exchangeInfo 是两个独立端点，
现货那一半的数据**不依赖**合约那一半的响应。

**但有一个真实的依赖**必须说清：默认视野（`show_all_pairs = false`）下，
**bStock 现货池要靠 fapi EQUITY 白名单识别**（`is_bstock_base` 拿 base 去尾 B 去比白名单）。
合约挂掉 ⇒ EQUITY 白名单拿不到 ⇒ **默认视野下现货那一半也算不出来**（会误把非股票现货当股票）。

故降级**必须区分口径**：
- `show_all_pairs = true`（全量）：现货与合约**互不依赖**，可以真降级（现货照给，合约标"—"）。
- `show_all_pairs = false`（默认，仅股票类）：现货那一半**依赖**合约白名单 ⇒ 合约挂 ⇒
  **现货那一半也标不可读**（不能说"0 个股票现货" —— 那是编造）。

这条区分是本变更的**核心难点**，写在这里以免后来者把它简化掉。

### 2.2 如实标记，不假装是 0

`PairsView` 加两个字段：

```rust
/// 现货那一半**是否取到**。`None` = 没这个信息(旧数据/未知); `Some(false)` = 取不到。
pub spot_ok: Option<bool>,
/// 合约那一半**是否取到**。同上。
pub futures_ok: Option<bool>,
```

- 用 `Option<bool>` 而不是 `bool`：老调用点/老数据不填时是 `None` = "没这个信息"，
  前端按**原来的行为**显示（不凭空多出一个"—"）。
- `Some(false)` = **取不到**：前端显示「—」并说明原因，**不显示 0** ——
  延续 062/063 的"取不到 ≠ 0"纪律。

### 2.3 快速失败

视野快照取数加**超时**（8 秒）。理由：它是**列表页的冷启动必经路径**，
前端 `markets.js` 自己也有 `LIST_TIMEOUT_MS = 10000` 的上限 —— 后端比前端还慢 4 倍，
前端必然先超时，用户看到的是"加载中…"而不是原因。

### 2.4 前端

- `renderScope()`：`spot_ok === false` 时现货那一段显示「—」而不是 `0`。
- `renderGroup()`：不可用的一组显示"取不到"而不是空列表（空列表会被误读成"这个市场没有交易对"）。
- 概览的 bStock 覆盖卡：`scope` 已有"取不到显示—"的路（064 做的），这里补"半边不可用"的口径。

## 3. 刻意不做

| 项 | 理由 |
| -- | -- |
| 缓存"上一次成功的视野"再降级返回 | 那是**过期数据**。062 的纪律是"读不到就说读不到，不留旧数字冒充当前" |
| 自动切到镜像域 | 自动改数据源会让用户不知道自己在用哪个域；且镜像只覆盖公开数据 |
| 放宽 `validate_base_url` 白名单 | 那是**审计红线**（放行未知主机 = 把 API key 与签名交给它）。实测 `testnet.binancefuture.com` 就被正确拦住了 —— 白名单工作正常，不该为了绕过它而放宽 |
| 把现货那一半"凑"出来（如去掉 EQUITY 交叉） | 那会给出**错误的股票类识别**（crypto 假阳性：ARBUSDT/STXBUSDT/QNTBUSDT） |

## 4. 验收判据

1. 合约端点不可达时，`GET /api/markets` **不返回 500**，返回 200 + 现货数据 + `futures_ok=false`。
2. 全量视野（`show_all_pairs = true`）下，现货那半**照常给真数据**（不被合约失败连累）。
3. 默认视野（仅股票类）下，合约挂 ⇒ **现货那半也标不可读**（因为股票池依赖合约白名单）——
   **不能**给一个假的"0 个股票现货"。
4. 现货端点不可达时对称成立。
5. 视野快照取数**不超过 8 秒**（不再 42 秒）。
6. 前端：不可用的一侧显示「—」/说明，**不显示 0**、不显示空列表。
7. `PairsView` 的新字段 `Option<bool>`，老调用点不填时行为**与改动前完全一致**。
8. 门禁六件全绿 + 真机两路全绿 + 066 专项走查全绿。
