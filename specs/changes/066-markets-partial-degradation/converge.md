# 066 收敛记录 —— 市场视图部分降级 + 快速失败

## 1. 问题（一手证据，2026-10-25）

`GET /api/markets` 在**合约端点不可达**时：

```
HTTP: 500
{"error":"network error: error sending request for url (https://fapi.binance.com/fapi/v1/exchangeInfo)"}
耗时: 42.43 秒
```

**现货明明是通的**（同一台机器上现货镜像的 K 线/exchangeInfo 都 200），
用户却连**现货交易对都看不到** —— 整个市场视图挂掉。

### 根因

`pairs::fetch()` 用 `tokio::try_join!` 并发拉三份数据（现货 exchangeInfo / 合约永续 / 合约 EQUITY 白名单）：

- `try_join!` = **任一失败则整体失败** ⇒ 合约挂 ⇒ 现货也白拉 ⇒ 整个端点 500。
- 42 秒 = 币安客户端 30 秒超时 × 重试（`max_attempts: 4`）+ 退避。

### 这与项目自己的约定冲突

**同一个文件**（`crates/ricow/src/commands/pairs.rs`）里 `ensure_pair_in_scope` 明写：

> 视野快照拉取失败(网络抖动)→ **warn 后放行**: 范围校验是辅助检查,
> 不该把一次 exchangeInfo 抖动升级成主功能不可用。

一处"抖动不升级"，另一处（`/api/markets`）直接 500 + 42 秒 —— 这不是设计取舍，是**漏了一处**。

064 已在 `/api/overview` 上踩过同一个坑（把 `current_view` 放进聚合端点，币安不通时整页 HTTP 000），
当时用 `tokio::time::timeout(5s)` + `scope = None` 修掉了。**同一类问题在 `/api/markets` 上没修。**

## 2. 做了什么

### 2.1 视野快照各半独立

`fetch()` 改成**三份各自成败**（`tokio::join!` + 各自吞错误），失败的那半记为"取不到"。

**客户端构造失败仍整体失败** —— 那不是网络抖动，是配置错误（如域名不在白名单），**必须硬失败**：
静默降级会让用户以为自己在用合法域名。

### 2.2 关键的依赖关系（本变更的核心难点）

默认视野（`show_all_pairs = false`）下，**bStock 现货池要靠 fapi EQUITY 白名单识别**
（`is_bstock_base` 拿 base 去尾 B 去比白名单）。合约挂掉 ⇒ EQUITY 白名单拿不到 ⇒
**默认视野下现货那一半也算不出来** —— 若照样给出现货列表，就是把 crypto
（ARBUSDT / STXBUSDT / QNTBUSDT 的 base 都以 B 结尾）当股票。

故降级**分口径**：

| 口径 | 合约不可用时 | 现货不可用时 |
| -- | -- | -- |
| 全量（`show_all_pairs = true`） | 现货**照常给真数据**（互不依赖） | 合约照常给 |
| 默认（仅股票类） | **现货那半也标不可读** | 合约那半标不可读 |

### 2.3 如实标记，不假装是 0

`PairsView` 加两个字段：

```rust
pub spot_ok: Option<bool>,     // None = 没这个信息(老数据); Some(false) = 取不到
pub futures_ok: Option<bool>,
```

用 `Option<bool>` 而不是 `bool`：`None` = **没这个信息**（老调用点/老数据），
前端按**改动前的行为**显示；`Some(false)` = **取不到** ⇒ 显示「—」+ 说明，**不显示 0**。

序列化用 `skip_serializing_if = "Option::is_none"` ⇒ **老响应形状不变**。

### 2.4 每半各自超时（不是整体一个）

第一版写 **8 秒**，实测**太紧**：经代理拉币安官方公共镜像的 exchangeInfo 实测 **52 秒**（17 MB）
—— 8 秒会把**正常传输**判成超时（把"慢"误报成"挂"），那比慢更糟。

改成 **25 秒**，且**每一半各自套**（`with_timeout`）：现货 exchangeInfo 17 MB、合约 EQUITY 白名单只是一段 JSON，
体量差极大 —— 整体套一个超时会用"慢的那半"误判"挂了的那半"。

### 2.5 前端

- `renderScope()`：不可用的一侧显示「—」。
- `renderGroup()`：不可用的一侧显示"读不到"说明 + 指引，**不显示空列表**（会被读成"这个市场没有交易对"），
  **也不给"看全部交易对"的空态按钮**（网络故障时那按钮会把人引向错误的排查方向）。
- 概览的 bStock 覆盖卡：同样带可用性，一侧不可读显示「—」+ 一句说明。

## 3. 撞出来的三个真问题（都已修 + 回归断言）

### 真问题一：`spot_readable` 取错了字段

第一版实现：

```rust
let spot_readable = if futures_ok == Some(false) && !show_all { Some(false) } else { futures_ok };
```

`else` 分支用了 `futures_ok` —— 于是"**现货失败 + 合约成功**"时，现货明明取不到却因合约正常而**标成可读**。
（`futures_ok` 应为 `spot_ok`。）

**怎么发现的**：变异验证。原先的 M1 变异（把 `spot_readable` 简写成 `futures_ok`）**断言仍绿**，
因为默认视野下两种写法结果恰好相同 —— 换句话说**原断言没有牙齿**。
改成有意义的变异（去掉 `&& !show_all` 守卫 / 把 `spot_ok` 换成 `futures_ok`）后才暴露。

修法：`else { spot_ok }`，并补两条**成对**的断言（全量视野 + 默认视野各一条）——
只钉一条区分不开实现。

### 真问题二：降级引入新的误判

`ensure_pair_in_scope` 走 `current_view`。降级后现货那半可能是**空的**（合约挂了 → 股票池认不出来），
若照常判越界 ⇒ **任何**交易对都会被误判"越界"，用户会被引导去改 `show_all_pairs` ——
而真正原因是网络挂了，改了也修不好。

修：**要查的那一半取不到 ⇒ 不判越界，放行**（与"快照完全失败"同一处置，只是触发点从"整体失败"扩到"半边失败"）。

### 真问题三：概览的 `scope` 会把降级显示成 0

`/api/overview` 的 `scope` 也走 `current_view`。降级时那一半是**空列表** ⇒
`v.spot.len()` 会显示成"0 个"（假信息）。

修：`ScopeCounts` 同步加 `spot_ok` / `futures_ok`，bStock 卡据此显示「—」。

## 4. 验证

| 项 | 结果 |
| -- | -- |
| 门禁六件 | 全绿（整仓 **1088 passed / 0 failed / 22 ignored**） |
| **真机降级实测** | 合约不可达时：`HTTP 200` + `futures_ok=false` + **现货照常给 1383 个真数据** + 耗时 **3.5 秒**（原 500 / 42 秒） |
| **真机默认视野** | 合约不可达时：`spot_ok=false` + `futures_ok=false`（股票池依赖合约白名单 ⇒ 现货也读不了，**不给假的 0**） |
| **变异验证 7/7 全抓住** | M1 去掉 `!show_all` 守卫 / M1b 现货可用性错取 `futures_ok` / M2 显示 0 / M3 删不可读分支 / M4 改回 `.length` / M5 字段改非 Option / M6 去掉 Option 钉子 |
| 066 专项走查 `probe066.mjs` | **8 PASS / 0 FAIL**（不可用侧显示「—」+ 指引；可读侧照常显示真实交易对；都通时不噪音；老响应行为不变） |
| e2e / CDP | **全绿**（e2e 460 PASS / 0 FAIL；CDP 全绿） |

### 变异验证踩到的坑（复用价值高）

1. **变异脚本的锚点必须逐条确认** —— 本轮连踩三次：① `cargo fmt` 把多行压成一行，锚点失效（表现为 `[SKIP]`）；
   ② Python 三引号里的中文引号被当字符串定界符（SyntaxError）；③ python 改文件后**没回读确认**，改动没落盘。
   ⇒ **锚点先在磁盘上 `in` 检查一遍再跑**；改完**立刻回读确认**。
2. **等价变异是无效变异** —— M1 第一版把 `spot_readable` 写成 `futures_ok`，而这在**所有**输入下
   与原实现**结果相同**（因为只有 `futures_ok == Some(false)` 时才走到不同分支，而那时两者都是 `Some(false)`）。
   变异必须**真的改变某个输入下的输出**。
3. **断言要与实现"成对"** —— 只钉默认视野那条时，把实现简化成 `futures_ok` 仍绿（结果恰好相同）。
   必须全量视野 + 默认视野**各钉一条**。

## 5. 刻意不做

| 项 | 理由 |
| -- | -- |
| 缓存"上一次成功的视野"再降级返回 | 那是**过期数据**。062 的纪律是"读不到就说读不到，不留旧数字冒充当前" |
| 自动切到镜像域 | 自动改数据源会让用户不知道自己在用哪个域；且镜像只覆盖公开数据 |
| 放宽 `validate_base_url` 白名单 | 那是**审计红线**。实测 `testnet.binancefuture.com` 就被正确拦住了 —— 白名单工作正常，不该为了绕过它而放宽 |
| 把现货那一半"凑"出来（去掉 EQUITY 交叉） | 那会给出**错误的股票类识别**（crypto 假阳性） |
| 把"不可用"做成 `bool` 而不是 `Option<bool>` | `bool` 会让老调用点被当成"false" ⇒ 凭空多出一片「—」，行为与改动前不一致 |
