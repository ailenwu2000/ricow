## 真机取证细节(可复跑)

1. 起服务: `RICOW_ROOT=<repo>/tmp/verify-040 ./target/debug/ricow.exe web --no-open --port 18797`
   (**先 `cargo build`** —— 自己起的服务锁 `target/debug/deps/ricow.exe`, 否则 LNK1104)。
2. 探针: `python -u tmp/probe_040_stream.py http://127.0.0.1:18797 <token>` → **23 PASS / 0 FAIL**(exit 0)。
   上游是**真实币安 WS**, 断言的是"数据真的在跳"而不是"接口返回 200":

   - **§1 参数在联网之前就拒绝**(6 条全绿): 缺 `interval` → 400「interval 必填(如 1h), 实时订阅不接受缺省周期」;
     缺 `market` → 400; 白名单外周期 `2m` → 400 并列出支持列表; `ZZZUSDT` → **404**「现货市场没有交易对 ZZZUSDT (实时订阅只接受行情视野内的交易对)」(而非连上后静默无数据); 无 token → **401**(与其余端点同一道门)。
   - **§2 现货 ETHUSDT 1h, 22 秒窗口**: 收到 **189 帧** = `hello`×1 + `kline`×10 + `depth`×178 + `error`×0。
     `close` 在流里**真的变化**(`2612.46 → 2612.47 → 2612.46 → …`)—— 这是"不是静态快照"的唯一证据;
     同一根 K 线被**原地重复推送**(覆盖 1 个 `open_time`, 即未收盘那根), 与 FR-2 的 `update` 语义一致;
     帧里 `t`/`T` 是 epoch 毫秒且 `T > t`, `o/h/l/c/v` 全是字符串。盘口**恰好 20 档**(服务端已截断), 档字段名与 REST 一致,
     买一 `2612.46000000` < 卖一 `2612.47000000`(无穿价)。
   - **§3 与 REST 交叉核对**: WS 末帧 `open_time = 1791342000000` 与 REST 末根 `open_time` **逐位相等**;
     WS `close = 2612.47` 与 REST 末根 `close` 相对差 **0.000000%**; 盘口买一/卖一与 `?depth=1` **逐字相同**, 中值一致。

     `{"type":"error","scope":"kline","msg":"上游已连接但 12 秒内未推送任何数据"}`, 且**同一连接的盘口不受连累**;
     同一轮现货 K 线拿到 10 帧 → 排除"网络整体不通"。

3. **根因定位(2026-10-07 补充取证)**: 初判"合约 K 线流零帧"**过于狭窄**。逐类对照后真相是:

   故与"合约有没有成交"无关。

   **① 按数据来源分类对照(20s 并行窗口)**

   | 流 | 数据来源 | 合约 `fstream` | 现货 `stream:9443` |
   | :-- | :-- | --: | --: |
   | `bookTicker` | 订单簿 | **9 105** | 414 |

   | `aggTrade` | 成交 | **0** | 26 |
   | `trade` | 成交 | — | 62 |
   | `kline_1m` / `kline_1h` | 成交 | **0 / 0** | 6 / 7 |

   `WebSocket` 看不到)读 18s: 合约 `kline_1h` 汇总 `{}`, **连 PING / CLOSE 都没有**; 同主机 `bookTicker` 3 779 条 text 帧。

   `{"result":null,"id":1}`(订阅 `btcusdt@kline_1h` 被接受)→
   `{"result":["btcusdt@kline_1h","btcusdt@bookTicker"],"id":3}`(**列表确认 kline 已登记**),
   然后 20s 内 6 552 条 text **全是 bookTicker, kline 一条没有**。现货主机同流程完全正常。
   → 排除"我们订阅得不对": 订阅在协议层被承认, 数据就是不下发。

   **④ 逐 IP 排除单节点故障**: `fstream.binance.com` 解析到的 **8 个 IP 全部**呈 `bookTicker≈7 000 / kline=0`,
   且 8 个 IP 的证书指纹一致 → 不是某台叶子节点坏了。

   **⑤ 90 秒窗口排除"预热慢"**: 合约 `kline_1m` **0 帧**; 同一 90s 内合约 `bookTicker` **38 264 帧**、现货 `kline_1m` 42 帧。

   **⑥ 排除中间人 / 走错主机**: TLS 证书为真币安 `*.binance.com`(签发者 `GeoTrust TLS RSA CA G1 / O=DigiCert Inc`,

   **123 320 笔成交**, REST `aggTrades` 返回的成交时刻距本机仅 **~7 秒**。

   **⑧ 排除客户端库**: Node 内置 `WebSocket`、自写裸 TLS+WS 客户端、ricow 自身的 Rust(tokio-tungstenite)
   三条路径现象完全一致。

   **结论(严格区分"实测"与"推断")**

   - **实测事实**: 在合约 WS 主机上, 订单簿流正常且高频; 成交派生流(`aggTrade` / `trade` / `kline_*`)与服务端计算流

   - **推断(未证到币安内部)**: 这条出口网络拿到的合约行情是**只有订单簿的那一份子集**,

## 收敛期踩到的坑(供下次复用)

1. **探针的"无 token"用例把自己挂死了**: 第一版 `status_of(path)` **无条件**带上 `Authorization` 头 ——
   于是"无 token → 401"那条实际发出的是**合法请求**, 在 SSE 端点上 `r.read()` 永不返回(流不会结束),
   表现是**整条命令空输出后被 SIGTERM**, 看着像产品不响应。修法: 该函数加 `with_token` 开关,
   并在注释里写明"**只用于预期被拒绝的请求**; 带 token 且合法时会打开流, `read()` 不返回"。
   同时 `read_stream` 的 socket 超时压到 8s, 静默窗口不再拖住整个探针。
   > 教训同 039 的"先分清是产品还是断言": **探针自身的阻塞/公式错误会伪装成产品缺陷**。
2. **别用 `python x.py > f.txt` 的复合命令观感判断成败**: 首次跑时 shell 包装先收到 SIGTERM, 工具侧显示空stdout,
   而**输出文件其实已写入**。看产物文件比看 shell 回显可靠。

## 决策记录

- **D1 上游按 `(市场,标的,周期)` 共享**: 一个进程内同键只开**一条**币安 WS。每标签各开一条是把币安连接配额当计数游戏;
  代价是必须自己做引用计数与生命周期(FR-6~FR-8)。
- **D5 就绪窗口 + 按路隔离**(本变更最关键的工程判断): 上游"订上了但一帧不给"若不做检测,
  就表现为"图冻住了但界面说实时" —— 与 FR-9 直接冲突。分路隔离的依据是**实测**(同轮合约盘口正常而 K 线零帧),
  不是设计者的猜想。
- **D7 流端点 `interval` 必填**: 不继承兄弟端点的 `1h` 默认。订阅是长承诺,
  静默默认会让"我传了 4h、它订了 1h"这种错在界面上表现为"图不对"而不是一条明确的 400。
- **D4 不做 Last-Event-ID 续传**: 行情无补发语义, 重放旧帧等于把图拉回过去; 重连一律 REST 快照重对齐。
- **D8 只留一份退避实现**: `futures_ws.rs` 的第二份 `backoff_delay` 随本变更删除(第三个使用者出现, 三份就是自找不一致)。
- **D10 不做**: 订阅并发上限(回环 + token + 单用户, 不留无依据的保守余量) / 运行页实时化(数据源是本机 daemon 状态而非行情) / 新依赖。

## 遗留

- **合约非订单簿行情在本机不可用**(根因见 §3: 上游只下发订单簿流)。产品已如实降级为"快照 + 明确提示",
  **不是静默错误**。**ricow 侧无可改之处**(订阅被上游正常受理, 是数据不下发)。
  换网络 / 换地区复测; 若届时恢复正常, 本变更零改动即可工作。
  若长期不可用, 可考虑的一个**新变更**(非本轮, 且需遵守 FR-9 不得伪装实时):
  合约 K 线在明确标注"非实时、定时刷新"的前提下回退到 REST 轮询, 而盘口保持实时 —— 这需要先有产品决策, 不在 040 范围内。
- **浏览器像素级"帧到达后图动了"未截图取证**(本机未装 agent-browser)。已用替代手段覆盖:
  SSE 帧序列 + `close` 随时间变化 + REST 交叉一致 + JS 语法检查。
- **运行页实时化**(5 秒轮询本地 daemon 状态)按 spec §五 非目标另起变更。
