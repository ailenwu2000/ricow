# 040 行情实时化（P0 实时类）

> 依据: `tmp/webui_analysis.md` 第四节 P0-2（对标 FreqUI / FMZ / QuantConnect）。用户拍板：
> **路线 = 后端 WS → SSE（真实时）**，而非前端轮询增强；本合同一轮做 K 线 + 盘口两路实时。
>
> 039 已把"图表能画的东西"补齐，但**数据仍是死快照**：K 线只在进入详情时拉一次 200 根、
> 盘口一次性请求、现价跟着盘口一次性取。本变更把这三块接到币安 WebSocket 上。

## 一、K 线实时化

### 动机

主流产品（FreqUI / TradingView / FMZ）的 K 线是**逐笔长出来的**：最新一根随价格跳动，
收盘后定格、再长出新的一根。本项目的 K 线进入详情时才拉一次，之后**永不更新** ——
用户盯着一个静止的图，看不出"正在发生什么"。

后端 `ricow_binance` 已有**增量盘口**订阅（`ws.rs` / `futures_ws.rs` 的 `subscribe_depth`），
但**没有任何 K 线流订阅** —— 这是本变更要补的最主要缺口。

### 需求

- FR-1: 新增币安 **K 线流订阅** `<symbol>@kline_<interval>`（现货 `${ws_base}` / 合约
  `${ws_base}` 各一条），解析为 `ricow_core::Kline` 并逐帧下发；断线**指数退避重连**
  （复用既有 `backoff_delay` 口径），消费端退出即停止重连（不泄漏守护任务）。
- FR-2: K 线流要能识别"**当前未收盘的那根**"：同一 `open_time` 的帧是**原地更新**，
  出现更大的 `open_time` 才是新的一根。前端据此 `update` 而非 `append`。
- FR-3: Web 端 `GET /api/markets/{symbol}/stream?market=&interval=` 一条 **SSE** 连接下发
  K 线增量；进入详情页即连、离开即断；切周期 / 换标的时**旧连接必须关闭**（不许泄漏）。

## 二、盘口 / 现价实时化

### 动机

盘口与现价现在各发一次 HTTP 请求，用户看到的"买一/卖一/深度"是**进页面瞬间的定格**。
合约/现货的增量盘口订阅早已实现（含审计 H-4 的重连快照重建），只差把它接到页面上。

### 需求

- FR-4: 同一 SSE 连接同时下发**盘口增量**（`OrderBookUpdate` 已是**累计**盘口语义，
  前端直接整体替换，不需要自己合并）；现价由盘口最优买卖档求中值得到，**不再单独发请求**。
- FR-5: 服务端下发的盘口**截断到面板实际展示的档数**（20 档），不把 50 档原样推给浏览器。

## 三、订阅复用与生命周期（本变更的核心工程点）

- FR-6: 上游币安 WS 订阅按 **`(市场, 标的, 周期)`**（K 线）/ **`(市场, 标的)`**（盘口）**共享**：
  同键的 N 个页面共用**一条**上游连接。绝不为每个浏览器标签各开一条币安连接。
- FR-7: 最后一个订阅者离开 → **立即**中止上游守护任务并释放连接（不设宽限期：空闲连接会
  白占币安连接配额）。引用计数与条目增删**全部在锁内**完成，条目只在计数归零时移除。
- FR-8: 已死条目（上游任务已退出）不得被新订阅者复用 —— 订阅入口先验证计数，
  计数为 0 的条目一律**中止重建**，不把新订阅者挂到一条死管道上。

## 四、诚实性（不可协商）

- FR-9: **连接状态必须可见**。页面上的行情面板要有三态标识：`实时`（含**最后更新时刻**）/
  `重连中` / `已断开`。绝不允许"数据停了但界面还显示得像实时的"。
- FR-10: 上游订阅失败**必须说出来**，且**按路隔离**：K 线失败不该连累盘口。失败路径下发的
  错误帧要带**实际原因原文**（币安原文或网络错误），不吞成一个笼统的"失败"。
- FR-11: 断线重连后**以 REST 快照重新对齐**，不做事件续传 —— 行情没有"补发"语义，
  断线期间的价格变动不可能补发；重放旧帧只会让图回到过去。故**不实现** Last-Event-ID 续传。
- FR-12: 前端零持久化（禁 localStorage/sessionStorage）；帧数据一律经 `textContent` / DOM API
  注入，不拼 HTML；不出现任何交易所写动作（面板只读不变，D17）。
- FR-13: SSE 走**同一道 token 中间件**（与其余全部端点一致），不新开端口、不新增放行口。

## 五、非目标（显式不做）

- **运行页实时化**：运行页的 5 秒轮询查的是**本机 daemon 的状态**，不是交易所行情，
  数据源与推送语义都不同（轮询本地进程状态没有"实时"需求）。另起变更，不混进本变更。
- **订阅并发上限**：服务只绑回环 + token 门 + 单用户，不预设"连接被刷爆"的保守余量
  （宪法原则五：不留无依据的保守余量）；若将来暴露到非回环再加。
- **多 symbol 单连接 / SUBSCRIBE 复用**：沿用既有"一流一连接"写法（与 `subscribe_depth` 同构），
  不引入连接内多路复用协议。
- **新增依赖**：不引 `tokio-stream` / 新 WS 库 —— 广播频道 → 流的适配复用本仓既有
  `futures::stream::unfold` 写法（`web/sessions.rs` 同款）。

## 六、验收（真机取证，不可用替身）

- 上游是**真实币安 WS**：`curl -N` 读 SSE，断言 `hello` 首帧 + K 线帧 + 盘口帧真的到达，
  且**数值随时间变化**（静态快照不可能变化）—— 这是"真的实时"的唯一证据。
- 与 REST 交叉核对：最后一根 K 线的 `close` 与 `GET /api/markets/{symbol}/klines` 的末根
  `close` 一致（同源同周期）；盘口最优档与 `GET .../orderbook?depth=1` 一致。
- 失败路径用**真实不存在的标的**（如 `ZZZUSDT`）取证：上游必须回错误帧且带原文，
  而不是静默空转或假装实时。
- 既有接口零回归：官方冒烟脚本 `e2e_web.py` 全绿。
