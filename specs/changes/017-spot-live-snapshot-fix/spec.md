# 017 功能规格: 现货实盘快照一致性修复(dogfood 实测发现)

**状态**: 已实施 (2026-09-13) | **触发**: P4 dogfood 的 demo 实盘链路预演(无真实资金)

## 一、为什么

用户在 P4 阶段执行"demo 试 + 主网 Dry Run"预演时, 一轮 **demo 现货实盘**跑下来暴露了三个缺陷, 其中两个会造成**资金层面**的错误:

| # | 现象(实测) | 后果 |
|:--|:--|:--|
| **A** | 停机 `stop --close-all` 报告 `平仓单=未执行 / 平仓说明: 无持仓, 无需平仓`, 而交易所账户**实际持有 2.016 ETH** | **安全网静默失效**: 用户以为已平仓, 实际持仓留在交易所 |
| **B** | 策略每 tick 卖出量按 `1.0079 → 0.5039 → 0.252 → 0.126 → 0.063 → 0.0315 …` 几何级数递减, **2.016 ETH 被全部卖光**, 而策略意图只是卖一半回到 50% | **实盘现货网格会把持仓卖光**(非策略意图的过度交易) |
| **C** | 同一再平衡单在 1.4s 内下 3 次(同价同量) → 2 次成交 + 1 次 `insufficient balance` 报错 | 资金利用率错乱 + 账单噪音 |

根因(逐条定位到代码):

- **A**: 012 把停机清理的持仓源换成 `Exchange::get_positions_directional`, 而现货实现 `BnSpotExchange::get_position` 对现货**恒返回 `None`**(注释写着"现货无持仓概念")→ 默认实现包出的 `get_positions_directional` 恒为空 → `plan_cleanup` 判定"无持仓"。
  (011 当时走的是引擎侧 `spot_position_of`, 所以能平; 012 换成 directional 后现货这条路**静默失效**, 而 012 的实盘验证只在合约侧做过。)
- **B**: `LiveContext::record_fill` 只记 PnL; 实盘的持仓/余额靠引擎主动刷新。成交后的 `refresh_positions` **只刷了持仓、没刷现金** →
  策略按 `equity = 现金 + 持仓价值` 定目标仓位时, 现金停在启动快照(≈0.57 USDT, 因为钱都买了币) →
  每一 tick 都认为"只有币没有钱" → 每 tick 再卖一半 → 几何级数清仓。
  (算术完全吻合: `sell_n = 0.5·P_n − 0.5·C_stale/px`。)
- **C**: 成交回写走用户流(异步, 数百 ms), 期间本地快照陈旧 → 策略按旧状态重复下单。Dry Run 不出现此问题(虚拟撮合是同步的)。

## 二、范围

**做**: ① 停机清理与残留复查的持仓源按市场分支(现货走 `spot_position_of`); ② 现货成交后**同时**刷新持仓与现金;
③ 下单批次内出现成交 → 立刻对齐快照(闭合回写延迟窗口)。

**不做**: 不改 `Exchange::get_position` 对现货的语义(不动 crate 层约定); 不加 mock 测试替身(宪法禁);
不改策略本体(错误不在策略, 在上下文刷新链路)。

## 三、功能需求

- **FR-001**: 现货停机清理必须能取到"现货持仓 = base 余额"(与成交后刷新同源), 使 `--close-all` 真正平仓。
- **FR-002**: 现货成交后, base 与 quote 余额都要刷新(策略按 equity 决策, 缺任一侧都会算错目标仓位)。
- **FR-003**: 下单批次内出现成交后立即对齐快照, 压缩"重复下单"窗口; 刷新失败只 warn, 不中断交易循环。
- **FR-004**: 残留复查与清理使用**同一**持仓源(否则会一边平仓一边报"残留 0")。
- **FR-005**: 刷新失败必须如实上报(不静默当作"无持仓")。
