## 二、为什么这轮"没有单元测试"

本组缺陷的性质是**接线与时序**(取数源选错、只刷一半、回写窗口未闭合), 不是纯逻辑错误:
- 宪法明令交易流程禁 mock Exchange 替身, 因此无法为"清理时用哪个持仓源"写单测;
- 真实 demo 链路(无真实资金 + 真实 API/撮合语义)是这里唯一有效的验证方式, 已实跑并留档对照数字。

如实记录: 这三处修复**没有**新增单测, 证据 = demo 实跑前后对照 + 交易所账户核对。

## 三、收敛遗留

1. 现货持仓的"成本价/未实现盈亏"在实盘侧仍无来源(持仓由 base 余额包装, entry/mark 记 0)—— 要显示真实现货盈亏需另设
   数据源(交易所不提供现货成本价), 属新变更。
2. `min_order_notional` 与再平衡量级的匹配问题(见 P4 runbook 教训)属**参数配置**范畴, 不改为代码默认值。

## 四、留档教训

1. **跨市场共用取数点, 改动后必须逐市场实跑**: 012 改清理数据源时"现货走默认实现"看似零改动, 实则让 `--close-all` 静默失效 ——
   默认实现不等于安全实现。
2. **"只刷新一半状态"比不刷新更危险**: 半新的快照会让策略算出方向性的错误动作(本次是几何级数清仓), 而不是随机噪声。
3. **异步回写 + 同步决策 = 必须主动对齐**: 只要决策读本地快照、成交经异步通道回写, 就存在窗口; 下单后主动拉一次是最小代价的闭合手段。
4. **实盘验证不能只看"跑起来了"**: 必须核对**交易所侧**的余额/挂单/成交, 才会发现"报告说平仓了、账户却还持仓"这类不一致。
