## 二、① AI 按资金量给建议

### 数据来源
`load_instance_initial_cash()` 读实例 TOML 的 `[backtest].initial_cash`。**取不到一律 `None`，绝不回退内置默认 10 万** —— 回退等于替用户编一个资金量，与 `tools.rs` 里 `initial_cash`「必问项，绝不替他填」同一条纪律。拿到 `None` 就如实告诉模型「不知道本金，要先问」。

### 知识来源（真跑出来的事实，不是推演）
同一个内置网格策略，2026-10-18 在 demo 测试网真跑阶段 0：

| 本金 | 结果 |
|:--|:--|
| `--cash 100000`（默认） | **21 笔成交**，净 +6.07 |
| `--cash 300`（手册建议的小资金下限） | **只成交 1 笔**（建仓那一笔），之后一单挂不出 —— 建仓吃掉一半后只剩 149.85 |

**所以本金不足时策略是「跑不起来」，不是「收益差一点」。** 不把这件事写进提示词，AI 会照默认 10 万的直觉给建议，用户小额跟单时才发现只成交 1 笔。

### 四档判据（`CASH_TIER_GUIDE`）
- **< 1000**：网格/分批挂单类很可能跑不起来；单笔压到本金 1%~2%，或改用小资金友好的形态（点名 `paired_grid`），并**如实说明原形态在这个资金量下为什么不行**
- **1000 ~ 1万**：多数网格可运行，单笔须 ≤ 本金一两成；手续费占比明显偏高
- **1万 ~ 10万**：常规参数可用，重点看单笔与本金是否匹配
- **> 10万**：单笔不构成约束，可谈间距与档位密度

### 接进的位置
`build_params_prompt`（AI 调参数）与 `build_assess_prompt`（评估改动影响），经 `append_cash_section()` **插在 `## 输出要求` 之前** —— 放末尾会被模型当成「补充说明」而权重降低。对话侧同步进 `TRAPS_GUIDE` 第 5 条。

### 边界（宪法 D15/D17：平台不做投资判断）
只判**可行性**（这个钱数跑不跑得动），**不做**「该投多少 / 预期收益 / 该不该用它」这类投资判断。单测 `test_cash_tier_guide_judges_feasibility_not_investment` 用禁用词表（`建议投入` / `推荐买入` / `预期收益` / `稳赚` / `加仓到`）把这条红线锁死 —— 这段一旦被「优化」成收益承诺，就是把平台拉回做投资判断。

### 一条**归位**决策（不是为过测试而删）
资金判据最初写进了对话助手的常驻 `RULES`，测试立刻报 **4676 > 4000 字节**上限。那个上限是**成本纪律**（每次对话都付）。最终放进 `TRAPS_GUIDE`（`read_doc("commands")` 按需取），正合既有的「谈部署/改参前先读」纪律，且 `tools.rs` 与 `agentkit.rs` **直接引用同一常量、无副本**，改一处自动同步三处。

## 三、② kill switch 的 Web 端入口

### 位置
**运行视图表头**（`runs.js` 的 `sg-head` 加 `#rn-kill-all`）。**不进顶栏** —— 它是运行域动作不是全局导航；也天然避开只读红线 `assets.rs::test_frontend_panels_are_read_only`（那条只作用于对话视图右栏 `<aside id="panels">`）。

### 交互
复用既有 `openModal` / `modalActions` / `sg-btn-danger` 骨架，逐字短语输入区照抄实盘启动那套（复用 `rnPhraseHint` 键）。期望短语 `确认停止全部` / `确认停止全部并平仓`，与后端逐字一致。

### 三条刻意设计
1. **短语本身不进 i18n 字典**（只放「提示」）—— 它必须与后端逐字比对；写成可替换文案等于给了它一个被翻译掉的入口。
2. **`stopped == 0` 不套「已全部停止」头衔**（027 报告口径），另给 `rnKillNone`「当前没有运行中的实例(无需停止)」。
3. **勾平仓后清空输入框** —— 期望短语变了，旧短语必须重打。

## 四、真机验证（本轮最有价值的部分）

### 静态门抓不到、只有真机能抓的 bug
`openKillModal` 是**同步**函数，我却在挂载处写了 `openKillModal().catch(...)` → 浏览器运行期 `TypeError: Cannot read properties of undefined`。
而 `node --check` / `web_frontend_check.mjs` / Rust 单测 / curl **四道全绿** —— 与 042 的 `S.onUndo` 漏导出同型教训，**再次印证 CDP 真机走查不可省**。

### 探针自身也栽了一次
用 `.sg-btn` 类名挑主按钮会挑到**取消**按钮（它也带该类且默认未禁用）→ 断言变成永远为 true 的**假绿**。改为**按文案定位**主/取消钮；同时让 `Log.entryAdded` **连 URL 一起打** ——「Failed to load resource」的 text 不含路径，只打印 text 定位不到是哪个资源 404。

### 端到端实测（curl 直打 `POST /api/runs/kill`）

| 请求 | 结果 |
|:--|:--|
| `{}` / `{"confirm":"y"}` / `"确认停止全部 "`（尾部空格） | 400 `confirm_required` |
| `close_all:false` 却填 `确认停止全部并平仓` | 400（变体不串） |
| 无 token | 401 |
| 正确短语 + 真实 demo 策略在跑 | **200 `{"stopped":1}`** |

**关键验证 = kill 与 shutdown 的分界**：返回 `stopped:1` 后策略停了、挂单撤干净（`已撤挂单=1 撤单失败=0 残留=0`），而 **daemon 与 Web 服务都还活着** —— 完全符合设计。

### CDP 真机走查
新增 **13 条 058 断言**（入口存在 / 弹窗有短语框 / 写明后果 / 说清 daemon 仍在 / 裸 y 不放行 / 尾部空格不放行 / 逐字对才放行 / 勾平仓清空 / 旧短语失效 / 更长短语放行 …），基线 **86 → 99**，干净 root 下全绿。

## 六、踩坑（留给下一个）

- **`show_all_pairs` 第 4 次踩**：干净 root 默认 `false` → `ETHUSDT` 不在视野报错；且它是**启动期**读取，改完必须重启服务，重启后 token 也会变。
- **058 当轮漏跑了 `cargo fmt` 与 `clippy`**（2026-10-18 盘点时补跑才发现两道都红）：fmt 差 4 个文件；
  clippy 2 条 `doc_lazy_continuation` / `doc_overindented_list_items`，**全在文档注释缩进**
  （`order_guard.rs:13/43`、`provider.rs:697/698`）。**CI 的 `lint` job 第一件事就是这两条 → 会挂**。
  两个教训：① 提交前**六件门禁要跑全**，别只跑 `cargo test` + 真机两路；
  ② clippy **编译到第一个 error 就停**，必须**迭代到 exit 0** 才算完（058 修完一处才暴露下一处）；
  ③ 文档注释列表续行缩进**别自己数格**（`②` 是 CJK 宽字符，2 格判 lazy、5/6 格判 overindented），
  **照 clippy help 给的那一格改**。
- **token 三路没有 `X-Ricow-Token`**：是 `Authorization: Bearer` / `?token=` / cookie（我一开始猜错头名导致全 401）。
- **探针同 root 不可跑第二轮**：临时探针策略已删 → `/api/strategies/<它>` 404，必须换干净 root（与 `e2e_web.py` 同纪律）。
- **`daemon start` 是前台阻塞的**：同一串命令后面的 `ricow start` 永远不会执行，要另开 shell。
