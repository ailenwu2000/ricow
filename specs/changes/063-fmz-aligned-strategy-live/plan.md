## 1. P0 后端

### 1.1 策略列表补时间字段

`GET /api/strategies` 的 `StrategyRow` 加两个**可选**字段：

```
last_modified: Option<String>   // RFC3339 或 "YYYY-MM-DD HH:MM"
created_at:    Option<String>
```

**取值口径（重要）**：
- 用户策略：读 `strategies/<id>.toml` 与 `strategies/<market>/<id>.lua` 的 mtime，取**较新**者为 `last_modified`；`created_at` 取 `.toml` 的 mtime。
- 内置策略：**无磁盘文件** → 两个字段都给 `None`。
- 读不到（权限/IO 错）→ 给 `None`，**不编造时间**。

**为什么不放 catalog**：catalog 是编译期资产 + 磁盘扫描的混合体，`CatalogEntry` 不带 IO 副作用的时间戳；时间戳是**投影层**的事，在 `strategies.rs::list_strategies` 里算（它已经有 `state.root`）。

**断言**：`declared`/`duplicate_of` 那套"读不到就给 None"的诚实性延续 —— 加一条单测：磁盘上没有文件时两个字段都是 `None`。

### 1.2 新增实例落盘端点

**问题**：现在"改参数"只能通过 `POST /api/strategies`（连带 code 一起存）实现。新建实盘要**只改参数不改代码**，且要能落到实例 TOML。

**新端点**：`POST /api/strategies/{id}/instance`

请求体：
```json
{ "pair": "BTCUSDT", "params": { "atr_mult": 2.0, "flag": true } }
```

行为：
1. id 合法（`validate_strategy_name`）+ 目录审计（`catalog::run_block`）—— 与其它写端点同口径。
2. **内置策略 → 409**（`builtin`）：内置脚本编译期嵌入，改不了。要用先复制。这一条必须明确，否则用户会以为改成功了。
3. **用户策略**：读现有实例 TOML（`strategies/<id>.toml`），**只改 `params` 与 `pair`**，其余（`live_enabled` / `market` / `position_mode` / `backtest` 段）**原样保留**。
4. 落盘走**同一份** `write_strategy_files` 备份语义（先 `.bak`）。
5. 返回 `{ "pair": "...", "params": {...} }`（回读后的实际值，不是回显请求）。

**为什么不复用 `POST /api/strategies`**：那个端点的语义是"保存策略（含代码）"，会让前端必须把 code 一起传上来 —— 新建实盘场景下前端手上**没有**用户的代码改动，硬传会覆盖。

**落盘实现要点**：`StrategyConfig` 的 `params` 是 `HashMap<String, ConfigValue>`；`pair` 在 params 里是**保留键**（前端保留 `script`/`script_path`/`pair` 三键）。所以：
- 写 `pair` → 写进 `params["pair"]`。
- 前端传上来的 `params` 里若含 `script`/`script_path` → **原样保留不覆盖**（那是引擎装载细节，用户不该改）。

**单测**：
- 用户策略改参数 → 落盘后 `live_enabled`/`market` 等未提及字段**没丢**（回归护栏）。
- 内置策略 → 409。
- `params` 里带 `script_path` → 不被覆盖。

## 2. P1 策略库改混排表格

### 2.1 目标形态（对齐 fmz `/m/strategies`）

```
┌ 策略库 ────────────────────────────────── [新建策略 ∨] [搜索框] ┐
│ 名称                最后修改      创建日期      操作项            │
│ 现货智能持仓        2 小时前      2026-10-20    编辑 复制 删除 更多│
│ 合约做多香农网格    3 天前        2026-10-15    编辑 复制 删除 更多│
└───────────────────────────────────────────────────────────────┘
```

- **一张表**混排所有策略，**不再按 现货/合约 × 内置/我的 分四组**。
- 内置/我的用**行内徽章**区分（事实，不是分区）。
- `最后修改` / `创建日期` 读 P0 的字段；**读不到显示 `—`**（不显示"1970"或空）。
- 操作项是**行内文字链接**（fmz 形态），不是按钮。

### 2.2 「编辑」对内置策略的行为

内置策略**不能编辑**（编译期嵌入）。fmz 上内置模板在 `/square` 另一个入口。ricow 的选择：
- 内置行的「编辑」→ **改为「复制」语义的一次点击**：点「编辑」直接打开详情页但**代码区只读**并显示提示「内置策略不可直接编辑，请先复制」+ 一个「复制为我的策略」按钮。
- 用户策略的「编辑」→ 正常进详情。

**为什么不做成"点编辑自动复制"**：那会静默产生新文件，用户不知道自己的"编辑"变成了"新建"。必须显式。

### 2.3 保留不动的

- 「展开」按钮（看说明摘要）→ 保留在名称下方（fmz 的策略名下方也有说明）。
- 诚实性徽章（未声明清单 / 与内置逐字相同 / AI 生成）→ 保留。
- `sg-firststep`（一个自己的策略都没有时的"下一步"引导）→ 保留，但改成放在**表格下方**。

## 3. P2 编辑页双 Tab + AI 助手右置

### 3.1 目标形态（对齐 fmz `/m/add-strategy`）

```
← 返回策略列表        [策略编辑] [模拟回测]
┌ 代码编辑器 ─────────────┬─ AI 助手 ──────────────┐
│                         │ 量化策略助手            │
│                         │ [写一个均线交易策略]    │
│                         │ [写一个带止损止盈的网格]│
│                         │ [分析我的代码有什么问题]│
│                         │ [给代码添加中文注释]    │
│                         │ ─────────────────────── │
│                         │ [指令输入框]  [执行]    │
└─────────────────────────┴────────────────────────┘
```

- 详情页从"一个长页"改成**双 Tab**：代码/参数/清单在「策略编辑」Tab，回测/寻优/历史在「模拟回测」Tab。
- AI 助手**从页面底部的卡片**移到**右侧常驻栏**（fmz 形态）。窄屏（<1200px）降级为 Tab 内联卡片。
- 加 fmz 式**快捷指令按钮**：一组固定短语，点击即填进指令框（**不自动执行** —— 执行要让用户看见改了什么）。

### 3.2 AI 快捷指令清单（对齐 fmz 实测的那些）

固定 6 条（取自 fmz 实测面板）：
1. 写一个均线交易策略
2. 写一个带止损止盈的网格策略
3. 分析我的代码有什么问题
4. 给代码添加中文注释
5. 写一个 RSI 超买超卖策略
6. 写一个双均线交叉策略

**必须能改**：fmz 的这些是可点的建议。ricow 的指令框是自由文本，所以快捷指令 = **预填文本**，用户可改后执行。

### 3.3 「模拟回测」Tab 的内容

把现有的回测卡 + 寻优 + 样本外 + 历史**整块搬进这个 Tab**（不改逻辑，只改位置）：
- 配置参数：交易对 / K线周期 / 天数 / 高级（费率 / 初始资金 / 杠杆）
- **初始资金**：沿用 058 口径 —— 真值 = 实例 TOML `[backtest].initial_cash`；**读不到就不渲染该字段**（不猜 10 万）。
- 跑完出结果 → **「AI 解读」按钮**接 `ai-assess`（已有端点），形成"跑回测 → AI 解读"闭环（需求 4）。

## 4. P3 实盘视图 + 新建实盘表单

### 4.1 实盘视图（`#runs` 改形态，不改路由）

列名对齐 fmz：

| fmz 列 | ricow 现在 | 本轮 |
| -- | -- | -- |
| 名称 | 名称 | 名称 |
| 托管者 | —— | **不做**（ricow 无托管者） |
| 状态 | 状态 | 状态 |
| 盈利 | 净收益 | **盈利** |
| 创建日期 | —— | **不做**（实例无创建时间概念；或用台账首见时间？→ **不做**，避免造事实） |
| 策略 | 来源 | **策略**（值改成策略名） |
| 操作 | 操作 | 操作 |

**新增列**：`模式`（dry_run/demo/live）—— fmz 没有（它只有实盘），但 ricow 有三模式，**这一列是 ricow 的事实，不能丢**。放最后。

> 诚实性取舍：为了"对齐 fmz"而丢掉 ricow 的真实信息（模式、成交数、运行时长）是倒退。**做法**：列名对齐 fmz 的可对齐部分（盈利/策略），ricoy 独有的列**保留并加宽**，不去掉。

### 4.2 新建实盘表单（替换现在的弹窗）

对齐 fmz `/m/add-robot/` 的字段序：

| # | 字段 | 控件 | 数据源 |
| -- | -- | -- | -- |
| 1 | 实盘名称 | 输入框 | 缺省 = 策略名（可改；**改名 = 复制实例**，见下） |
| 2 | 运行策略 | **可搜索**下拉 | `GET /api/strategies` 全部（内置+我的混排） |
| 3 | 策略参数 | 参数表单（类型/默认值/说明） | 选中策略的 manifest params + 当前值 |
| 4 | 交易对 | 输入框 + 常用下拉 | 沿用现有 `sg-bt-pair` 的输入方式 |
| 5 | 模式 | 单选：模拟 / 模拟盘 / 实盘 | 沿用 `dry_run`/`demo`/`live` |
| 6 | —— | 实盘时额外：逐字确认短语 + 风险披露 | 沿用现有 `runs.js` 的门禁（**一字不改**） |

**新建的两种情形**：
- **选「我的」策略** → 调 `POST /api/strategies/{id}/instance`（P0）写参数 → 调 `POST /api/strategies/{id}/start` 启动。**不改策略名**。
- **选「内置」策略** → 内置不能直接改实例 → **先复制**（`POST /api/strategies` 带 `copy_from`）→ 再落参数 → 再启动。**名称用用户填的实盘名**。

### 4.3 「创建实盘」的落点

fmz 是"创建实盘"（只创建，不启动）。ricow 的 `start` 是"启动实例"。

**决定**：按钮叫**「创建并启动」**，一步做完（创建参数 + 启动）。理由：ricow 没有"已创建但未运行"的实例概念（`strategies/<id>.toml` 既是配置也是实例），分两步会让用户以为有个中间态。

## 6. 风险与已知难点

| 风险 | 处置 |
| -- | -- |
| 改策略页 DOM 会撞 053（参数未保存提示）与 059（离开守卫） | 这两处的锚点 ID **一个字都不改**，只挪位置；改完必跑这两条相关的真机断言 |
| 双 Tab 切换会丢未保存状态 | 切 Tab **不销毁 DOM**（只是隐藏），离开页面才触发离开守卫 |
| `POST /{id}/instance` 写坏实例 TOML 会让策略跑不起来 | 走 `write_strategy_files` 的 `.bak` 备份；落盘后**回读校验** |
| 快捷指令按钮点多了会误执行 | 快捷指令**只填文本不执行** |
| 「实盘」视图名与「运行」重复 | 侧栏保留「运行」文案（用户熟悉），只在**页头**写「实盘」；或者——见 §7 待拍板 |
| 内置策略当"运行策略"被选后不能落参数 | 走复制路径（§4.2），并在表单里**先提示**「内置策略将先复制为你的策略」 |
