### 掩盖掉的真问题一：K 线缓存路径与直连路径**行为不一致**（产品 bug，已修）

- 现象：需要 aux 预热的策略（如 `linear_position_grid`）在**缓存命中**时恒报「预热段不足: 请求 24 根高周期历史, 交易所只有 23 根」，而同一窗口**直连交易所能跑通**。
- 根因：`get_klines_range` 用**闭区间** `open_time <= end_ms`，而调用方拿到数据后按 `open_time < window_end` 裁掉末根（**窗口本就是半开的**）。两个语义打架 → 窗口根数比调用方以为的多一根 → `ORDER BY open_time DESC LIMIT N` 把**最早那根挤掉** —— 而那根正是预热段的第一根。
- 修法：区间查询改成**半开** `[start, end)`，与调用方语义统一。
- 回归断言：`test_get_klines_range_is_half_open_and_keeps_oldest_when_exact_fit`（半开语义 + 窗口根数恰等于 limit 时最早一根不能被挤掉）。旧单测的期望值同步改为半开口径。

### 掩盖掉的真问题二：新建实盘**参数根本没落盘**（产品 bug，已修）

- 现象：新建实盘弹窗走完 → 弹窗照常关闭、实例照常启动，但**回读实例 TOML 时参数是空的**。
- 根因：新建实盘用**隐藏 `<select>`** 承接选中的策略 id，而那个 select **从来没被填过 option** —— 浏览器对"不存在的 value"会把 `select.value` 置成**空串**，于是 `currentStrategy()` 取到 `""`，提交时按"没选策略"**提前返回**，参数一个都没落。
- **迷惑性**：症状是"弹窗关了、启动发生了"，只有**回读落盘结果**才看得见 —— 不回读就发现不了。
- 修法：选中策略时先往 select 里补 option，再赋 value。
- 回归断言：`test_new_live_select_gets_a_real_option_before_assigning_value`（钉住"补 option 在赋 value 之前"）。

### 本轮又挖出两个真问题（都已修 + 回归断言）

#### 真问题四：默认交易对硬编码 `BTCUSDT`，与默认配置自相矛盾

- **现象**：新装 ricow（默认 `[market].show_all_pairs = false`，**视野里只有股票类**）→ 点「新建策略」/「复制」/「新建实盘」→ 默认交易对是 `BTCUSDT` → 提交必然撞视野门禁「交易对 BTCUSDT 不在当前视野」。
- **根因**：`strategies.js` 里 `DEFAULT_PAIR = "BTCUSDT"` 硬编码，三处表单（新建策略 / 复制 / AI 生成）都拿它当默认值。
- **谁对谁错**：**门禁是对的**（它如实拦住视野外的对），**错的是表单给了一个自己都跑不起来的默认值**。
- **修法**：
  1. 新增 `S.defaultPair()` —— 从 `/api/markets`（**视野端点**，返回的就是视野内的列表 + `filtered` 标志）取第一个现货对；拉不到才回落 `BTCUSDT`。
  2. 新增 `S.fillDefaultPair(input, fallback)` —— 异步回填，且**只在用户没改过这个值时**才回填（晚到的异步结果不能抹掉用户输入）。
  3. 三处默认交易对都走它（断言钉住"恰好 3 处"且"不许再有硬编码赋值"）。
  4. **新建实盘选中策略后**再做一次视野校验（`syncPairScope`）：策略自带的 pair 不在视野里就换成视野内的，并给一句说明「原值 → 现值 + 请复核价格类参数」。拿不到视野时**不动**（交给门禁如实报，不猜）。
- **回归断言**：`test_default_pair_comes_from_market_scope_not_hardcoded`、`test_new_live_checks_pair_scope_after_selecting_strategy`。

#### 真问题五：文案占位符只替换了第一个匹配

- **现象**：视野说明里残留了未替换的 `{0}`（截图里一眼看到）。
- **根因**：`String.prototype.replace` **只替换第一个匹配**；文案里 `{0}` 出现两次 → 第二次原样留在界面上。现有文案机制是 `t(key).replace("{n}", 值)`，全部单占位符，所以从未暴露过这个问题。
- **修法**：改用 `replaceAll`，并把文案里的重复引用改成不重复的表述。
- **回归断言**：视野那条断言钉住 `replaceAll("{0}", want).replaceAll("{1}", fallback)`。

### 探针自身的教训（本轮新增）

1. **保存成功的判据是全局 toast，不是 `#sg-savemsg`** —— 后者是**错误位**（成功时是空的）。拿它当成功判据会永远等不到，症状是"保存没给出结果"（假红）。
2. **回测参数里的价格类必须按真实价格重算** —— 换个交易对后价格差几个数量级，参数不跟着调 → 价格全在区间外 → **0 成交**。判据：键名是 `start_price`/`p_low`/`p_high` 这类"价格锚"。
3. **别用正则猜每个参数该给什么值** —— `low` 会把 `pos_low_pct`（仓位占比 0.7）误当成价格下沿。正确做法：**优先用实例里已落盘的值**，只对"代码读了但实例没有"的键补默认。
4. **参数提取要认多种写法** —— AI 生成的代码用 `ctx:config_f64("k")`，内置策略用 `param(ctx, "k")`/`num(ctx, "k", ..)`。只认一种 → 提取出空列表 → 回测不给参数 → 误判成"AI 改坏了"。
5. **AI 生成的代码可能与原策略完全不同** —— 所以断言不能钉"某个具体实现"，只能钉"**代码真的变了**"+"**指令要求的符号真的出现了**"。

### 顺带记录：AI 新加的参数不在清单里

AI 在 `code` 模式下新增了 `ma_period`，但**清单里没有这一项**（清单是复制时派生的 19 项）。两个后果：
- `ctx:config_f64("ma_period")` 对未声明键返回 **0.0**（不是 nil）→ 代码里 `ma_period <= 0` 恰好等于"关闭过滤"，**默认不生效**；
- 参数表单画不出这一行 → 用户在界面上**改不了它**。

这是「AI 改代码模式只改代码、不改清单」这一既定设计的固有结果（清单是用户显式声明的）。**本轮不扩范围去改**，但已记在此处，供后续决定要不要做「AI 改完代码后提示补声明参数」。

## 3. 后端新增能力

### `POST /api/strategies/{id}/instance` —— 只改参数与交易对

**为什么要有这个端点**：新建实盘要"选策略 + 设参数"，但**不该碰用户的代码**。既有的 `POST /api/strategies` 语义是"保存策略（含代码）"，它要求前端把 Lua 传上来 —— 新建实盘时前端手上没有代码改动，硬传会把用户的代码覆盖成旧版本。

三条纪律各有单测守着：

**加强后的断言形态**（可复用的经验）：

- 钉**取值表达式**（`fmtRelTime(s.last_modified)`）而不是字段名 —— 否则"换成常量但保留一句 `void (s.last_modified)`"就能骗过它。
- 钉**对象字面量里的键**（`cells: { ... }` 的五个键）而不是"某处含 `created:`" —— 否则删掉一个键断言仍绿。
- 钉**整个函数体**（`applyTab`）而不是其中一行 —— 否则在别处加一句 `innerHTML = ""` 断言仍绿。
- 锚点带**引号**（`"/instance"` 而不是 `/instance`）—— 否则子串匹配会把 `/instanceZZZ` 也算命中。
- 顺序断言要排除**注释行** —— 文件头的注释里也写着 `/api/strategies/{id}/start`。
