# 优化策略制订流程的计划（054）

> 依据：[`audit.md`](./audit.md) —— AI 策略生成逻辑审核报告
> 目标：让**普通投资者**在 ricow 上能按「我是谁 → 我想做什么 → 做出来 → 验证 → 敢用」的顺序，配置一份**自己理解得了、且经过验证**的量化策略
> 编号：054（`ls specs/changes/` 最大 053；054–056 无占用，058/059 已被 019 的 FR 编号占用——FR 编号与变更编号不同域）

---

## 〇、设计原则（先立规矩）

1. **不新增引擎能力，先把已有能力接通**。回测引擎、无前视防护、确认门、口径规范都已存在且扎实。本计划的核心是**编排**，不是重造。
2. **两条链路收敛，不各做一套**。Web 生成与对话生成的差异（有/无回测）是本轮认定的**缺陷**，不是"两条产品线"。收敛方向：**Web 向对话链路的能力看齐**（生成即回测）。
3. **结构化输入必须真被使用**。新增的每个字段都必须出现在提示词里、或被后端用于校验，否则就是装饰。
4. **诚实优先于好看**。滑点假设、历史不代表未来、AI 未经验证、平台不做风控——这些"不利信息"必须出现在用户决策时刻，而不是藏在文档里。
5. **不替用户做投资决策**。平台不设风控限额是有意设计（宪法立场），本计划**不推翻它**；要做的是**让用户知道自己承担了什么**。

## 二、P1：生成即验证（Web 链路接回测闭环）

### 目标
用户点「生成」后，**看到的不是一段代码，而是一份带回测结果的策略**。

### 方案（两条备选，推荐 A）

**A. 生成后自动跑一次默认窗口回测，结果随生成一起返回（推荐）**

```
POST /api/strategies/ai-generate
  ↓ 编译门禁（现有）
  ↓ 自动入队一次回测：窗口 = 90 天 / 生成时选定的 interval / 生成时选定的 pair
  ↓ 返回 { code, warnings, backtest_summary }
前端：生成成功 → 详情页回测卡**直接显示这次结果**（复用现有 renderJob / renderMetricCards / renderBtChart）
```

- **复用**：`backtest_jobs.rs` 已有作业队列 + 轮询；`renderJob`/`renderMetricCards`/`renderBtChart` 已有完整渲染；`runParamAssess` 已有"跑回测 + 等结果"的编排范式（`strategy_backtest.js:1072-1092`）。
- **关键设计**：窗口**写死并在 UI 明示**（与 `ASSESS_DAYS=90`/`ASSESS_INTERVAL="1h"` 同思路——不同窗口比出来的差异分不清是参数还是窗口造成的）。
- **超时**：沿用 `ASSESS_TIMEOUT_MS`（10 分钟）如实报超时，**不静默降级**（与实时行情三态 chip 同一纪律）。
- **不可用情形**：AI 未配密钥、网络不可达（`api.binance.com` 返回 `000`）→ 回测失败要**如实说"未能验证"**，并保留「手动跑一次」按钮，绝不能让用户误以为已验证。

**B. 不自动跑，但把「跑一次验证」做成生成后的唯一主行动按钮**
改动更小，但用户仍可跳过 → 不推荐。

### 验收判据
- 生成成功路径：用户**无需任何额外点击**即看到 6 张指标卡 + 权益曲线 + 基准虚线。
- 回测失败路径：详情页明确显示「未验证（原因：…）」+ 重试入口，**不显示任何指标卡**。
- e2e 断言：新增「ai-generate 回包含回测摘要」+「回测失败时不出现指标卡」两条。

### 顺带修 #7（报告截断）
`clamp_output` 8000 字符对回测报告过紧。改为：**结构化摘要优先**（把报告拆成"概览/成本/风险/成交"分块，按预算从前往后填，**末尾附 `[已截断：剩余 N 字符]`**），或对 `run_backtest` 单独提高上限并把完整报告落 run card 供 `read_doc` 式按需取。**不允许静默截断**——模型必须知道有东西没看到。

## 三、P2：投资意图入口（结构化收集约束）

### 目标
把"稳一点""激进一点"翻译成**可被提示词和校验使用的数字**。

### 新增字段（`AiGenerateRequest` + 生成弹窗）

| 字段 | 类型 | 必填 | 用途 |
|---|---|---|---|
| `initial_cash` | f64 | ✅ | 直接写入策略 TOML `[backtest]`，回测口径与用户真实资金一致 |
| `risk_tolerance` | enum: `conservative` / `balanced` / `aggressive` | ✅ | 映射到**明确数字**后进提示词（见下表） |
| `max_drawdown_pct` | f64 | 可选 | 有则写进提示词要求策略自实现回撤止损（`ctx:net_pnl()`/`ctx:equity()`） |
| `max_position_pct` | f64 | 可选 | 单笔最大仓位占权益比 |
| `leverage_cap` | f64 | 仅合约 | 合约杠杆上限 |
| `constraints` | textarea | 可选 | 保留（自由补充），**不再是唯一风控入口** |

### 关键设计：`risk_tolerance` 必须映射成数字，不能只传词

提示词里**不能出现"保守一点"**这种词——它无法校验，也无法解释。应映射为可执行约束：

```
conservative → 最大回撤目标 ≤ 10%; 单笔仓位 ≤ 10% 权益; 无杠杆或 ≤ 2x;
               禁止无止损的加仓; 优先低换手
balanced     → 最大回撤目标 ≤ 20%; 单笔仓位 ≤ 25% 权益; 杠杆 ≤ 3x
aggressive   → 最大回撤目标 ≤ 40%; 单笔仓位 ≤ 50% 权益; 杠杆 ≤ 5x
```

（具体数值需在 `plan.md` 阶段与领域口径确认，此处为示意；**映射表必须单点定义**，提示词与前端提示同一来源。）

### 后端校验（"结构化输入必须真被使用"）
- `initial_cash > 0`，`max_drawdown_pct ∈ (0, 100]`，`max_position_pct ∈ (0, 100]`，`leverage_cap ∈ [1, 10]`（与 `max_leverage` 上限一致）。
- 选了 `market=spot` 却给了 `leverage_cap` → 400（现货无杠杆，**不接受无效输入**）。
- 所有字段**必须出现在 `build_generate_prompt` 的输出里**——加一条单测断言提示词包含每个非空字段。

### 对话链路同步（`RULES`）
`RULES` 的「生成前问清」软提示升级为**结构化追问清单**，并要求：**未收集到资金与风险偏好时不得直接生成**（先问）。这是把"模型不问就丢"变成"必须问"。

### 验收判据
- 单测：提示词包含 `initial_cash` / 风险档位映射后的具体数字；现货+杠杆组合返回 400。
- 前端：生成弹窗字段可填、有校验、有默认值；**风险档位选择后立刻显示它对应的数字含义**（不能让用户以为选个词就够了）。

## 四、P3：认知护栏（风险披露与来源标记）

### P3-1 生成弹窗风险提示（#3）
在「生成并保存」按钮上方加固定提示条，文案要点：
- 这是**能真实下单**的交易代码；
- **未经实盘验证**，回测结果不代表未来；
- 平台**不代做风控**，仓位与止损由策略自己负责 —— 请在使用前确认代码里有止损。

**不做成可勾选确认框**（生成阶段就要求确认会滥用确认语义，稀释 live 启动那个真正重要的门禁）；做成**常驻提示条**即可。

### P3-2 策略来源标记（#3）
- `GET /api/strategies` 增加 `origin` 字段：`builtin` / `user` / `ai`（**落盘时写入**，不能事后猜）。
- 列表行与详情页显示「AI 生成 · 未验证」徽章；**回测跑过一次后**变为「AI 生成 · 已验证（<窗口>）」。

**关键**：徽章必须由**服务端事实**驱动（是否跑过回测、跑的是什么窗口），不能由前端自己记 —— 与 `help.js` 引导条"判据全是服务端事实"同一纪律。

### P3-3 回测指标卡免责（#11）
指标卡区固定一行：「同一段历史窗口的回测结果，**不代表未来收益**；滑点假设见下方口径说明」。文案与 AI 评估提示词第 5 条同源，避免两处说法不一致。

### P3-4 成本假设显式化（#4）⭐ 这条最容易被忽略但影响最大
回测卡高级项里把**当前生效的成本假设**（费率/滑点/限价穿透）**显示在指标卡旁**，而不是折叠在 `<details>` 里：
- 滑点为 0 时明确提示：「**滑点假设为 0（乐观）**：网格/高频类策略的收益会被系统性高估」。
- 提供「按千分之 N 滑点重跑」的一键入口。

理由：用户看到"年化 +80% 曲线漂亮"时，**没有任何线索**知道这是零滑点下的数字。这一条比任何免责声明都有效。

### P3-5 平台风控立场说明（#13）
在帮助层（`help.js`）与生成弹窗提示条里各写一次「平台不代做风控」的**用户可读版本**（不是 `TRAPS_GUIDE` 那种给模型看的版本）。

## 五、P4：稳健性验证（样本外与过拟合防护）

> 本阶段的定位：**先给用户"这是不是巧合"的判据**，而不是一步到位做 walk-forward 引擎。

### P4-1 样本外切分（优先，改动最小）
回测增加「样本内 / 样本外」显示模式：
- 自动按 70/30 切分，指标卡同时给出**两段**的净盈亏与最大回撤；
- **样本外表现显著劣于样本内**时，显式打标：「⚠️ 样本外表现明显退化，可能存在过拟合」。

这条不需要新引擎能力（就是跑两次回测、切窗口），但能把"回测赚钱"和"策略有效"区分开——对普通投资者是**认知上最关键的一步**。

### P4-2 把 `optimize` 暴露给 AI（#6）
- 加入 `VIRTUAL_TOOLS`（只读计算结果、不落盘；`--write-back` 走既有确认门）。
- **必须同时**解决 #12：修正 `--metric annual_return` 名不副实（`optimize.rs:154-155` 实际按 `net_pnl` 排序），并加单测锁住三个 metric 的排序行为。
- `RULES` 增加指引：「参数寻优结果**必须**配合样本外检验才能下结论」。

### P4-3 walk-forward（**本轮做**，用户明确要求）

> ⚠ 本段已按 2026-10-14 决策改写：原写的是"本轮只做设计文档、不实现，留独立变更 055"，
> 用户明确「**这个很重要，本轮必须做**」，故纳入本轮交付。完整规格见 [`spec.md`](./spec.md) §八。

两种形态，**切分逻辑不同，不要混实现**：

| | 形态 A：固定参数（**默认**） | 形态 B：每轮重寻优（**可选开关**） |
|---|---|---|
| 参数 | 全程不变 | 每轮用验证段之前的数据重新寻优 |
| 切分 | 窗口均分 N 段，每段独立回测 | 第 i 轮 `[起点,T_i]` 寻优 → `(T_i,T_{i+1}]` 验证 |
| 回答 | 策略在**不同行情阶段**都行吗 | 我的**调参过程**是不是在过拟合 |
| 成本 | **N 次回测** | **N × 100 次串行回测**（`MAX_COMBOS=100`，`optimize.rs:218` 串行） |
| 依赖 | 无，**可先行交付** | 依赖 P4-2（`optimize` 接通） |

**为什么重寻优必须是可选开关**：成本高两个数量级（3 次 vs 300 次串行回测），
且 Web 层同一策略同时只允许一个 running 作业（409 busy，`backtest_jobs.rs:37,88`）无法叠加并发。
不是功能次要，是**成本高两个数量级**。

**段数自动决定**（D10，可单测）：`段数 = clamp(floor(总天数/60), 2, 5)`，且**每段 ≥ 30 天**否则报"样本不足"。
→ 30天→报不足 / 60天→2段 / 90天→2段 / 180天→3段 / 360天→5段（上限）。
形态 B 段数上限压到 **3**（成本高，3 段已够看参数稳定性）。

**术语纪律**：形态 A 严格说是"滚动窗口分析"，经典 walk-forward 指形态 B。
UI 文案**不要统称 walk-forward** —— A 说「分段验证」，B 说「滚动验证（含重新调参）」。

**呈现**：形态 A 每段一组指标并排 + 离散度提示；形态 B 拼出样本外曲线，与 A 的全窗口曲线并列（图例说明两条线含义不同）。
开关处**必须明码标价**「含重新调参：约 N×100 次回测，可能达十分钟级」。走异步作业 + 进度，失败/超时如实报。

### 验收判据
- 单测：样本外切分边界（窗口过短时如实报"样本不足"，不硬切）；三个 metric 排序各自正确。
- 前端：过拟合警示标只由服务端算出的两段指标驱动。

## 七、风险与反向考虑

| 风险 | 应对 |
|---|---|
| **P1 自动回测拖慢生成**（生成 1–2 分钟 + 回测） | 回测与编译**分离返回**：编译通过即返回代码并落盘，回测**异步展示**在详情页（进度条+超时如实报）。不阻塞用户。 |
| **P1/P4 增加回测压力** | 复用 `backtest_jobs` 的 409 busy / 队列；生成触发的回测标记为低优先级，避免挤占用户主动发起的回测。 |
| **P2 字段太多把用户吓跑** | 风险档位是**单选**，资金有默认值；`max_drawdown_pct` 等高级项折叠在"高级"里，**但档位映射的默认值必须可见**。 |
| **P3 提示条变噪音被无视** | 只保留 4 条最高价值提示（风险/未验证/滑点/不代做风控），其余进帮助层。宁少勿多。 |
| **P2 后风险档位映射表被各处抄一遍** | **单点定义**（后端常量），前端文案与提示词都从它派生；加一条"三处一致"的单测。 |
| **推翻"平台不做风控"立场** | 明确**不推翻**。P3 只做"让用户知道"，不改引擎风控语义。若将来要加，是独立变更。 |

## 八、验收总纲

沿用项目既有纪律，**五道门 + 真机两路**：

1. `cargo fmt --all -- --check` 零差异
2. `cargo clippy --workspace --all-targets -- -D warnings` 零告警

7. `scripts/probe_web_ui.mjs` CDP 真机走查 —— 基线 **86**

**基线两处镜像**（`specs/roadmap.md` 权威 + `specs/architecture.md` 第九节）**必须一起改**。

### 本阶段特有验收
- **真跑 AI**（与 e2e 分开起服务，密钥走 `RICOW_AI_API_KEY`）：
  - P1：真实生成一次，确认**自动回测真的跑起来且结果真的展示**（053 的教训：离线单测只能验证"提示词里有没有这段话"，测不出端到端是否真的接通）。

## 九、实施顺序建议（可分批落地）

```
第一轮（最小可见价值，建议先做）
  P1 生成即验证  +  P3-4 成本假设显式化
  → 用户立刻能"看到策略跑起来是什么样"，且知道这个数字有多乐观

第二轮（输入侧）
  P2 结构化约束 + P3-1/3-2/3-3 认知护栏
```
