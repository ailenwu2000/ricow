# AI 策略生成逻辑审核报告

> 审核对象：ricow 的「AI 生成量化策略」全链路
> 审核视角：**一个普通投资者**（不懂 Lua、不懂量化、想用真金白银或模拟仓跑策略）
> 审核日期：2026-10-14
> 方法：源码走查（`crates/ricow/src/ai/`、`crates/ricow/src/web/`、`crates/ricow_strategy/src/`）+ 文档核对（`specs/lua-api.md`、`specs/backtest.md`、`specs/architecture.md`）

---

## 〇、一句话结论

**工程上很扎实，产品上「不像给普通投资者用的」。**

ricow 的 AI 策略生成在三件事上做得比一般开源量化框架好：**编译门禁硬、写操作确认门严、回测口径诚实**。但从「普通投资者配置量化交易」这个目标看，它缺的不是能力，而是**把能力按人的决策顺序组织起来的那一层**：

| 缺口 | 一句话 |
|---|---|
| **没有投资要素入口** | 风险偏好、可用资金、能接受多大回撤 —— 全程只能塞进一个名叫「风控与约束」的自由文本框 |
| **没有验证闭环** | Web 生成后只过编译门禁，**从不回测**；用户拿到代码时根本不知道它历史上会不会爆仓 |
| **没有过拟合防护** | 无样本内/外切分、无参数稳定性检验；`optimize` 明确"不做过拟合检测" |
| **没有实盘预期管理** | 生成环节零风险提示；回测指标卡旁无「历史不代表未来」；滑点默认 0 却没人告诉用户 |
| **AI 看不到完整报告** | 回测报告经 8000 字符截断，策略统计/基准区块/窗口口径可能被切掉 |

---

## 一、链路现状：其实有**两条** AI 生成链路，能力不对等

审核中最关键的结构性发现：项目里存在两套完全不同的 AI 生策略机制。

| | **链路 A：对话助手**（`ricow ai`） | **链路 B：Web「AI 生成」**（`POST /api/strategies/ai-generate`） |
|---|---|---|
| 入口 | `ai/session.rs` 多轮工具循环 | `web/strategy_io/mod.rs:1839` 单轮 |
| 编排 | `max_turns` 默认 8，模型自由调工具 | 单次 LLM 调用，`tools=[]` |
| 结构化输入 | **无**（靠模型自觉追问） | market/pair/interval/idea/constraints 5 字段 |
| 提示词 | `prompt.rs::RULES`（精简常驻 <3300B）+ `read_doc` 按需取 | `provider.rs::build_generate_prompt:697` 一次性塞 lua-api 全文 |
| **回测验证** | ✅ `preview_strategy` 生成后**立即跑真实 K 线沙箱回测**，报告文本回给模型 | ❌ **只过编译门禁 + 静态 lint，不跑回测** |
| 迭代修正 | 半自动（模型可自主重写再 preview） | 无 |
| 落盘 | 用户回确认词 | 前端另调 `POST /api/strategies` |

**这是最刺眼的一处不一致**：能力更强的链路（能回测、能自我修正）藏在**终端对话**里；而普通投资者唯一会用的**图形界面**，走的恰是**最弱的那条**（无回测、无迭代）。

> 一个普通投资者打开 Web 界面 → 填表 → 点「生成并保存」→ 得到一份**从未跑过回测的 Lua 代码**。他看到的只有「编译通过」。这与"用 AI 帮我配量化"的心理预期差距很大。

## 二、逐维度审核

### 维度 1：投资要素收集 —— **不合格**

**现状**：Web 生成弹窗（`strategies.js:1279-1414`）只有 6 个字段：

```
策略名 / 市场(现货·合约) / 交易对 / K线周期 / 策略思路(textarea) / 风控与约束(可选 textarea)
```

- ✅ **交易对、周期、市场**：有独立字段，且周期走白名单（`1m/5m/15m/1h/4h/1d`）。
- ❌ **可用资金**：生成弹窗里**没有**。`initial_cash` 只出现在回测卡的折叠高级项里（`strategies.js:859`）。
- ❌ **风险偏好**：**没有结构化控件**，只有自由文本 `constraints`，后端原样拼进提示词（`provider.rs:707`），缺省填 `"无特别约束"`。
- ❌ **止损/最大回撤容忍/单笔仓位比例/杠杆上限**：全无字段。
- ❌ **对话链路完全无收集**：`RULES` 里只有一句软提示「生成前问清: 交易对、市场、资金量/下单量/频率/阈值」——**只是给模型的指令，无代码层校验，模型不问就丢**。

**对普通投资者的后果**：他说"我想稳一点" —— AI 只能凭这句话猜。而"稳"对量化而言是几个具体数字（年化波动率上限？回撤容忍？仓位比例？），**没有入口收这些数字，模型就只能生成一个看起来合理的随机策略**。

**一个具体的自相矛盾**：`build_generate_prompt` 第 7 条要求「依据上面的风控约束」做止损/仓位上限，但那个 `constraints` 字段**缺省是"无特别约束"**——即默认情况下，这句要求指向一个空对象。

---

### 维度 2：产物约束与校验 —— **合格偏优（工程侧）**

| 检查项 | 结论 | 证据 |
|---|---|---|
| 策略名合法性 | ✅ 硬校验：`[A-Za-z0-9_-]`、≤24、**不得互为前缀**（防订单归属前缀塌缩误撤单） | `create.rs::validate_new_name` |
| 内置名占用 | ✅ 409 `reserved` | `strategy_io/mod.rs:1861` |
| 同名冲突 | ✅ 生成**前**就 409，不让用户白等一轮 AI | `strategy_io/mod.rs:1884` |
| Lua 编译 | ✅ 硬门禁，与保存同一路径，**失败零副作用** | `ricow_engine::create_strategy` |
| Lua 静态 lint | ✅ 5 类陷阱（`fill.price`/`or` 陷阱/沙箱禁用库/`type=`误用/`while true`） | `lint_lua` `strategy_io/mod.rs:373-416` |
| 参数类型 | ✅ 仅 String/Float/Integer/Boolean | `tools.rs:886` |
| 写操作权限 | ✅ **模型没有任何写实工具**；13 类写操作全走「登记 pending + 用户回确认词」 | `tools.rs:62-89`、`confirm.rs` |

**这一维度是项目最硬的部分**，应保留并作为后续扩展的模板。唯一瑕疵：`lint_lua` 只覆盖 5 类，**不检查"有没有止损"**——而 `build_generate_prompt` 第 7 条恰恰要求必须有止损或仓位上限。**要求了但没验证**。

---

### 维度 3：生成 → 回测 → 修正闭环 —— **不合格（Web 侧）**

**对话链路**：有"半环"。

```
preview_strategy (tools.rs:835)
  → create_preview (create.rs:76)
  → 拉真实 K 线 + Engine::backtest_and_preview
  → 返回 format_backtest_report 文本给模型  ← AI 真的能看到回测结果
```
但**没有自动化**：提示词里没有「回测不佳必须迭代」的硬规则，全靠模型自主决定重写。

**Web 链路**：**零闭环**。

```rust
// strategy_io/mod.rs:1901-1905
ricow_engine::create_strategy(name, &code, pair, HashMap::new())
    .map_err(|e| WebError::compile_failed(...))?;
let warnings = lint_lua(&code);
Ok(Json(AiGenerateReply { code, warnings }))   // ← 到此为止，不跑回测
```

**对普通投资者的后果**：他拿到的策略**从未被验证过**。而项目里明明有完整的回测引擎、有 `POST /api/backtest`、有现成的 `runParamAssess` 编排——**零件都在，就是没接起来**。

**一个真实的次生风险**：`run_backtest` 工具返回的报告经 `clamp_output` 截断到 **8000 字符**（`tools.rs:97`）。实测报告正文（概览+净盈亏分解+基准区块+成交统计+风险收益+分侧统计+生效参数+窗口口径）很可能超过 8000 —— **AI 可能只看到报告前半部分**，恰好丢掉「策略统计」与「窗口口径说明」。

---

### 维度 4：回测保真度 —— **良好，但有"默认乐观"陷阱且未向用户披露**

**做得好的**：
- ✅ **无前视防护体系完整且有回归测试锁死**（`on_tick` 只见当前 bar open；指标只喂已收盘 bar；`ctx:klines` 尾窗化无未来根；有测试断言成交价≈建仓日 open 而非 close）
- ✅ **数据缺口硬报错拒绝回测**，不静默跳过（`gaps.rs::find_gaps`）
- ✅ **报告口径规范 v1**：百分比强制带绝对值、真实成本不得消失、期末无仓不得只写 0
- ✅ 手续费非零（现货 10bps；合约 maker 2 / taker 5bps）
- ✅ 基准 = 买入持有对照，**且基准线建仓前是空白不要画 0**
- ✅ `run card`（`run/backtest/*.json`）留源代码 sha256 + 参数快照 + 数据窗口，可做机器比对
- ✅ `--sensitivity` 成本敏感性扫描

**陷阱（用户不知道的）**：

| 陷阱 | 影响 | 是否披露 |
|---|---|---|
| **滑点默认 0** | 网格类策略成交率与收益**系统性高估** | ⚠️ 只在策略 TOML/CLI 参数说明里；**UI 未提示** |
| **限价单"触及即成交"**（`limit_fill_penetration_bps` 默认 0） | 忽略排队位置，乐观 | ⚠️ 报告里有一行提示，但需用户读到 |
| **基准从首次成交价起算**（`backtest.rs:1491-1495`） | 建仓前空仓期归零，跨参数对比时基准不可直接比 | ✅ 已写进 `AI_ASSESS_PREAMBLE` 并单测锁住 |
| **夏普分母只有 `1e-18` 数值容差**（`metrics.rs:94`） | 成交笔数极少/低波动时被放大到失真（实测 −9 → −737） | ✅ 已写进评估提示词 |
| **OHLC 合成撮合**、整单成交、MMR 单层近似、资金费常数 | 与实盘有系统性差异 | 📄 引擎自认，但用户看不到 |
| **`optimize --metric annual_return` 名不副实** | 实际按 `net_pnl` 排序（`optimize.rs:154-155`） | ❌ 未标注 |

### 维度 5：过拟合 / 参数寻优 —— **能力存在但 AI 用不上，且无防护**

| 能力 | 现状 |
|---|---|
| 网格搜索 | ✅ `ricow optimize`：`--param key=v1,v2` 多键笛卡尔积、`grid\|random`、上限 100 组合 |
| **是否暴露给 AI** | ❌ **不在 AI 工具白名单**（`READ_ONLY_TOOLS` 15 个 + `VIRTUAL_TOOLS` 3 个，均无 `optimize`/`sweep`） |
| 走查验证 walk-forward | ❌ **完全没有**（代码/文档 grep 无命中） |
| 样本内/外切分 | ❌ 回测就是单窗口全段 |
| 过拟合检测 | ❌ `optimize.rs:1-4` 明确写着"不做智能搜索与**过拟合检测**" |
| 参数稳定性/敏感性矩阵 | ❌ 仅单轴成本敏感性 `--sensitivity` |

**这是最大的"看起来能做但 AI 实际做不了"的缺口**：一个有完整网格寻优能力的项目，AI 助手既不能调用它，系统提示里也不提它。

**对普通投资者的后果**：AI 生成的参数是**单次拟合的产物**，没有样本外验证。用户会误以为"回测赚钱 = 策略能赚钱"，而实际上这极可能是曲线拟合。

### 维度 6：前端呈现与用户认知 —— **交互成熟，但缺"投资"视角**

**做得好的**：
- ✅ 中英双语完备（470·470 键对齐），静态标签 `data-zh/data-en` 就地刷新
- ✅ 术语表全局单例，回测指标/图例/表头可点（`R.glossary.decorate`）
- ✅ 回测结果呈现完整：6 张指标卡（涨红跌绿）+ 权益曲线 + 基准虚线 + 回撤副图 + 平仓明细 + 策略日志 + 完整文本报告
- ✅ `sgSendToAi` 可把回测结果一键填回 AI 输入框（只填不发，用户仍可改）
- ✅ 诚实性口径贯穿：「未声明清单」「与内置重复」「滚动窗口」「缺值」都有徽章
- ✅ 未保存提示（053）覆盖代码侧与参数侧，含行内「原 X → 改为 Y」+ 一键还原

**缺失（按对普通投资者的风险排序）**：

1. 🔴 **AI 生成弹窗零风险提示**。全文无「风险/实盘/资金」字样（grep 确认）。用户在**可能产生真实下单代码**的生成环节毫无感知。而 live 启动的强门禁（`need_risk_ack` → 逐字「确认风险」→ 短语「确认实盘 <id>」）在 `runs.js:620-800`，属**后续步骤**。
2. 🔴 **无「AI 生成 / 未经实盘验证」标记**。`GET /api/strategies` 不返回来源字段，列表里 AI 生成的策略与手写的**外观完全一致**。
3. 🔴 **回测指标卡旁无「历史不代表未来」免责**。这句只在 AI **评估回复**里出现（`provider.rs:651`）。
4. 🟠 **无「先验证再运行」的强引导**。GUIDE 里写了"先回测"，但那只是帮助文本，生成流程不触发、不强制。
5. 🟠 **影响评估入口对"手动改参数"不可见**。`syncAssessPanel` 判据只看 `st.aiThreads.params` 最后一条 AI 回包的 `changed`（`strategy_editor.js:457-460`）——用户自己改参数时看不到评估按钮。
6. 🟠 **生成策略无逻辑摘要**。`sgFitSummary` 只在清单声明了 `summary` 时显示，AI 生成的策略无清单 → 空。**用户面对一坨 Lua 代码，没有"这份策略在做什么"的一句话**。
7. 🟡 **参数含义缺失**。术语表只含回测指标名与通用金融术语，**不含策略参数名**；AI 生成的策略清单为空 → 参数只有键名没有中文名/说明（需用户点「从脚本识别参数」）。

### 维度 7：安全边界 —— **优秀，应作为标杆**

- ✅ 币安域名白名单 `validate_base_url()`；HTTP 客户端 `.redirect(Policy::none())` 防重定向绕白名单
- ✅ AI base_url 主机门；`allow_custom_base_url` 故意不进 `WRITABLE`
- ✅ 策略名校验唯一权威 `validate_strategy_name()`
- ✅ 模型无写实工具调用面；13 类写操作 fail-closed
- ✅ 确认词只认当前语言、**整行全等**、刻意不含 `y/yes/ok/空行`（防肌肉记忆误触）
- ✅ Lua 沙箱：无 os/io/debug/package/coroutine，禁 require/loadstring/pcall，100 万指令预算，64MB 内存
- ✅ 不索取不复述 API 密钥

**唯一值得商榷的设计立场**（不是缺陷，但影响普通投资者）：**平台不做任何投资风控**——`[risk]` 段与 `RiskEngine` 静态限额已整体删除，仓位/止损/回撤**全部由策略自管**（`GATES_GUIDE`、`TRAPS_GUIDE`、实盘确认块三处重申）。

对一个普通投资者而言，"风控由策略自己负责"意味着：**如果 AI 生成的策略没写止损，就没有任何兜底**。这在专业用户视角是设计自由度，在普通用户视角是**隐性风险**——而 UI 从未向他解释这一点。

## 四、总体判断

**"是否符合一个普通投资者用于配置量化交易？"**

**答：不符合，差距不在能力而在"组织方式"。**

ricow 把 AI 策略生成的**每一颗零件**都造得很硬——编译门禁、沙箱、回测引擎、确认门、口径诚实性、双语 UI。但它把这些零件**按工程师的视角**摆放，而不是按投资者的决策顺序：

```
投资者需要的心智路径：
  我是谁（资金/风险承受）→ 我想做什么（思路）→ 做出来看看（生成）
  → 历史上行不行（回测）→ 会不会是巧合（样本外/稳健性）
  → 有多大不确定性（成本假设/滑点）→ 我能承受吗（风险披露）→ 才敢用

ricow 现有的路径：
  填表 → 生成 → 编译通过 → 落盘 →（用户自己想起来去点回测）
```

**缺的那一层不是新的引擎能力，而是"把已有能力编成投资者的决策流程"**——也就是审计结论指向的那两件事：**结构化收集投资约束** + **生成即验证的闭环**。

其中链路 A（对话助手）已有 `preview_strategy`（生成即回测）与 `run_backtest`（读回测）两个现成工具——**Web 链路缺的正是这两个**。
