## 第一轮 · P1 生成即验证 + P3-4 成本假设显式化

> 目标: 用户点「生成」后**看到的不是一段代码, 而是一份带回测结果的策略**。
> 这一轮单独就能消掉审计里最大的风险(#1 用户拿到未验证代码)。

### P1 生成即验证

- [x] **T1** `AiGenerateRequest`(`web/strategy_io/mod.rs:1046`)加两个字段:
      `verify: Option<bool>`(默认 **true**)与 `verify_days: Option<u32>`(默认 **90**, 范围 1–3650)。
      `verify=false` 让用户跳过验证(明码标价: 跳过则不知道它历史上表现如何)。
- [x] **T2** `ai_generate_strategy`(`:1839`)在**编译门禁通过后**调
      `commands::create::create_preview(name, &code, pair, market, [], days, interval)`
      跑一次**真实 K 线沙箱回测**。
      **关键**: 该函数**不落盘**(`create.rs:76`, 对话链路 `preview_strategy` 已在用)——
      于是语义变成「**先验证, 再落盘**」: 用户看到结果后才决定是否保存。
      这是 Web 向对话链路看齐的核心一步(plan 原则 2)。
- [x] **T3** `AiGenerateReply` 加 `verify` 字段:
      `VerifyOutcome { ok: bool, days, interval, report_text: Option<String>, reason: Option<String> }`。
      **失败不阻断生成** —— 返回 `ok:false` + 具体原因, 代码照常返回。
- [x] **T4** 单测(离线): ① 验证成功路径返回 `ok=true` 且 `report_text` 非空;
      ② 回测失败(网络/超时)→ `ok=false` + `reason` 非空, **且 `code` 仍返回**;
      ③ `verify=false` 时不发起回测; ④ `verify_days` 越界 400。
- [x] **T5** 前端生成弹窗(`strategies.js:1279`)加「回测窗口」选择:
      90 / 180 / 360 / 手填, 默认 90。**天数越大耗时越久必须写在旁边**(§五 纪律)。
- [x] **T6** 前端生成成功后**直接展示**验证结果 —— 复用现有
      `renderJob` / `renderMetricCards` / `renderBtChart`(`strategy_backtest.js`),
      不新写渲染。用户**无需额外点击**即看到 6 张指标卡 + 权益曲线 + 基准虚线。
- [x] **T7** 失败路径 UI: 详情页显示「**未验证(原因: …)**」+ 「手动跑一次」按钮,
      **绝不显示任何指标卡**(不能让用户以为已验证)。与实时行情三态 chip 同一纪律。
- [x] **T8** 修 #7 报告截断: `clamp_output`(`ai/tools.rs:97`)对回测报告 8000 字符过紧 ——
      改为**结构化摘要优先**(拆"概览/成本/风险/成交"分块按预算填),
      末尾附 `[已截断: 剩余 N 字符]`。**不允许静默截断** —— 模型必须知道有东西没看到。
      单测锁住"超长输入必带截断标记"。

### P3-4 成本假设显式化(审计 #4, 最易忽略但影响最大)

- [x] **T9** 把当前生效的**成本假设**(费率 / 滑点 / 限价穿透)从回测卡的折叠 `<details>`
      里**提到指标卡旁边**显示(`strategies.js:855-863` → 指标卡区)。

      这条比任何免责声明都有效。

### P4-3 walk-forward(本轮做)

- [x] **T30** **形态 A(默认)**: 固定参数、窗口均分 N 段、每段独立回测。

- [x] **T31** **形态 B(可选开关)**: 每轮用**验证段之前**的数据重新寻优 → 验证紧随其后的一段。

      开关处**明码标价**: 「含重新调参: 约 N×100 次回测, 可能达十分钟级」。

- [x] **T32** UI 呈现: 形态 A = 每段一组指标**并排** + 离散度提示(只描述差异, 不下定论);

      **术语纪律**: A 叫「分段验证」, B 叫「滚动验证(含重新调参)」,**不统称 walk-forward**。

## 已知的「刻意不做」(写下来, 免得后人当 bug 修)

| 项 | 不做的原因 |
|---|---|
| 档位目标做成硬拦截 | 实测超限 ≠ 策略违规(可能窗口特殊), 会分不清"换窗口跑"与"策略真有问题"(D1) |
| 生成阶段加勾选确认框 | 稀释 live 启动那个真正重要的门禁语义(P3-1) |
| 徽章带"已验证/未验证" | P1 让所有 AI 策略生成即回测 → "未验证"永不出现, 退化为冗余(D8) |
| 样本外退化说成"过拟合" | 成因有多种, 一概归因超出证据范围(D6) |
| walk-forward 随机切分 | 会制造前视偏差, 违反 `backtest.md §一` 最高约束(D4) |
| lint 止损做硬拦截 | 静态判断不绝对可靠, 会误杀合法策略(T35) |
| `origin` 用正式字段 | 与 `declared`/`duplicate_of` 的"推导而非存储"哲学不一致(D7) |
| 自定义档给默认数字 | 给了就等于替用户偷偷选了档(D3) |
| 前端 JS 手抄档位数字 | 两处必然在改表时静默分叉; 一律向 `/api/strategies/risk-profiles` 取(§四-1) |
| 摘要复用用户的原始思路 | 想法里有、代码里没落地的部分一旦写进摘要, 详情页就在骗人(T37) |
| 「补摘要」失败阻断生成 | 代码已过编译门禁, 少了摘要只是详情页少一行; 但**不静默**, 回 `meta_note`(T37) |
| `_summary` 复用 `ai-name-params` 的系统提示 | 那条契约是"只能输出参数键", 混用会让前端以为冒出一个参数(T37) |
| 用静态脚本抓 const 的 TDZ | 需要真作用域分析; 由 CDP 真机点击兜(054 实测抓到 `skipBox` 那一处) |
| 给 AI 客户端加超时 | 上游挂起属**上游故障**; 超时值要单独定(正常生成 ~100s), 需上游正常时复测, 本轮只留痕(T41) |
| 验证回测用默认 10 万本金 | 已修: 用户填多少就跑多少(spec §四-2); 抽 `verify_spec` 纯函数加单测钉住(T41 真跑发现) |

### 本轮追加的"刻意不做"

| 项 | 为什么不做 |
|:--|:--|
| 为传 reqwest 超时把本仓 reqwest 升到 0.13 | 依赖树里有两个 reqwest(本仓 0.12 / rig 0.42 用 0.13), 传不进去; 升级会牵动交易所那条线。外层 `tokio::time::timeout` 效果等价且覆盖所有调用 |
| B3 核对单笔仓位 / 网格间距 / 杠杆上限 | 回测指标里**没有**对应数字, 凑出来就是编造实测值 |
| 没拿到实测值时也摆一个核对框 | 空框 = 用界面暗示"已经核过" |
| 对话侧把本金设成 required | 硬性必填会让工具调用整体失败, 助手连"先问用户"那一轮都走不到 |
| 超时后自动重试 | 一次 300 秒, 重试三遍是十几分钟; 宁可早点如实报错让用户自己决定 |
| 给 AI 的 HTTP 客户端加 `.redirect(Policy::none())` | 想做, 但客户端由 rig 构造、传不进自定义 reqwest(同上), 本轮没有落点; 留痕 |
