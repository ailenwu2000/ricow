**功能目录**: `specs/changes/004-risk-guards`

**创建日期**: 2026-09-06

**状态**: ✅ 已实施 (2026-09-12; 见 tasks.md 完成记录与文末实测表)

> **实施范围修正 (2026-09-12, 按代码复核后)**: ① **补上关键缺口** —— 本变更不只是"加两条规则":
> 复核发现 `RiskEngine` 此前只挂在无消费者的 `StrategyScheduler` 上, **回测 / Dry Run / 实盘三条下发单路径都不过风控**(即四条既有规则实际从未生效),
> 故落地范围含"三条 `place_order` 统一接入"; ② 拒单语义 = 返回 `Rejected` ack(与资金不足同形, 策略循环不中断)并计入报告"拒单次数" + `tracing::warn!(target="risk")`,
> 而非抛错; ③ 参数来源 = `[risk]` TOML **与** `--param risk_*`(优先级后者覆盖前者), 非法值在配置装载边界拒绝;
> ④ 一级结算周期默认 `day`(与既有"单日最大亏损"粒度一致), 可配 `hour`; ⑤ 熔断告警先落日志(003-notifications 未上线, 原假设 A5 不变)。

**输入**: 用户描述: "竞品调研差距 G7 拍板(2026-09-06): RiskEngine 补护栏 = 下单频率上限(参照 NautilusTrader 默认 100/s)+ 两级连续亏损熔断(2026-09-06 拍板 Q2=C: 一级连续 N 结算周期净亏损停开仓, 二级已实现盈亏峰值回撤超阈值停策略)。直接服务 P4 '不会让用户莫名亏损'验收。依据: specs/research/competitor-gap-2026-09.md §七 D3-G7。"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 下单风暴被频率上限拦截 (优先级: P1)

策略因 bug/逻辑失控在短时间内发出大量下单请求(如 tick 风暴中循环下单)时, 引擎按配置的频率上限拒绝超限请求并记录原因, 防止账户被无效订单淹没或触发交易所限频。

**优先级理由**: 引擎级护栏, 不依赖策略自律; 频率上限是 NautilusTrader 同款预交易检查。

**独立测试**: 配置极小频率上限(如 1/s), 单测构造 1 秒内多个下单请求, 断言超限请求被拒且原因记录。

**验收场景**:

1. **给定** 配置下单频率上限为每秒 N 次, **当** 策略在 1 秒内发出超过 N 次下单请求, **则** 第 N+1 次起被拒绝, 拒绝原因含"频率上限"及配置值
2. **给定** 正常节奏策略(TWAP/网格/DCA 常规节奏), **当** 按默认参数运行回测与 Dry Run, **则** 无请求被误拒(默认值不误伤)
3. **给定** 实盘与 Dry Run 同一代码路径, **当** 触发超限, **则** 两态行为一致(计数/拒绝语义相同)

### 用户故事 2 - 两级亏损熔断, 不再"莫名亏损" (优先级: P1)

策略持续亏损时两级防护(2026-09-06 拍板 Q2=C):
- **一级(温和)**: 连续 N 个结算周期(默认自然日, 可配)净亏损 → 拒绝新开仓请求(平仓/减仓不受阻), 产生告警; 后续周期转盈则计数清零自动恢复
- **二级(强)**: 已实现盈亏从运行期峰值回撤 ≥ 阈值 X% → 停止该策略全部新交易活动(与正常 stop 同语义, 不强制平仓), 产生告警; 恢复靠用户手动重启

**优先级理由**: P4 验收核心("可用且不会让用户莫名亏损"); 一级防"温水煮青蛙"式连续失血, 二级防"先赚后亏光", 语义对齐 Passivbot 亏损闸门 + Equity Hard Stop Loss 思路的简化。

**独立测试**: 单测分别构造"连续 N 周期亏损"与"先盈利后回撤超阈值"两类成交序列, 断言一级停开仓/自动恢复与二级停策略各自生效且产生告警事件。

**验收场景**:

1. **给定** 配置连续亏损周期数 N, **当** 策略连续 N 个结算周期已实现净亏损, **则** 一级熔断生效: 新开仓请求被拒(原因含"连续亏损熔断"), 平仓/减仓不被阻止, 产生告警事件
2. **给定** 一级熔断生效中, **当** 后续某一结算周期转盈(净盈利), **则** 连续亏损计数清零、开仓自动恢复, 无需人工干预
3. **给定** 配置峰值回撤阈值 X%, **当** 已实现盈亏相对运行期峰值回撤 ≥ X%, **则** 二级熔断生效: 策略全部新交易活动停止(不强制平仓, 与正常 stop 一致), 产生告警事件
4. **给定** 二级熔断触发后, **当** 用户手动重启策略, **则** 熔断状态清零、策略按新会话正常运行(重启 = 有意重新开始)
5. **给定** 熔断生效期间存在未平仓位, **当** 用户发起平仓, **则** 平仓路径不被阻止(风控目的 = 防亏损扩大, 保留退出能力)

### 用户故事 3 - 参数可配且三态一致 (优先级: P2)

频率上限与两级熔断参数(频率上限 / 连续周期数 N / 结算周期 / 回撤阈值 X%)均通过 CLI `--param`/策略 TOML 配置; 回测、Dry Run、实盘同一代码路径与语义, 参数校验拒绝非法值。

**优先级理由**: 护栏默认保守但不误伤; 三态一致是 Locus 回测门禁模型的基石。

**独立测试**: 同一参数在回测与 Dry Run 下行为一致(计数/熔断判定同路径); 非法参数(负值/非数值)被校验拒绝。

**验收场景**:

1. **给定** 任意配置参数, **当** 回测与 Dry Run 分别运行同一策略, **则** 频率/熔断判定结果一致(同语义)
2. **给定** 非法参数(如频率上限 ≤ 0、N ≤ 0、X% 为负或 > 100), **当** 提交配置, **则** 校验拒绝并给出明确错误

### 边界情况

- 结算周期核算规则: 周期内发生平仓且已实现净盈亏 < 0 → 连续亏损计数 +1; 周期内有平仓且净盈亏 ≥ 0 → 计数清零; 周期内无平仓 → 不改变计数(避免"停开仓后无交易自动解除"与"空跑周期误清零"两个陷阱)
- 结算周期默认与现有日粒度风控周期一致(plan 阶段确认口径), 可配置(如按小时)
- 熔断计算口径 = 已实现盈亏(含手续费/资金费), 与回测报告口径一致; 不含未实现浮盈(浮盈波动不应触发/解除熔断)
- 二级峰值基线 = 该策略运行期内已实现 PnL 的最高点(含费用/资金费), 重启后重算
- 熔断按策略实例独立核算, 不跨策略联动(单策略失控不误伤其他策略)
- 一级/二级熔断触发均对接 003 告警事件; 003 未上线时完整日志(含原因与关键数值)
- 回测中两级熔断均生效(与实盘同语义), 保证策略在回测里就能暴露熔断行为
- 频率计数窗口语义: 滑动窗口(避免整秒边界突刺)
- 频率上限默认值需覆盖正常策略节奏(TWAP 分片/网格挂撤/再平衡)且留余量; 具体默认值在 plan 阶段按实测节奏定, 不留无依据的保守大余量(宪法原则五)

## 功能需求 *(必填)*

### 功能需求

- **FR-001**: 系统必须提供下单频率上限检查: 单位时间内下单请求数超限即拒绝该请求并记录原因(含配置值与实际计数)
- **FR-002**: 频率计数必须使用滑动窗口语义, 实盘/Dry Run/回测同一代码路径
- **FR-003**: 系统必须提供一级亏损熔断: 连续 N 个结算周期已实现净亏损 → 拒绝该策略新开仓请求(平仓/减仓不受阻), 产生告警事件; 有平仓的周期转盈则计数清零自动恢复
- **FR-004**: 系统必须提供二级亏损熔断: 已实现盈亏相对运行期峰值回撤 ≥ X% → 停止该策略全部新交易活动(与正常 stop 语义一致, 不强制平仓), 产生告警事件; 恢复靠用户手动重启
- **FR-005**: 熔断触发必须产生告警事件(供 003-notifications 消费; 003 未上线时以日志呈现, 含原因与关键数值)
- **FR-006**: 熔断不得阻止用户发起的平仓/减仓请求(风险处置路径保留)
- **FR-007**: 熔断状态按策略实例独立; 策略重启后状态清零(手动重启 = 有意重新开始)
- **FR-008**: 熔断判定基于已实现盈亏(含手续费/资金费), 与回测报告口径一致; 不含未实现浮盈
- **FR-009**: 频率上限、连续亏损周期数 N、结算周期、回撤阈值 X% 必须可配置(CLI `--param`/TOML), 参数校验拒绝非法值(≤0/非数值/X% 越界)

### 关键实体 *(涉及数据时填写)*

- **频率计数状态**: 按策略实例, 滑动窗口内下单请求时间戳/计数
- **熔断状态(策略实例级)**: 一级 = 连续亏损计数 + 最近核算周期结果(结算周期末核算); 二级 = 已实现 PnL 峰值基线 + 当前回撤; 两级开关独立; 重启清零

## 假设

- 假设 A1: 两级熔断语义(2026-09-06 拍板 Q2=C): 一级 = 连续 N 结算周期净亏损停新开仓(自动恢复); 二级 = 已实现盈亏峰值回撤超阈值停策略(手动重启恢复)

- 假设 A3: 手动重启 = 有意重新开始, 两级熔断状态重启后清零不持久化
- 假设 A4: 已实现盈亏口径含手续费与资金费, 与 specs/backtest.md §六 报告口径一致
- 假设 A5: 依赖 003-notifications 的告警事件接口; 实施顺序 003 先行, 004 的 FR-005 先以日志落地再对接
- 假设 A6: 频率上限与两级参数的默认值在 plan 阶段按内置策略实测节奏与 dogfood 数据确定, 不拍脑袋(宪法原则五)
- **假设 A7**: 结算周期默认与现有日粒度风控周期一致(plan 阶段确认口径); "无平仓的周期不改变一级计数"为核算规则(见边界情况)
