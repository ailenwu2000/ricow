# 016 功能规格: Dry Run 虚拟本金可配 (`params.initial_cash`)

**状态**: 已实施 (2026-09-13) | **触发**: P4 dogfood 执行清单整理时的实测发现

## 一、为什么

Dry Run 的初始虚拟本金原先是**硬编码 100,000 quote**。整理 P4 清单时按"小资金实盘"写了 `[risk]` 限额
(名义 400 USDT)去跑 Dry Run, 结果**65 单全部被拒**:

```
WARN risk: 风控拒单: max position exceeded: current=50000.000000000005943867620294, limit=400
统计: tick=66 提交订单=65 拒单=65 成交=0
```

原因: Dry Run 的虚拟权益是 100k, 网格目标仓位 = 50% × 100k = 50k, 而限额是给小资金设的 400。
于是**同一份配置不可能同时预演 Dry Run 与实盘** —— 而"先用 Dry Run 预演再切实盘"正是产品的核心主张
(`product.md` §三.2/§三.3)。dogfood 要验的恰恰是这同一份配置, 所以这不是"小瑕疵", 是预演链条断了。

## 二、范围

**做**: 新增 `params.initial_cash`(Dry Run 虚拟本金, 缺省 100,000 保持既有行为); 非法值报错不静默回落; 单测 + 真实预演验证。

**不做**: 不改实盘路径(实盘本金由交易所账户决定, 无此参数); 不改回测(`--cash` 早已可配); 不改默认值。

## 三、功能需求

- **FR-001**: Dry Run 启动时读 `params.initial_cash` 作为虚拟本金; 缺省 `100_000`(与既有行为逐位一致)。
- **FR-002**: 非法值(≤0 / NaN / inf) → **报错退出**, 报错含参数名与收到的值; **不得静默回落到 100k**
  (静默回落会让"预演口径"悄悄变回 100k, 正是本变更要消除的坑)。
- **FR-003**: 本金币种仍按交易对报价资产(`quote_asset_of`)配平, 不因本参数改变。
- **FR-004**: 启动时打印 `Dry Run 虚拟本金: <金额> <币种>`, 让预演口径**可见**(避免"我以为是 300, 其实跑的是 100k")。

## 四、验收标准

- **SC-001**: `cargo test --workspace` 全绿零回归。
- **SC-002**: 单测: 缺省=100k / 自定义 300 与 0.5 / 非法值(0、-1、NaN、inf)报错且信息含参数名。
- **SC-003**: 真实预演: 同一份含 `[risk] max_position_notional = 300` 的小资金配置, 在 `initial_cash = 300.0` 下
  建仓 50%×300=150 USDT(实测 `size=0.060554314192115 @ ~2477.115`)、拒单 0(对比修改前同一配置 65 单全拒)。
- **SC-004**: 非法值真实复现: `initial_cash = 0.0` → `params.initial_cash 非法 (需 > 0 的有限数, 收到 0)`。
- **SC-005**: 文档同步: `lua-api.md`(运行时参数)、`architecture.md` §五 CLI、`roadmap.md`、P4 清单(runbook)。
