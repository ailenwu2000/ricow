## 二、决策

### D1 共享机制 = 命名空间对象 + 顶部别名，不做作用域拼接

`strategies.js` 原本靠**闭包**共享一切。多文件下没有"同一作用域"可拼接（CSP `default-src 'self'`
禁 `eval`/`new Function`，`with` 在严格模式禁用）。故：

- 共享物挂到 `R.sg`（`S`）；
- 各文件顶部对**工具 / 常量 / 跨文件函数**做一次别名，**正文零改写**；
- 只有**共享状态**必须改写（`gen` → `st.gen`）—— 因为它是可写的绑定，别名会断开链接。

这条取舍把改写面从"约 260 处（含所有跨文件调用）"压到"约 160 处（只有状态）"。

### D2 跨文件函数一律延迟查找

```js
const onSave = (...args) => S.onSave(...args);   // 调用时才查 S
```

需求是**双向**的：外壳的 `mount` 要绑 `onSave`（子文件），`onSave` 又要调 `enterDetail`（另一子文件）。

- 若写成 `const onSave = S.onSave`（加载期取值）→ 谁先加载谁 `undefined`，且是**静默**的
  （事件绑到 `undefined` 不报错，点保存毫无反应）。
- 延迟查找把"加载顺序"从**正确性条件**降级为"外壳必须最先"这一条弱依赖（FR-5）。

### D3 状态用单一状态袋 `R.sg.st`，不用 13 个 `S.xxx` 散槽

- 散槽会让"这个状态属于谁"失去线索；状态袋 + 顶部 `const st = S.st` 让每份文件明确声明
  "我要读写视图级状态"。
- **不做按归属拆分**（如把 `btChart` 只给 backtest）：`gen` 的作废语义跨全部四份文件，
  `jobs` 被 form 与 backtest 共读写 —— 强行归属只会制造跨袋引用。

### D4 改写用脚本 + 词法跳过，不手抄

2626 行手抄 4 份必然引入笔误（漏行、错缩进、漏改某处 `gen`）。改用一次性脚本
（`tmp/split_042.py`，不入库）：
- 按行区间切分（区间由通读确定，写在脚本里）；
- 状态名改写走**逐字符词法扫描**，跳过注释、字符串、正则字面量与属性位置（`obj.jobs` 不动）；
- 生成后立即用 `node --check` + 逐符号核对（T004）验证，脚本本身留档以便复现。

### D5 i18n 键留在外壳，不分散

`Object.assign(R.TEXT.zh/en, {...})`（约 320 行）整体留在 `strategies.js`：
- 它是**一张表**，按视图再切只会让人找文案时跨 4 个文件；
- 子文件一律通过 `t("sgXxx")` 取值，与现在完全一致。

### D6 文件命名沿用"视图_子视图"惯例

`strategy_form.js` / `strategy_editor.js` / `strategy_backtest.js`：与 `markets.js` / `runs.js`
同一层，不进子目录（`ASSETS` 的名字必须**平铺**，见 `assets.rs::test_asset_table_is_well_formed`）。

### D7 不新增任何 `id` / `class`；不动 CSS

`e2e_web.py` 的 144 条断言大量依赖 `#sg-*` 选择器与 class；CSS 也按它们写。拆分只搬 JS。

### D8 状态改写的**可判定验收**

机械改写最大的风险是"漏改一处 → 静默走全局"。所以必须可判定：
- 4 份文件里对 13 个状态名的**裸出现**（不带 `st.`）必须为 **0**（词法级扫描，排除注释/字符串/属性名）；
- 反向：`st.<name>` 里的 `<name>` 必须都在那 13 个之内。
两条都进 T004 的核对脚本，不靠人眼。

## 三、风险与处置

| 风险 | 处置 |
|---|---|
| 漏改状态名 → 静默走全局 | D8 的双向扫描；`gen` 漏改的直接后果是"切视图后旧响应仍改 DOM"，E2E 覆盖不到，故**必须**静态卡死 |
| 跨文件函数取成加载期值 | D2 强制箭头包装；T004 检查每个跨文件别名的右侧形如 `=> S.` |
| 加载顺序被后人打乱 | FR-5 写进 `assets.rs` 注释 + `index.html` 注释；`ASSETS` 表顺序即加载顺序，且新增一条纪律断言：三份子文件必须排在 `strategies.js` 之后 |
| 纪律扫描覆盖面缩水 | NFR-1：扫描函数 `all_js()` 派生自 `ASSETS`，新文件自动纳入；T004 断言 4 份都被扫到 |
| 拆完 E2E 绿但某条路径没被覆盖 | 真机走查四态（验收 4），逐条对照原行为 |
