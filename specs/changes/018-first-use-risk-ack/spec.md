# 018 功能规格: 首次使用风险确认

**状态**: 已实施 (2026-09-13) | **依据**: `specs/product.md` §十(安全与合规) 风险披露行 = "README 免责声明 + **首次使用风险确认**"

## 一、为什么

`product.md` §十 把风险披露写成两条: README 免责声明 + 首次使用风险确认。核对现状:

- README 免责声明 ✅ 已有(`README.md` / `README_zh.md` §免责声明, 含 shannon_grid 专项风险提示);
- **"首次使用风险确认" ❌ 代码里完全没有** —— 任何人克隆仓库、配好 key, 一条 `--live` 就能用真钱开跑,
  软件一次风险告知都没有。这是**发布前的合规承诺缺口**(P4 后半段"公开发布"的直接前置)。

## 二、范围

**做**: 实盘启动路径加一道**一次性**确认闸: 未确认 → 拒绝并打印披露要点 + 确认方式; 带 `--accept-risk` →
在数据目录落地确认记录后放行; 之后实盘不再要求。

**不做**: 不改 Dry Run / 回测(不涉真实资金, 不做打扰); 不做交互式弹窗(纯 CLI 定位); 不引新的存储机制(记录写在
数据目录内的 `risk_ack.json`, 与 `run/daemon.json` 同级同性质)。

## 三、功能需求

- **FR-001**: 实盘启动(`run --live` / `start --live`)时判定: 已确认 → 放行; 未确认且带 `--accept-risk` → 记录并放行; 未确认且不带 → **拒绝**。
- **FR-002**: 拒绝消息必须包含: 披露要点(学习研究用途/无止损/子账号与小额建议/不代管资金密钥)、指向 README 免责声明、确认方式、以及"先用 Dry Run 预演"的建议。
- **FR-003**: 确认记录落 `$LOCUS_ROOT/risk_ack.json`(含 schema 版本 + 时间戳 + 披露正文); 披露实质变更时递增版本即可触发重新确认。
- **FR-004**: 判定顺序 = **风险确认 → Dry Run 时长门禁 → 时钟预检**(最早拦截, 不浪费一次交易所往返)。
- **FR-005**: Dry Run / 回测不受影响。

## 四、验收标准

- **SC-001**: `cargo test --workspace` 全绿零回归。
- **SC-002**: 单测: 未确认+无开关 → 拒绝且消息含披露/`--accept-risk`/README; 未确认+开关 → `JustAcked`; 已确认 → `Proceed`(带不带开关都是)。
- **SC-003**: 真实链路(全新数据目录, demo 端点): ① 不带开关 → 拒绝且 `risk_ack.json` **不存在**; ② `--accept-risk` → 打印确认路径且文件写入(含版本/时间戳/披露正文); ③ 再跑不带开关 → 不再被风险闸拦(直接进入时钟预检并启动)。
- **SC-004**: 文档同步: `architecture.md` §七(安全模型) + §九 基线; `product.md` §十 标注落地; `roadmap.md` 018 行; P4 runbook 首次实盘步骤加 `--accept-risk`。
