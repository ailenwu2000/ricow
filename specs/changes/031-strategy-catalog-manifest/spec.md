# 031 功能规格: 策略目录重构 + 策略清单(manifest)+ 统一注册 + UI 配置

**状态**: 草稿 (2026-09-25) | **依据**: 用户三条需求(现货/合约分目录 · 内置/用户统一 · UI 展示配置) + 已复核架构计划 + `specs/constitution.md` 架构铁律(引擎/CLI/绑定层零策略参数名)

## 一、为什么

用户提了三条需求, 对应三个现状断链(均已定位到代码):

1. **现货策略与合约策略没有按市场分开**。当前内置策略全部现货(`strategies/builtin/` 下 `shannon_spot_grid.lua` + `paired_grid.lua`), 合约策略只是靠实例 TOML 里的 `market = "futures"` 字段区分, 目录上混在一起。`market` 字段早已存在([config.rs](../../../crates/ricow_strategy/src/config.rs#L77-L78)), 但只用于撮合/费率分支, 从未用于目录组织与 UI 分组 —— 用户分不清"这是现货策略还是合约策略"。

2. **内置策略与用户策略是两套割裂的机制**。内置策略走编译期 `include_str!` 嵌入 + `templates.rs` 登记表; 用户策略走磁盘 `strategies/<name>.toml` + `scripts/<name>.lua`。内置策略本应是"给用户照抄的示例", 却被做成一条特殊路径 —— 用户想"复制一个内置策略改改"和"自己写一个"走的是两条不同的路。

3. **项目拿不到策略的展示元数据**。现在唯一接近"策略描述"的是 `templates.rs` 的 `Template{name,summary,params,code}`([templates.rs](../../../crates/ricow/src/commands/templates.rs#L11-L20)): 只有英文标识 + 一句话 + **参数键数组**, 缺中文名、参数类型、默认值、必填、枚举项 —— 这些是"在 UI 里展示策略并让用户填参数"所必需的, 所以现在 UI 无法做策略浏览与参数配置, 用户只能手写 TOML。

本次变更主旨: **引入一份机器可读的"策略清单(manifest)"作为策略自述的描述层**, 由它统一驱动三件事 —— 现货/合约分组、内置/用户统一注册、UI 展示与配置。清单是**表现层数据**, 不碰交易执行(架构铁律不变)。

## 二、范围

**做**:

- **策略清单(manifest)**: 每个策略一份机器可读清单, 声明中文名、市场、说明、参数 schema(名/类型/说明/默认值/必填/枚举)。
- **现货/合约分目录**: 策略源码按市场分 `spot/` 与 `futures/` 两个目录。
- **统一注册表**: 内置示例与用户自写策略合并成一份统一目录(catalog), 取消"内置 vs 用户"的结构性区分。
- **Web 展示 + 配置**: 只读端点 + 前端策略面板, 展示中文名/说明/参数表单; 配置走既有确认流。
- **架构守卫反哺**: 守卫黑名单从清单派生, 加"清单参数键 == Lua 读取键"一致性校验。

**不做**:

- **不改架构铁律**: 引擎/绑定层仍零策略参数名, 清单只是表现层数据, 不参与撮合/执行; 清单参数名不进入引擎任何读值路径。
- **不改任何执行语义**: 下单/撮合/风控/确认门禁/Dry Run 默认 一行不动。本次只加"描述 + 呈现 + 统一加载", 不改"怎么交易"。
- **不强制迁移旧部署**: 旧 `script_path` / 内嵌 `script` / 内置 `type` 继续兼容读取, 不做迁移脚本。
- **不新增写通道**: 策略参数配置复用既有 `update_strategy_params` + `create`/`deploy` + 确认流, 不新增旁路写 TOML 的端点。
- **不做策略市场 / 云端策略分发**: 清单只描述本机已有的策略, 不引入在线策略广场。
- **不引入前端构建链**(沿用 025 D4): 手写静态资源 + 编译期内嵌。
- **不做参数自动优化 / 无代码拖拽编辑器**(product.md 已明确不做)。

## 三、功能需求

### 策略清单 manifest(F0)

- **FR-001**: 每个策略有一份**机器可读清单**, 至少声明: 英文标识(全局唯一)、中文名、市场(`spot` | `futures`)、一句话说明; 可选长说明、适用场景、不适用场景。
- **FR-002**: 清单声明**参数列表**, 每个参数至少含: 键名、中文名、类型(`f64` | `i64` | `string` | `bool` | `enum`)、说明; 可选默认值、是否必填、枚举项(仅 `enum` 类型)。
- **FR-003**: 清单是**纯描述数据** —— 引擎(`ricow_engine`)与绑定层(`ricow_strategy::context/lua`)不得读取清单、不得持有任何策略参数名; 清单只供 UI/CLI/AI 展示与表单渲染(架构铁律)。
- **FR-004**: 清单声明的市场与所在目录**必须一致**, 不一致时加载**报错**而非静默修正。
- **FR-005**: 清单的参数默认值只是 UI 预填值; 运行时缺省仍由策略脚本自身的兜底决定, 二者须一致(由一致性校验兜底, 见 FR-014)。

### 现货/合约分目录(F1)

- **FR-006**: 策略源码按市场分目录: 现货策略在 `spot/`, 合约策略在 `futures/`; 不存在第三个市场目录。
- **FR-007**: 内置示例与用户自写策略**同目录、同清单格式**统一存放 —— 内置示例就是放在对应市场目录里的样例文件, 不再有单独的 `builtin/` 特殊目录。
- **FR-008**: 内置示例仍**编译期嵌入**二进制(单文件分发不破坏), 与用户策略在同一注册表里统一呈现, 仅以"来源"字段区分。

### 统一注册表(F2)

- **FR-009**: 项目能把「内置示例(编译期嵌入) + 用户自写(磁盘)」合并成**一份统一策略目录**, 每个条目含: 清单 + Lua 源码 + 来源标记(`builtin` / `user`)。
- **FR-010**: 目录按英文标识**去重**; 内置示例的英文标识是**保留名**, 用户策略不得占用(占用时报错)。
- **FR-011**: 旧部署方式继续可加载: 实例 TOML 的 `type` 指向内置标识、`script_path` 引用脚本、内嵌 `script` 字符串, 三种都照旧工作, 不要求用户改写。
- **FR-012**: 三个出口共用同一份目录: CLI 的 `--strategy` 帮助、AI 只读工具(`list_templates`/`read_template`)、Web 策略端点 —— 三者展示的中文名/说明/参数一致。

### Web 展示与配置(F3)

- **FR-013**: Web 提供**只读**端点列出全部策略, 每条含中文名、市场、一句话说明、来源; 挂在既有 token 鉴权之后, 无 token / 错 token 一律 `401` 且响应体不含策略数据。
- **FR-014**: Web 提供**只读**端点返回单个策略详情, 含中文名、说明、适用/不适用、参数数组(每项 name/type/desc/default/required/options)。
- **FR-015**: 前端按市场分「现货 / 合约」两组展示策略; 点选某策略显示详情 + **参数表单**, 表单按参数类型渲染(f64/i64 数字输入、string 文本、bool 勾选、enum 下拉), 每项显示中文名 + 说明 + 默认值预填 + 必填标记。
- **FR-016**: 表单的写动作(回测 / 建实例 / 部署 / 启动)**走既有确认流**, 前端**无任何直连交易所/直连落盘的写按钮**(守 026 D17 红线)。

### 架构守卫反哺(F4)

- **FR-017**: 架构守卫的「策略参数名黑名单」**从清单派生**(而非手抄), 新增内置策略参数时无需手动同步黑名单。
- **FR-018**: 存在一条一致性校验: 清单声明的参数键 == 策略 Lua 实际读取的参数键(`config_*`/`num`/`cfg_str`), 防清单与 Lua 漂移。

### 零回归(F5)

- **FR-019**: 内置策略迁移目录后, `--strategy {shannon_spot_grid,paired_grid}` 真实 K 线回测行为与迁移前**逐位一致**。
- **FR-020**: 所有面向用户/外部的 `strategies/builtin` 路径口径同步到新目录(文档 + 官网 + AI 提示词)。

## 四、验收标准

- **SC-001**: 三门禁全绿: `cargo fmt --all -- --check` 零差异、`cargo clippy --workspace --all-targets -- -D warnings` 零警告、`cargo test --workspace` 全绿; 基线 **529 passed / 0 failed / 22 ignored** 不倒退。
- **SC-002**: 清单解析单测覆盖: 全类型参数、默认值、枚举项、必填、非法类型、缺英文标识、市场与目录不一致 —— 各自按预期解析成功或报错。
- **SC-003**: 统一注册表单测覆盖: 内置 + 用户合并、按标识去重、内置保留名占用被拒、旧部署三种方式(`type`/`script_path`/内嵌 `script`)均能加载。
- **SC-004**: 迁移后真实回测: `ricow backtest --strategy paired_grid --pair SOLUSDT` 与 `--strategy shannon_spot_grid` 的报告与迁移前逐位一致(真实 K 线, 禁 mock)。
- **SC-005**: Web 端点: 无 token / 错 token 请求返回 `401`; 策略列表与详情返回的中文名/市场/参数 schema 与清单一致。
- **SC-006**: 前端人工冒烟: `ricow web` 起服务后, 策略面板按现货/合约分组显示两个内置策略(中文名 + 一句话), 点开显示参数表单且默认值预填; 编辑参数经确认后 TOML 正确落盘。
- **SC-007**: 架构守卫: 黑名单已从清单派生, 且"清单键 == Lua 读取键"一致性测试通过。
- **SC-008**: 文档同步: `specs/architecture.md` / `specs/lua-api.md` §九 / `specs/product.md` §六 / `specs/constitution.md` §二 / `README*.md` / `website/*.html` / AI 提示词 中的 `strategies/builtin` 口径全部更新为新目录, 无残留旧路径。

## 五、已拍板决策

- **D1 — 清单文件后缀 = `<id>.toml`**(2026-09-25 用户拍板): 与实例 TOML 同后缀, 靠目录隔离(清单只存在于 `spot/`/`futures/`, 实例只在根), 少一层命名负担。
- **D2 — 建实例不把清单默认值全写进 params**(2026-09-25 用户拍板): 缺省走 Lua 脚本自身兜底, 只加"清单默认值 == Lua 默认值"一致性断言防漂移; 待 UI 需显示"当前生效值"时再评估是否写全。
- **D3 — 清单是表现层数据, 放 CLI 层**: 架构铁律(引擎/绑定层零策略参数名)不变; 清单只是"策略自述描述", 引擎读不到、不参与撮合。
- **D4 — 内置脚本保留编译期嵌入**: 单文件分发是核心价值; 内置示例与用户策略在统一注册表里呈现, 仅 `source` 字段区分, 不做"内置改为运行时读盘"。

## 六、假设

- 市场维度只有现货 / 合约两个(`market` 字段现有取值即 `spot`/`futures`), 不引入第三个市场分类。
- 内置标识保留名的判定靠注册表查重 + 部署时校验, 不新增独立的运行时保留名注册机制。
- 清单默认值与 Lua 兜底值的一致性由单测兜底(D2), 不引入运行时的二次读取或预计算流水线。
- Web 前端仅作只读视图 + 对话前端, 新增策略面板不复制任何业务逻辑(与 025/026 同一原则)。
- 内置策略当前只有现货两个; `futures/` 目录先立好, 首个合约内置策略落地时自然进入, 清单 `market="futures"`。
