# 052 · Web UI 复制新建策略的「配置断层」补齐

> 上游取证与方案: `specs/research/webui-strategy-config-gap-2026-10-11.md`(本文是其**落地**)。
> 用户原话: **「通过 Web UI 复制新建一个策略的时候, AI 修改里面如何帮助用户修改这个策略的配置?
> 目前感觉用户完全不知道该怎么配置。」**

## 一、问题(取证结论, 非猜测)

用户「不知道该配什么」**不是文案问题, 是数据在复制的瞬间就丢了**。

策略的「参数有哪些 / 叫什么 / 什么意思 / 默认多少」四件事**全在清单(manifest)里, 不在 Lua 里**;
而复制流程只搬 Lua、不搬清单:

| 环节 | 事实 | 证据 |
|:--|:--|:--|
| 复制 | 提交 `params: {}`, 只带原策略 Lua | `web/assets/strategies.js` 的 `openCopyModal` |
| 落盘 | 内核只写 `<name>.lua` + 实例 TOML, **不写清单** | `ricow_engine/src/strategy.rs::write_strategy_files` |
| 扫盘 | 没清单 → 合成空清单(`params: Vec::new()`, `declared: false`) | `strategies/catalog.rs::scan_user_in` |
| 渲染 | 参数表单照清单画; 清单空 → 循环零次 | `web/assets/strategy_form.js::renderParams` |

**结果**: 复制完打开详情页, 「参数」卡片里只有「交易对」一个输入框。

第二个断层: 用户寄希望的「AI 修改」**被设计成只改 Lua 源码**(`ai/provider.rs::build_edit_prompt`
硬性要求"与本次指令无关的原有逻辑逐字保留"; 返回体 `AiEditReply` 只有 `code` 一个字段) ——
用户说「间距调大点」, AI 去改**算间距的那几行代码**, 而不是把 `spacing_pct` 改成新值。

## 二、目标(可证伪)

1. **复制/模板新建一个策略后打开详情页, 「参数」卡片直接是一张带中文名的参数表** ——
   而不是只剩「交易对」。判据: 复制 `paired_grid` 后 `GET /api/strategies/{new}` 的
   `declared == true` 且 `params` 与源策略一致; 前端参数行数 = 清单参数数 − 保留键(`pair`)。
2. **任何一份 Lua(含用户自己粘进来的裸脚本)都能一键列出它读了哪些参数** ——
   不需要 AI、不需要用户读代码。判据: 纯函数 `extract_param_hints(paired_grid.lua)`
   的键集合 == 该策略清单声明的键集合。
3. ~~**「AI 修改」能听懂「调参数」和「改代码」是两件事**。判据: `mode=params` +
   「把网格间距改成 0.02」→ 返回 `params.spacing_pct == 0.02`, **Lua 编辑器内容一字不变**。~~

   **本条判据 2026-10-12 作废**（用户判定"毫无意义"）。

   > **为什么作废**：它只证明"机器把话翻译对了"，没回答「我该不该改、改了会怎样」。
   > 而且"把 X 改成 Y"这件事用户自己点两下表单就能做，**根本不需要 AI** ——
   > AI 该干的是**用户干不了的那部分**。用户原话见 `new-tasks.md` 的 N3 一节。

   **重定义后的判据（现行，已落地）**：
   - 用户只说**意图**（「保守点」「更看好震荡市的数据面」）→ AI 给出**整组**参数，
     并逐项讲**为什么这么改**与**风险**。风险依据**只准**来自四样：清单里作者写的 `desc`、
     参数的类型/默认值/当前值、Lua 代码本身、**实测指标**；四样之外的"经验之谈"必须标明是模型推断。
     清单 `desc` 为空（N2 之后是常态）要**如实标注"依据不足，仅供参考"**。
   - 改动以 `changed` 列表**逐项可见**（键 · 中文名 · 旧→新 · **是否只是清单默认值**），
     并如实区分"这组参数真的在跑"与"这只是清单默认值、你还没保存过" —— 混在一起就是编造运行事实。
   - **影响由实测回测得出**：同一窗口（`90` 天 / `1h`）跑改前、改后各一次，把两组实测指标交给 AI 解读；
     **没跑成（busy / 超时 / 取数失败）的部分必须标注为推演**，不得拿推演冒充实测。
   - 全程**不落盘**：AI 只给建议，用户点「保存」才写（沿用 052 既有两段式）。
   - **多轮**：`params` 模式接受前端回传的 `history`（有字符上限；超长保留**尾部**并如实标注"更早的对话已省略"）。
     `code` 模式**仍是有意的单轮** —— 它每轮产出整份代码，历史没有增量信息还要挤占代码的注意力预算。
4. 未声明清单的策略, 参数卡片给**可点的下一步**(不是一句只有结论的红字)。

## 三、范围

> **2026-10-11 / 10-12 追加需求**(用户指令): N1 允许在 Web UI 删除自定义策略 ·
> N2 识别参数后不再要求用户填中文名 · N3 「AI 修改」改成**多轮对话 + 说意图改整组 + 自动回测评估影响**。
> 详见同目录 `new-tasks.md`; 遗留风险计划见 `risks.md`。

### 做

- **方案 1(核心)**: `POST /api/strategies` 增加 `copy_from`。服务端用 `catalog::find`
  取源清单, 把 `id`/`market` 改写为新策略后**一并落盘**到 `strategies/{market}/{name}.toml`。
  清单的唯一真相留在后端, 前端不搬运副本。
- **方案 2**: 新纯函数 `extract_param_hints(code) -> Vec<ParamHint>` +
  无状态端点 `POST /api/strategies/extract-params`。前端在参数引导卡上挂「从脚本识别参数」。
- **方案 3**: `POST /api/strategies/{id}/ai-edit` 增加 `mode: "params" | "code"`(缺省 `code`,
  向后兼容)。`params` 模式把自然语言翻译成 `{键: 值}`, **只允许清单里真实存在的键**,
  返回体填进参数表单(**不落盘, 用户点保存才写**)。
- **方案 4**: 参数卡片在未声明清单时给引导卡(两个按钮); 「其他已保存参数」补来源说明。

**追加需求(2026-10-11 / 10-12, 均已落地 —— 实况见 `new-tasks.md` 文末「落地结果」)**:

- **N1**: `DELETE /api/strategies/{id}` —— 删三件套(实例 TOML + 市场子目录脚本 + 清单)与该 id 的 `.bak`;
  **回测历史与台账保留**(确认框里如实写明); 内置 409 `reserved`、实例运行中 409。
  顺带修掉旧实现"只删根目录 `.toml`"导致市场子目录脚本**变孤儿**的缺陷。
- **N2**: 清单保存**允许中文名/说明留空**(不写假数据, 界面回退显示键名) + `comment_docs` 从 Lua 注释
  搬说明原文 + 可选端点 `POST /api/strategies/ai-name-params`「让 AI 起中文名」(用户核对后才保存)。
- **N3**: `ai-edit?mode=params` 改**多轮**并回包 `advice`/`changed`; 新增 `POST /api/strategies/{id}/ai-assess`
  只解读**两份实测指标**(不跑回测、不落盘); 前端「跑改前 → 跑改后 → 问影响」三步编排, 窗口写死 `90` 天 / `1h`。

### 明确不做

- **不引入前端构建链、不新增运行时依赖**(宪法「少而精」)。扫描/解析全部手写, 不引 `regex`。
- **不让 AI 直接落盘** —— 保持「草稿 → 用户点保存」两段式(现状 `ai-edit` 全程不写文件)。
- **不为裸脚本自动编造中文名 / 说明** —— 静态提取只给**客观事实**(键 / 类型 / 字面量兜底默认,
  以及**脚本注释里明写的说明原文**); 中文名与说明属于作者意图, 不由程序凭空生成。

  > **2026-10-12 订正(需求变更)**: 上面这条的**后半句"由用户填"是错的假设** ——
  > 用户是脚本的**使用者, 不是作者**: 他知道自己要调什么, 但不知道作者把那个旋钮叫什么。
  > 于是 052 最初的设计("保存清单前必须补齐中文名")成了一道**用户过不去的门**:
  > 清单存不下来 → 清单为空 → `ai-edit?mode=params` 直接 400 → AI 调参数功能**根本进不去**。
  > 现行做法(见 `new-tasks.md` 的 N2): **允许留空**(不写任何假数据, 界面回退显示键名) +
  > 优先从**脚本注释**搬说明 + 可选「让 AI 起中文名」(用户核对后才保存)。
  > 「不编造作者语义」这条纪律本身**没变** —— 变的是**不再把负担转嫁给用户**。
- **不改已有 CLI 用户可见文案、不改回测数字口径、不动引擎的落盘内核签名**。
- **不给参数键挂术语表** —— `R.glossary` 的数据源是后端 `/api/terms`, 里面没有 `fee_side`
  这类参数键, 挂上去是空操作(研究文档曾把它列为方案 4 的一条, 复核后判定为无效, 不做)。

## 四、关键纪律(与既有产品口径一致)

1. **清单写失败不能留下「有一半」的状态** —— 与 `.lua`/`.toml` 回滚同口径: 先写清单,
   `write_strategy_files` 失败则**把刚写的清单回滚**(有旧清单则恢复备份, 否则删除)。
2. **`copy_from` 与 `overwrite: true` 互斥**(400) —— 复制是"新建"语义, 覆盖是"保存"语义;
   混在一起会让"清单该不该被覆盖"变成一个说不清的问题。
3. **AI 建议的键必须在清单里** —— 不在的一律丢弃并**如实回一条 warning**(不静默);
   一个都不在 → 400。红线: 不能让模型凭空编键去写实例 TOML(`ai/tools.rs` 的
   `update_params` 工具描述里已有同款纪律)。
4. **静态提取只信字面量** —— 形如 `ctx:config_f64(key)`(变量键)、`num(ctx, some_var, d)`
   一律**不提取**: 那不是"客观事实", 是推测。
