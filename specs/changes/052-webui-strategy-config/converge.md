# 052 收敛

> 起因（用户原话）：**「通过 Web UI 复制新建一个策略的时候，"AI 修改"里面如何帮助用户修改这个策略的配置？
> 目前感觉用户完全不知道该怎么配置。」**
>
> 取证与方案在 `specs/research/webui-strategy-config-gap-2026-10-11.md`。本轮把该文的
> 四条方案**完整落地**（后端 + 前端 + 测试 + 文档 + 双路真机走查）。

## 一、根因（一句话）

参数「有哪些 / 叫什么 / 默认多少 / 什么意思」四件事**全在清单（manifest）里，不在 Lua 里**；
而复制只搬 `.lua`（内置清单是编译期 `include_str!`，磁盘上没有可复制的源文件）→ 副本变成
`declared=false` 的裸脚本 → 详情页参数表单**只剩一个交易对框**。同时 `ai-edit` 被设计成**只改代码**
（提示词要求"与本次指令无关的原有逻辑逐字保留"）—— 用户说「间距调大点」，拿到的是**代码被改了**。

## 二、四条方案 → 落点

| 方案 | 落点 | 关键设计 |
|:--|:--|:--|
| **1 复制带清单** | `POST /api/strategies` 的 `copy_from` + `strategy_io::derive_manifest`；前端「复制」与「模板新建」都带 | **落盘顺序 = 先写清单 → 再 `write_strategy_files` → 脚本失败则 `rollback_manifest`**；`copy_from` 与 `overwrite=true` 互斥 400；源未声明清单也 400（直说"裸脚本复制不带来参数说明，请在副本页点识别"） |
| **2 静态提取** | `strategies/params.rs::extract_param_hints` + `POST /api/strategies/extract-params` + 清单编辑器「从脚本识别参数」 | **无状态**（吃编辑器里的草稿）；先遮罩注释/引号串/长括号串再扫；结果**按源码位置排序**去重；类型取 **API 语义**、默认值取**字面量兜底**；变量键一律跳过 |
| **3 AI 改配置** | `ai-edit` 的 `mode:"params"` + `provider::quick_params` + AI 卡分段 chip | 缺省仍是 `code`（老前端不带该字段照常）；**双保险** = 提示词只准用清单里的键 + 回包侧 `keep_manifest_params` 丢弃清单外的键并如实回 warning；全丢 → 400 `no_params` |
| **4 引导卡** | 参数卡里的 `#sg-params-guide` | 判据 = 服务端事实（`detail.params` 过滤保留键后为空）；清单为空时「问 AI 怎么配」**只把用户推去走第一步**，不假装能直接问 |

### 2.1 为什么"先写清单"而不是"先写脚本"

`write_strategy_files` 内部本来就是「备份 `.toml` → 写 `.lua` → 写 `.toml` → 失败回滚」的小事务。
把清单挂在它**之前**：清单写失败 → **一个字都还没落盘**，不需要回滚；
反过来（先写脚本）失败则要恢复 `.lua` **和** `.toml` 两个文件，回滚面大得多。
脚本阶段失败时调 `rollback_manifest`（原先不存在则删掉刚写的，原先存在则恢复备份），
不留"有清单没脚本"的半成品。

### 2.2 静态提取的三条边界（都写进了注释与测试）

1. **遮罩优先**：`--…` 行注释 / `--[==[…]==]` 块注释 / `"…"`·`'…'` 引号串 / `[[…]]`·`[==[…]==]`
   长括号串里的"调用"一律不得被提取（否则说明文字里的示例会被当成真参数）。
2. **顺序 = 源码顺序**：先收集 `(位置, 骨架)` 再排序去重。**不能边扫边 push** ——
   外层遍历的是标记表，直接 push 会让输出顺序取决于标记表顺序（所有 `num` 挤在一起）。
   清单声明的顺序就是表单顺序，顺序错了表单也跟着乱。
3. **变量键不猜**：`num(ctx, k, d)` 这种辅助函数体里的 `ctx:config_f64(k)` 是变量，不产出参数 ——
   所以辅助函数不会被误当成参数。

### 2.3 已知偏差**照实钉住**（不为了让断言好看去对齐）

`paired_grid` 有两处**代码字面量**与**清单声明**本就不一致：

| 键 | 代码里的字面量兜底 | 清单声明 |
|:--|:--|:--|
| `min_pair_profit` | `0` | `0.002` |
| `start_price` | `0` | 无默认（`required`） |

提取的职责是"**代码读了什么**"，不是"清单说该是多少"。两边都如实保留，
单测 `paired_grid_keys_match_manifest_exactly` 把 `min_pair_profit = f64:0` 显式断言住，
防止以后被"顺手对齐"。

> **验收口径订正**：研究文档 §四原写「默认值逐项相等」，**过强**，已在该文里改写并标注（本轮 T20）。

## 三、前端（无构建链，全部 `include_str!`）

- **AI 卡分段 chip**：默认停在「调参数」—— 用户的困惑正是"不知道该配什么"，先给一条**不动代码**的路。
  点 chip → `setAiMode()` 同时切高亮、换「执行」按钮标签、换一行提示语。
  **`data-zh`/`data-en` 与 `textContent` 一起改写**：只改 `textContent` 的话，切语言时
  `R.applyLang` 会按 data 属性把文案盖回**旧模式**那一句（这是本轮特意防的坑，CDP 走查有断言）。
- **params 回包 → 参数表单**：`fillParamInputs` 只认表单里画得出来的行（`st.paramInputs`），
  `pair` 单独走 `#sg-pair`。返回**真正填上**的条数，0 条时提示语换成「AI 建议的参数都落在本页参数表单之外」
  —— **绝不假报"已填好"**。
- **引导卡的位置**：必须放在 `#sg-params` **外面**。`renderParams` 每次 `innerHTML = ""`，
  放里面会被一起抹掉（写进注释）。
- **切语言**：引导卡的文字是动态建的（没有 `data-zh` 可换），`refreshDynamic` 里**只重建这块** ——
  重建参数行/清单行会把用户填了一半的值抹掉。
- **「其他已保存参数」**补一句来源说明（`sgOtherParamsHint`）。**没有**按研究文档原样挂术语表：
  `/api/terms` 里没有 `fee_side` / `spacing_pct` 这类参数键，挂上去是个**空操作**；
  而"这些键来自实例 TOML、还没被声明"才是用户看不懂的根源。
- `help.js` 的 `GUIDE` 第 2 步**扩写**（不是新增一步）：抽屉的纪律是"不复述后端能力清单"，步骤数也不该膨胀。

### 4.3 走查脚手架两处修正（都是**脚本自身**的问题，产品零改动）

新增 ⑨ 段后连着跑了 4 轮才全绿。两次红都是脚手架，**没有一次指向产品**，但都会长期影响可信度，故记下来：

| 症状 | 真因 | 处置 |
|:--|:--|:--|
| 第二次跑起 `无未捕获异常` 变红，报 409 | ⑧ 段用**固定名** `zz_cfg_probe` 造裸脚本策略；策略没有删除端点，第二次跑必然 409，而前端 `R.api` 会顺手 `console.error` → 染红收口断言 | 改成 `zz_cfg_probe<ts>`（与 ⑨ 的副本名同法）。注释里写明"这是脚本不幂等，不是产品缺陷" |
| ⑧ 段已干净，409 却**漂到最开头**（页面加载期的收口断言） | 走查是复用浏览器里**已存在**的那个标签页；`Log.enable` 会把该页**此前缓存的 console 条目重放一遍** —— 上一轮 ⑧ 段故意造的 409 于是被算进这一轮的"加载期零异常" | 改为每轮 `PUT /json/new` 开**全新标签页**（无历史可重放），跑完 `GET /json/close/<id>` 自关，结束后池里稳定只剩 1 个；`PUT /json/new` 不被支持的老 Chromium 退回复用现有页 |
| ⑨ 编号出现两次 | 新插的"用户原始路径"段沿用了收口段的编号 | 收口段改 ⑩ |

**这一条的普遍教训**：真机走查里"页面加载期零异常"这类断言，必须配**干净的初始页**，否则跨轮污染会伪装成产品回归 —— 而且方向恰好相反（红的是旧账，不是新错）。

## 五、明确不做（与研究文档一致）

- **不引入前端构建链**（宪法「少而精」）；本轮零新增依赖。
- **不让 AI 直接落盘** —— 两个模式都保持「草稿 → 用户点保存」的两段式。
- **不为未声明的裸脚本自动编造中文名 / 说明**；也**不**在复制时"自动跑一遍提取再自动落清单"：
  清单里 `min_pair_profit` / `start_price` 两处与代码本就不一致，自动写一份可能**失真**的清单，比不写更糟。
- 复制时不搬运源策略实例 TOML 里的**已调参数值**（副本按清单默认值起步）—— 保持"复制代码 + 复制说明书"，
  不偷偷继承一份用户看不见的取值。

## 六、遗留 / 风险

- **AI 两个模式的真实上游调用没有真机覆盖**：干净 root 无密钥，能断言到 403 `need_keys`（联网前即拒）；
  `mode=params` 的**回包解析与键过滤**由离线单测覆盖（`keep_manifest_params` / `extract_json_object` /
  `coerce_suggested`），但"真模型回一串 JSON"这一段没有端到端。属已知缺口，与 032 起 `ai-edit` 的覆盖口径一致。
- **复制不继承实例值**（见上，有意）。若日后要改，落点明确：`onCopy` 多取一次详情，把 `current` 作为 `params` 带上。
- 引导卡的第二个动作在清单为空时**只给指引**，用户要"点识别 → 保存清单 → 再回来问"三步。
  不是死路，但确实是三步；若日后要压成一步，最小改动是让「问 AI 怎么配」在清单为空时**先自动识别并保存**
  —— 那会引入"静默写盘"，与现有纪律冲突，故本轮不做。

## 七、追加需求 N1 / N2 / N3 收敛（2026-10-12）

起因是用户三条指令（逐字见 `new-tasks.md`），其中 N3 在开工前被**重定义**过一次。
任务分解与落地实况见 `new-tasks.md`；这里只记**决策与教训**。

### 7.1 三条需求的共同点：都是"用户干不了的那部分"

| | 用户原来的处境 | 改成 |
|:--|:--|:--|
| N1 | 建废的自定义策略**在 Web UI 里删不掉**（全仓没有任何删除端点） | 能删，且**如实告知"历史保留"** |
| N2 | 想保存清单就得给每个参数**起中文名** —— 而用户是脚本的**使用者不是作者**，他不知道作者把旋钮叫什么 | 允许留空（**不写假数据**，界面回退显示键名），有注释就搬、想更好就按「让 AI 起名」 |
| N3 | 得说"把 `spacing_pct` 改成 0.02" —— 而这件事**他自己点两下表单就能做** | 只说意图（「保守点」），AI 给整组 + 讲风险 + **实跑回测告诉他影响** |

### 7.2 关键决策（都写在代码注释里了，免得下次被当成 bug 修掉）

1. **`code` 模式仍然单轮**。`params` 改多轮是因为"上一轮那组参数"是增量信息；
   `code` 每轮产出**整份代码**，上一轮那版已在编辑器里,历史只会挤占代码的注意力预算。
2. **`ai-assess` 不跑回测**。回测是作业（409 busy / progress / 5 分钟保留 / running 兜底 60 分钟），
   `/api/backtest` 已有整套；在 AI 端点里再开一条同步回测路径 = 把并发规则**抄第二遍**，
   而且"没配 AI key"会让回测都跑不了。故拆成「前端串三步 + 后端只解读」。
3. **两次评估必须同窗口**（`ASSESS_DAYS = 90` / `ASSESS_INTERVAL = "1h"` 写死）。
   让用户两次各填窗口，出来的差异就分不清是参数造成的还是窗口造成的 —— 那这个对比就没有意义。
4. **`before` 有两种来源，必须分开标注**（`before_is_default`）：实例里的值是"这组参数**真的在跑**"，
   清单里的是"**只是默认值，你还没保存过**"。混在一起就是编造运行事实。
   比较用**格式化文本**（`1` 与 `1.0` 不算变）—— `ConfigValue` 没有 `PartialEq`,而且我们要的就是
   "用户看到的数字变没变"。
5. **保存成功后同步 `detailCtx.detail.current`**。否则评估的「改前」会一直比到**进页面时**那份
   （可能落后好几轮改动），对比出来的数字看着像实测、其实比错了对象。
6. **对话线程按策略清空**。历史会被原样拼进提示词,换策略接着聊会把上一个策略的上下文带过去。

### 7.3 教训：静态门抓不到"值错了"

N2-C 的 `sg-mf-name` **按钮与输入框撞 id** —— `getElementById` 只认先渲染的 input,
于是「让 AI 起中文名」的 click 挂到了文本框上、按钮还显示成「策略中文名」。
`markets.js` 的 `mkRetry` 也是**在同一个字典块里定义了两次**（后者胜出）。

这两条的共同点：**语法合法、双语齐、引用有定义** —— `node --check` / 双语对应 / 引用完整性 /
`data-zh` 配对**四道静态门结构上都抓不到**。故：
- `web_frontend_check.mjs` 加 **G 段「同名碰撞」**（字典重复键 / 同文件重复 DOM id 字面量）。
  **踩过的坑**：必须**先剥注释再扫** —— 注里提一句旧 id 就是假红线（首跑真报过）；
  `html` 还要先剥 `<!-- -->`（`index.html` 的 `id="panels"` 在注释里也出现过）。
- `probe_web_ui.mjs` 补真机断言：**按钮真的在、文案没被同名键盖掉、输入框仍是可编辑的 `INPUT`**。

### 7.4 教训：冒烟脚本自己有 3 条错断言（不是产品缺陷）

跑这一轮时 `e2e_web.py` 报了 4 条非网络 RED，分诊后**全在脚本侧**：

| 错断言 | 为什么错 | 改成 |
|:--|:--|:--|
| 「缺中文名 / 缺说明 / 顶层 name 为空」在**应 400** 矩阵里 | 这三条正是 N2 要**放开**的 | 移出矩阵，另立正向断言：**应 200 且留空要原样落盘**（回读确认，不是只看状态码） |
| 邻居策略 `zz_del_probe2.toml`（**清单**）必须在 | 那个邻居是**裸脚本**建的，**本来就没有清单** | 先如实取"现在真有哪几个文件"，再断言删邻居后**一个都没少** |
| 「内置脚本仍在磁盘上」查 `RICOW_ROOT/strategies/spot/paired_grid.lua` | **内置策略的脚本随仓库/binary 走，不在 `RICOW_ROOT` 下** | 改判**服务端还认它**（目录里仍在 + 详情仍可读）—— 这才证明 409 是"拒绝了且什么也没动" |

**使用前提**（也是这一轮踩到的）：`e2e_web.py` 假设**干净的 RICOW_ROOT**。同一个 root 连跑第二次
会撞「同名策略 'zz_web_probe' 已存在」（409），连带 3 条断言变红。换新 root 重起服务即可。
