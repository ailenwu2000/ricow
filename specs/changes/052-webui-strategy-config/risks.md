## R1 · AI 两个模式缺「真回包」端到端

**取证**

| 事实 | 位置 |
|:--|:--|
| 现有真机 smoke 明写纪律「不 mock，真实 HTTP」，且全部 `#[ignore]` | `crates/ricow/tests/ai_live_smoke.rs:15` |
| `mode=params` 的**回包解析与键过滤**只有离线单测 | `strategy_io/mod.rs:1181-1232` + `tests.rs` 的 `extract_json_object` / `keep_manifest_params` |
| 冒烟里没有一条走 `ai-edit` | `ai_live_smoke.rs` 的 S1–S13 全是对话链路 |

**危害**：能兜住的只有"我们**假定**的模型输出形状"。模型一旦把 JSON 包进 ```json 围栏、把
`params` 改成 `values`、或整段回成一个数组 —— 过滤逻辑会把结果**全丢**，前端只看到一句
"AI 建议的参数都落在本页参数表单之外"，没人能判断是模型的问题还是我们的问题。

**冲突点（关键，决定了落点）**

`ai_live_smoke.rs` 文件头自定纪律是「**不 mock，真实 HTTP**」。所以要加"假上游"必须
**另找落点**，否则等于当场违反那份文件自己写的规则。

**可行性取证（这条决定了成本）**

| 事实 | 位置 | 含义 |
|:--|:--|:--|
| 回环地址**无条件放行** AI 主机门 | `ai/config.rs:155-158` | 指向 `http://127.0.0.1:<port>` **不需要** `allow_custom_base_url`，不必动那个"故意不进 WRITABLE"的开关 |
| 回环端点缺密钥时用占位值 | `ai/provider.rs:86-88` | 测试**零密钥夹具**，不碰任何 secret |
| 已有 `ENV_LOCK` 串行化范式 | `commands::test_util::ENV_LOCK`（`strategy_io/tests.rs` 多处在用） | 设 `RICOW_AI_BASE_URL` 有现成做法 |

⇒ **「把 AI 指向本机假上游」可以零产品改动实现。**

**选项**

| | 做法 | 改动面 | 代价 | 能抓到什么 |
|:--|:--|:--|:--|:--|
| **A** | 在 `web/strategy_io/tests.rs` 加一条 `#[tokio::test]`：起本机假上游 → 指向它 → 走真 HTTP 调 `ai-edit?mode=params` → 断言"合法键留下 / 清单外键丢弃并 warning / 类型不符 warning / **Lua 一字未改**"，再补一条"回包不是 JSON → 400 `params_parse`" | ~120–150 行测试 + 一个假上游助手；**零产品改动** | 低；进 CI，永久防链路腐烂 | 我们自己的解析/过滤/错误映射整链 |
| **B** | 在 `ai_live_smoke.rs` 加 S14（`#[ignore]`，与既有 12 条同口径）：真模型答"把间距改成 0.02" → 断言回包是 JSON 且 `spacing_pct == 0.02` | ~40 行 | 低；仅在你有 key 时手动跑 | **真实模型的输出形状漂移**（围栏、字段名、回数组） |
| **C** | A + B | 两者之和 | 中 | 两者之和 |

**推荐 A + B**。若只想做一件：**选 A** —— 它进 CI，B 永远可能被忘掉。

**A 的实现细节（供判断）**：假上游两种写法 ——
① 用 `axum`（已是依赖）挂一个只处理 `POST /chat/completions` 的路由；
② 手写约 30 行裸 socket，读掉请求头后回一个固定 JSON。
**推荐 ②**：这个客户端只发一个 POST，裸 socket 更小、且不用在测试里装配路由。

所以任何方案都不能是"默认就继承且不告诉用户"。

**选项**

| | 做法 | 改动面 | 评价 |
|:--|:--|:--|:--|
| **A** | 保持现状 | 零 | 与现有纪律最一致；但用户直觉落空 |

| **C** | 默认继承 + 详情页标注"这些值继承自 X" + 给一个「恢复默认」按钮 | 前后端都要动（标注 + 恢复入口） | 解决了"看不见"，但**默认行为变了**，与 §五 冲突最直接 |

## R3 · 清单为空时「问 AI 怎么配」是三步（**有硬冲突**）

**取证**

| 事实 | 位置 |
|:--|:--|
| 清单保存**强制** `name`（中文名）非空 | `strategy_io/mod.rs:550-551` |
| 清单保存**强制** `desc`（说明）非空 | `strategy_io/mod.rs:553-556` |
| 静态提取只产出 `key` / `type` / `default` 三项，**刻意不产 `name`/`desc`** | `strategies/params.rs:16-19`（"不猜中文名、不编说明"） |

**危害**：用户点「问 AI 怎么配」→ 被告知"先去识别参数"→ 点识别 → 清单编辑器多出 11 行
**每行都缺中文名和说明** → 填完才能保存 → 再回来问。

**冲突点（硬）**：想压成一步就得"识别完直接保存"，而保存**必然**因为没有 `name`/`desc` 被 400 拒。
两条出路都会撞别的纪律：
- 放宽校验 → 清单可以带着空说明发布 → 参数表出现无说明的行，且**全仓所有**清单保存路径一起松绑；
- 自动填中文名/说明 → 就是 spec §三 明写"不做"的**编造作者意图**。

**选项**

| | 做法 | 代价 | 评价 |
|:--|:--|:--|:--|
| **A** | 保持三步 | 零 | 不是死路，但确实三步 |
| **B** | 点「识别参数」后**直接把用户送进清单编辑器并标出缺说明的行**（聚焦第一处） | 前端小改；**不动校验** | 仍是三步，但第二步不再是"对着一片空行发愣" |
| **C** | 放宽后端校验：`desc` 允许为空（只要求 `name`） | 后端 + 测试；**全仓清单保存一起松绑** | 与"说明必须填"的既有口径冲突，影响面超出 052 |
| **D** | 「识别并保存」用**键名**当 `name`、`desc` 填一句**诚实占位**（如「（自动识别，请补充说明）」），用户之后再补 | 前端小改；**不动校验**（占位非空，天然通过） | 占位**没有编造语义**（它没说参数什么意思，只说"请补充"），一眼看出是待补项；一键即可保存成功 |
| **E** | 静默写盘（自动识别 + 自动保存） | —— | 与"不让 AI/系统静默落盘"的纪律直接冲突，**不建议** |

**推荐 D**（可与 B 叠加：保存后仍把用户带到那几行待补项）。

**为什么 D 不算"编造说明"**：spec §三禁的是**编造参数的语义**（"间距百分比"这种作者意图）。
占位文本的语义是"这里还没写"，是**事实陈述**，不是猜测。这条界线要在落地时写进注释与测试名。

## R5 · 静态提取**静默**跳过变量键（本轮复核新发现）

**取证**：`strategies/params.rs:101-110` —— 当键不是字符串字面量时，代码**直接跳过且不计任何数**，
返回体 `ExtractParamsReply` 也只有 `params: Vec<ParamHint>`（`strategy_io/mod.rs:724-727`）。

**危害**：脚本里若有 `ctx:config_f64(k)` 这类**真读了参数但键是变量**的写法，提取结果会**看起来完整**
地少一项。用户照着清单保存 → 运行期这个参数没人声明 → 只能靠运行时报错发现。
这违反本仓库既有纪律「**略去的行必须报数**」。

**冲突点**：无（纯增强）。

**选项**

| | 做法 | 改动面 | 评价 |
|:--|:--|:--|:--|
| **A** | 保持静默 | 零 | 与纪律不符 |
| **B** | 提取时统计「形似参数读取但键非字面量」的处数，在返回体加一个计数字段，前端在识别结果后追加一句"另有 N 处用了变量键，已跳过" | `params.rs` 约 10 行 + 返回体 1 字段 + 前端 1 句 + 测试 | 与"报数"纪律一致；用户知道**可能不全**，不会误以为清单已完整 |

**推荐 B**。计数口径要写清楚：**只数"调用形态匹配、且 `ctx` 检查通过、但键不是字面量"**的那一类，
不把 `my_num(` 这类词边界过滤掉的误命中算进去（否则计数虚高，用户学会无视它）。
