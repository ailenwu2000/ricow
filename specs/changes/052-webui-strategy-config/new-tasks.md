### 冲突（要如实记，这是需求变更）

你这条**推翻了两处既有决定**：

1. **052 spec §三「明确不做」**写着：*不为裸脚本自动编造中文名/说明 —— 中文名与说明属于作者意图，**由用户填***。
   当时那个假设（"用户知道"）是错的：**用户是这份脚本的使用者，不是作者**。他知道自己要什么，
   但不知道作者把那个旋钮叫什么。
2. **上一轮 R3 的选定**（诚实占位「（自动识别，请补充说明）」）—— 它虽然没编造语义，
   **但仍然把负担留给了用户**，等于没解决你的问题。

## N3 · AI 修改 = 多轮对话 + 说意图改整组 + 自动评估影响

### 用户重定义（2026-10-11 深夜，逐字）

> AI修改参数对话建议改成多轮，甚至不需要用户说具体修改哪个参数、改成多少（这个毫无意义，因为我们可以通过接口直接修改）。应该用户可以根据用户的意见修改整体参数（如保守点， 如更看好什么数据面等等），而非具体修改哪个值。修改完了AI还要自动帮助用户评估当前参数组会带来的具体影响。只有这样，才是真正的AI修改参数！

**这推翻了上一轮选定的 N3-A（单轮 + 解释）。** 上一轮 A 的缺陷是：用户仍然得说"把 spacing_pct 改成 0.02" ——
而这件事用户自己点两下表单就能做，根本不需要 AI。AI 该干的是**用户干不了的那部分**：
把"保守点"这种意图翻译成一整套参数，并告诉你这么改的代价。

### 四条选定（本次）

| | 选中 | 要点 |
|:--|:--|:--|
| 对话落点 | **就地对话** | 策略页 AI 修改区改成对话面板；历史只在前端内存，刷新即失；每轮把「当前参数组 + 清单说明 + 上一轮评估」随请求带上，AI 因此不会忘 |
| 评估对照 | **两组对比** | 改前这组、改后这组，同一窗口各跑一次回测，比 `max_drawdown` / `annual_volatility` / `sharpe` / `win_rate` / `total_trades` 等 |
| 回测窗口 | **回测默认** | 与回测页面同口径（默认 90 天 / 1h），结论能跟回测页面、历史回测直接对上 |
| 交付 | **一次做全** | N1 + N2 + N3 同批做完，不拆成半成品 |

### 现状取证（为什么这次成本比想象低）

| **指标够用**：`max_drawdown` / `annual_volatility` / `sharpe` / `sortino` / `calmar` / `win_rate` / `total_trades` / `rejected_count` / `net_pnl` / `profit_factor` / `turnover_ratio` | `commands/backtest.rs::MetricsSummary` |
| 详情接口已给 `pair` 与 `current`（当前参数值），评估要用 | `strategy_io/mod.rs:263-275` |

### 硬约束（决定实现方式）

- **同一策略同时只能有一个回测在跑**（撞上 → 409 `code:"busy"`）；结果只留 5 分钟；running 兜底 60 分钟。
  → 两次评估必须**串行**，且要处理 busy 与超时。
- **`ChatSession::Options` 没有 system prompt 注入点** → 策略上下文只能随消息带进去。
  这正是选"就地对话 + 每轮带上下文"而不是"转交对话视图"的理由。
- 回测要么命中本地 K 线缓存（快），要么联网拉（慢 / 可能失败）→ 评估失败必须如实说，不许编。

### 闭环

```
用户说意图「保守点」「更看好震荡市的数据面」
  → AI 给出整组参数 + 说清为什么这么改 + 风险
  → 自动跑回测：当前组、建议组（同窗口，串行）
  → 把两组实测指标喂回 AI
  → AI 用大白话讲「这组参数会带来什么具体影响」（带数字）/ 明确标注哪些只是推演
  → 用户可继续追问（多轮）
  → 满意才点「保存」落盘
```

### 要写死的纪律

1. **数字只能来自实测回测。** 任何没跑成的项（busy / 超时 / 取数失败），答复里必须说明是**推演**而非结论，
   不得拿推演冒充实测。界面上两者要用不同的措辞区分，不能混成一句。
2. **不得编造作者没写的语义。** 风险说明的依据只有：清单里作者写的 `desc`、参数的类型/默认值/当前值、
   Lua 代码本身、实测指标。四样之外的"经验之谈"必须标明是模型的推断。
3. **清单说明为空时**（N2 允许留空，此后会常见）如实标注"依据不足，仅供参考"。
4. **评估不写盘。** 改完只是"建议"，用户点「保存」才落盘 —— 沿用 052 既有纪律。

### 计划外但必须记的三件事

1. **`code` 模式仍然是有意的单轮**。计划里只说 `params` 改多轮，没说 `code` —— 这不是遗漏：
   `code` 每轮产出**整份代码**，上一轮那版已经在编辑器里，历史没有增量信息、只会挤占代码本身的
   注意力预算。已把这句写进 `ai_edit_strategy` 的文档注释与前端注释，免得下次被当成 bug "修"掉。

2. **`ai-assess` 不跑回测是刻意的**。回测是**作业**（409 busy / progress / 结果留 5 分钟 / running 兜底 60 分钟），
   `/api/backtest` 已有整套；在 AI 端点里再开一条同步回测路径，等于把并发规则**抄第二遍**，
   而且"没配 AI key"会让回测都跑不了。故拆成「前端串三步 + 后端只解读」—— 职责单一，失败也各自可归因。

3. **顺带修掉两个既有缺陷，并为这一类加了护栏**：
   - 前端 `sg-mf-name` **按钮与输入框撞 id** → `getElementById` 只认先渲染的 input，
     「让 AI 起中文名」的 click 挂到了文本框上、按钮显示成「策略中文名」（**点了没反应**）。
     改 `sg-mf-autoname` + 文案键改名。
   - `markets.js` 的 `mkRetry` 在同一个字典块里**定义了两次**（后者胜出）。
   - 这两条共同点：**语法合法、双语齐、引用有定义** —— 四道静态门**结构上抓不到**。
     故给 `scripts/web_frontend_check.mjs` 加 **G 段「同名碰撞」**（字典重复键 / 同文件重复 DOM id 字面量），
     并在 `scripts/probe_web_ui.mjs` 补「按钮真的在、真的可点」的真机断言。
     `stripComments` 要先剥注释再扫 —— 否则注释里提一句旧 id 就是假红线（首跑真踩到过）。

### 顺手修掉的 3 条**冒烟脚本自身**的错断言（不是产品缺陷）
