# 025 功能规格: Web UI 模式(浏览器内对话 · 多会话历史 · 术语点击解释 · 双语)

**状态**: 待评审 (2026-09-19) | **依据**: 用户需求九条 + 六项已拍板决策 + `specs/constitution.md`「完全本地化 / 少而精 YAGNI」原则 + `019-ai-assistant` 预留的 `SessionSink` 架构缝

## 一、为什么

`019-ai-assistant` 落地了对话入口, `023-ai-chat-ux` 把对话体验做到了"非技术用户可用"。但入口形态仍是 **终端 stdio**:

1. **终端是门槛**: 双击启动脚本后是一个黑框, 用户要识字、要会用终端、要理解"回车 / Ctrl+C"; 对"对电脑技术不熟悉的用户"仍不友好。
2. **历史看完就没了**: 终端滚动区是唯一历史, `023` 的 `/history` 只回看**当前会话**, 关窗口即消失; 用户想"翻回上周那次对话"做不到。
3. **术语是墙**: `023` 做了"去术语化", 但回测报告里的 `夏普比率` / `最大回撤` / `年化收益` 这类**指标名无法去术语化**(它们是指标本身), 终端里也**没有任何方式**让用户就地查"这是什么意思"。
4. **无视觉层次**: 终端只有单色文本, 警告与报错和普通回执长得一样, 用户容易漏看关键信息。

`019` 在设计时已明确预留了本次变更的接入点 —— `crates/ricow/src/ai/session.rs` 模块头原文:

> 将来接网页端 = 新写一个 WS/HTTP sink 并复用本文件, 业务逻辑零复制。

本变更正是兑现这条设计意图: **新增一个浏览器前端, 复用全部会话内核**, 让"点击启动 → 浏览器里聊天 → 完成所有动作"成为主路径, **终端 CLI 一行不改**。

## 二、范围

**做**:
- 新增 `ricow web` 子命令: 启动内置 HTTP 服务, 只绑 `127.0.0.1`, 随机端口 + token 鉴权, 自动打开系统默认浏览器。
- 新增前端页面: 左侧竖长会话列表(可新建 / 切换 / 删除), 右侧上下拆分(上方 = 用户与 AI 输出区, 下方 = 输入区)。
- 新增 Web 侧 `SessionSink` 实现: 把助手增量文本 / 宿主行 / 密钥录入 / 用户输入全部改走浏览器通道, **复用 `ChatSession` 全部业务逻辑**。
- 输出分级着色: 普通 / 提示 / 警告 / 错误四种语义, 前端按级别给不同颜色。
- 术语解释: 回测指标名与量化术语可点击, 弹出当前语言的解释; 解释数据源取自既有 `format_backtest_report` 的指标文案全集, 不凭空造词。
- 多会话持久化: 会话与消息落 SQLite(复用既有 `ricow_strategy::db::Database`), 重开页面可恢复; 切换回旧会话时把**最近 20 轮**作为 AI 上下文(token 上限截断)。
- 单页面双语: 右上角语言切换按钮; 界面文案 / 术语解释 / AI 回复语言 / 宿主固定文案**整套切换**; 语言落 `ricow.toml` 的 `[ui].lang`, 与 CLI 共用同一配置。
- 新增 Web 专用启动脚本(Windows `.cmd` / macOS `.command` / Linux `.sh` 三平台), 双击即用。

**不做**:
- **不改任何既有 CLI 行为** —— `chat.rs` / `ai.rs` / `approve.rs` / `ctrl.rs` / `commands/*` 的用户可见行为与文案逐字保留; 现有三个启动脚本**逐字节不动**。
- 不引入 i18n 框架(沿用 `023` 决策 D13: 无 Fluent/gettext、无资源文件、无构建期生成)。
- 不引入前端构建链(无 npm / 无打包器 / 无 TypeScript 编译) —— 前端为**手写静态资源 + `include_str!` 内嵌**, 与 `templates.rs` / `prompt.rs` 既有做法一致。
- 不做 WebSocket 双向协议(单向流式用 SSE 足够)。
- 不做多用户 / 远程访问 / 账号体系 —— 服务**只绑 `127.0.0.1`**, 不上公网。
- 不做对话内的富交互(不改 `confirm` 状态机语义: 确认仍靠**回一句话**, 不做前端按钮直确认)。
- 不改 `PENDING_TTL(15 分钟)` / 单槽 pending / 过期优先 / 终端 tty 门禁。
- 不做回测图表可视化、不做 K 线图、不做策略编辑器 GUI。
- 不做会话导出 / 导入 / 云同步。

## 三、功能需求

### 启动与服务化(F0)

- **FR-001**: `main.rs` 的 `Command` 枚举新增 `Web(commands::web::WebArgs)` 变体, 并在 `main()` 分发链新增对应分支; `WebArgs` 至少含 `--port`(默认 `0` = 自动选空闲端口)与 `--no-open`(不自动开浏览器)。
- **FR-002**: 服务只绑 `127.0.0.1`; 启动时生成一次性随机 token, 通过 URL query 传给浏览器; 每个请求校验 token, 比较用**常量时间函数**(照抄 `supervisor::server::ct_eq`)。token 不匹配 → `401` 且不泄露任何会话内容。
- **FR-003**: 启动即打印/输出可点击 URL(含 token); 除 `--no-open` 外调用系统默认浏览器打开该 URL。
- **FR-004**: Web 启动路径与 CLI 对话路径**共用同一套前置检查**: 复用 `onboard::run_if_needed`(首次向导)与 `config_file::permission_warning`。无 AI 密钥时不得静默失败, 要在浏览器内给出可操作的提示。
- **FR-005**: Web 模式下 `ChatSession` 必须以 **`interactive = true`** 打开 —— 否则 `tools.rs` 的 `if !ctx.interactive` 分支会把所有确认动作替换成"当前不是交互式终端"提示, 用户无法在浏览器内完成任何写操作(这直接决定 FR-025 能否成立)。实现上须把 `session.rs` 的 `interactive` 判定从 `opts.interactive && stdin.is_terminal()` 改为**由前端能力声明**: 终端前端仍走 `is_terminal()`, Web 前端直接声明 true。

### 页面布局与交互(F1)

- **FR-006**: 页面为**单页**, 三区布局固定: 左侧竖长栏 = 会话列表; 右侧上区 = 对话流(用户与 AI 输出); 右侧下区 = 输入框。
- **FR-007**: 左侧会话列表每项显示会话标题与最后活动时间; 支持**新建会话**、**切换会话**(点击即加载该会话历史)、**删除会话**(需二次确认)。
- **FR-008**: 右侧上区按时间顺序渲染往返消息; 助手回复**流式增量呈现**(不是整段蹦出); 渲染期间自动滚到底部, 用户手动上滚时不强制拉回。
- **FR-009**: 输入区支持 `Enter` 发送 / `Shift+Enter` 换行; 助手回复期间输入区禁用并给出"正在思考"态; 空输入不发送。
- **FR-010**: 斜杠命令( `/history` `/lang` `/keys` 等)在输入区内可用, 行为与终端一致; 宿主产出的菜单以**可点击列表**渲染, 点击等价于输入对应序号。

### 对话能力对齐(F2)

- **FR-011**: 会话内核 `ChatSession` 的**全部既有能力**在 Web 端可达: 普通提问 / 流式回答 / 工具调用 / 只读查询 / 回测 / 预览 / 写操作确认 / `/history` / `/lang` / `/keys` / 菜单。
- **FR-012**: `SessionSink` 新增**输入侧抽象**: 用户输入读取与密钥录入不再由实现方自行 `stdin()` 硬编码, 而是由前端实现提供(终端实现行为一行不变)。`/keys` 在 Web 端必须**能录入密钥且不回显到对话流**。
- **FR-013**: `SessionSink` 的输出增加**语义级别**, 至少区分 `普通 / 提示 / 警告 / 错误`; 前端按级别着色。级别由宿主侧显式标注, **不做关键字猜测**。
- **FR-014**: `chat.rs` 的 `repl` 对 sink 的依赖由具体类型放宽为 trait 对象, 使 Web 前端可复用同一 REPL 循环; `StdioSink` 现有行为与输出**逐字不变**。
- **FR-015**: `SessionSink::secret` 若在 Web 端由异步通道提供, 须保持"**取不到就不写文件**"语义 —— `None` 一律放弃本次修改。
- **FR-016**: Web 端不做前端按钮直确认: 写操作确认仍要求用户在输入区回**当前语言的单个口语词**(沿用 `023` 决策, `confirm` 状态机零改动)。

### 历史会话持久化(F3)

- **FR-017**: 会话与消息落 SQLite, 复用既有 `ricow_strategy::db::Database`(其 `open` 已启用 WAL / 外键 / `create_if_missing`); 新表在 `db.rs` 的 `migrate()` 内以 `CREATE TABLE IF NOT EXISTS` **幂等**追加, 不改动任何既有表。
- **FR-018**: 至少两张表: 会话表(标题 / 创建时间 / 最后活动时间)与消息表(所属会话 / 角色 / 内容 / 级别 / 时间); 外键级联删除, 删除会话即删其消息。
- **FR-019**: 删除会话后不残留孤儿消息; **不自动清理**历史会话(不做 TTL / 不做上限淘汰)。
- **FR-020**: 切换回旧会话时, 把该会话**最近 20 轮**往返装入 `ChatSession.history` 作为 AI 上下文; 超出部分按既有 `clip_for_history` 的字符上限截断, 保证不撑爆 token。新会话为空上下文。
- **FR-021**: 重新打开 Web 页面(或重启 `ricow web`)后, 左侧会话列表与各会话消息**完全恢复**; 刷新页面不丢当前会话。
- **FR-022**: 会话标题自动生成(取首条用户消息截断); 不做手动重命名。

### 可视化与术语解释(F4)

- **FR-023**: 对话流中**关键字 / 警告 / 错误**按级别着色(FR-013); 配色与既有站点 `website/style.css` 的深色系保持一致。
- **FR-024**: 量化术语与指标名(如 `夏普比率` / `最大回撤` / `年化收益` / `资金费率` / `滑点` / `杠杆` 等)**可鼠标点击**, 弹出该术语**当前语言**的通俗解释(一句话 + 必要的口径说明), 面向小白用户。
- **FR-025**: 回测报告类输出在 Web 端以**结构化渲染**呈现(指标名可点击), 而不是原样贴一段等宽文本; 指标口径与 `format_backtest_report` **同一来源**, 不新增第二套定义。
- **FR-026**: 术语解释内容为**静态内置**数据(随前端资源内嵌), 不联网、不依赖 AI 生成 —— 保证离线可用与解释一致性。
- **FR-027**: 体验增强(策略列表查询等)必须是**只读**的: 任何从页面触发的写动作仍必须走 FR-016 的对话确认流程。

### 双语(F5)

- **FR-028**: 页面右上角提供**语言切换**控件(中文 / English), 切换后**整套**生效: 界面文案、术语解释、宿主固定文案、且 AI 回复语言随之切换。
- **FR-029**: 语言落 `ricow.toml` 的 `[ui].lang`(复用 `config_file::UiSection` 与 `set_values`, 保留注释); 与 CLI **共用同一配置** —— 在 Web 切到 `en` 后, 终端 `ricow ai` 也是英文, 反之亦然。
- **FR-030**: 切换语言后**立即生效**, 不需重启服务(会话内核须按新语言重建 LLM 客户端, 复用既有 `rebuild_llm` 语义)。
- **FR-031**: 语言非法值仍按 `023` 规则**硬失败**; 页面文案不允许出现中英叠排(不得写成 `请选择语言 / Choose your language`), 必须按当前语言单选呈现。

### CLI 零回归(F6)

- **FR-032**: 既有 CLI 的**用户可见行为零变化**: 默认 `ricow`(无参)仍进终端对话; `ricow ai "..."` 仍为单次模式; 全部子命令输出文案与退出码不变。
- **FR-033**: `packaging/` 现有三个启动脚本**逐字节不动**; Web 启动脚本为**新增文件**(三平台各一), 复用同一套"三级二进制查找 + 切换工作目录"逻辑, 只把启动行换成 `ricow web`。
- **FR-034**: 终端渠道的确认短语、tty 门禁、`require_interactive_terminal` 语义**一行不改**。

## 四、验收标准

- **SC-001**: `cargo fmt --all -- --check` 零差异、`cargo clippy --workspace --all-targets --locked -- -D warnings` 零警告、`cargo test --workspace --locked` 全绿, 基线 **403 passed / 0 failed / 21 ignored** 不得倒退。
- **SC-002**: 零回归证明: `git diff` 中 `crates/ricow/src/commands/chat.rs` 的 `StdioSink` 输出字面量、`approve.rs`、`ctrl.rs`、`commands/ai.rs` 用户可见文案**无改动**; `packaging/` 三个既有脚本**逐字节不变**。
- **SC-003**: 端到端(真实调用, 禁 mock): 双击 Web 启动脚本 → 自动打开浏览器 → 页面可加载 → 在输入区发一句真实提问 → 收到**流式**回答。全程无终端交互。
- **SC-004**: 写操作端到端: 在浏览器内完成一次"部署策略"或"启动测试网"—— AI 给出确认块, 用户回一个口语词, 动作**真实执行**; 证明 `ctx.interactive` 在 Web 端为 true(FR-005)。
- **SC-005**: token 鉴权单测/集成: 无 token 或错 token 的请求返回 `401`, 且响应体不含任何会话内容; 服务监听地址断言为 `127.0.0.1`(不监听 `0.0.0.0`)。
- **SC-006**: 持久化集成: 新建两个会话各发若干轮 → 关闭页面重开 → 两会话与消息完整恢复, 顺序与内容一致; 删除其中一个 → 其消息行数为 0(外键级联生效)。
- **SC-007**: 上下文恢复单测: 旧会话含 30 轮时, 装入 `ChatSession.history` 的往返数为 **20**, 且单条超长内容被截断(复用 `clip_for_history` 上限)。
- **SC-008**: 分级着色单测: 至少一条"错误"类输出与一条"普通"类输出, 其宿主侧标注级别不同(证明级别来自显式标注而非关键字猜测)。
- **SC-009**: 术语解释覆盖: `format_backtest_report` 输出的**每一个指标名**在术语表中有对应条目, 且**中英各一份**; 断言无遗漏(grep 双向核对)。
- **SC-010**: 双语一致性: 用 `en` 打开页面 → 界面文案与术语解释为英文、AI 回复为英文; 切到 `zh` → 全部变中文且 `ricow.toml` 的 `[ui].lang` 已落盘为 `zh`; 同一份配置下终端 `ricow ai` 语言一致。
- **SC-011**: `/keys` 在 Web 端可用, 且明文密钥**不出现在对话流**与浏览器 localStorage 中。
- **SC-012**: 离线可构建: 在断网环境下 `cargo build --locked` 成功(依赖仅用本地 registry 缓存; `Cargo.lock` 已含 axum 0.8 全套)。
- **SC-013**: 文档同步: `specs/architecture.md` 补 Web 模式接入点(并更新 `session.rs` 模块头"将来接网页端"表述), `specs/product.md` / `README.md` / `README_zh.md` 补 Web 启动方式, `specs/roadmap.md` 记录本变更。

## 五、假设

- 用户机器上已有**现代浏览器**(支持 EventSource / flex 布局); 不兼容 IE。
- 用户接受"服务只在**本机**运行、随机端口、关掉进程即停服"; 不需要开机自启或守护。
- Web 前端不参与策略执行, 仅作**对话前端**; 所有业务能力仍由既有内核提供, Web 层不复制任何业务逻辑。
- SQLite 会话库与既有行情库**同一文件/同一 `Database` 实例**; 若因并发写产生锁竞争, 以"对话场景低频写"为前提接受。
