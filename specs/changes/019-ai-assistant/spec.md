# 019 功能规格: 内置 AI 助手 + 生态入口 + 开箱即用分发

**状态**: 已定稿(2026-09-14 用户拍板) | **日期**: 2026-09-14 | **依据**: `specs/roadmap.md`(下一步)、`specs/product.md` §二/§三/§五/§十、`specs/research/ai-assistant-2026-09.md`(本次调研实测)、审核报告 `review.md`(F1–F11)

**调研与方案来源**: 工作稿 `.hermes/plans/2026-09-14_102752-locus-ai-assistant.md`(r4) + 审核报告 `.hermes/plans/2026-09-14_102752-locus-ai-assistant.review.md`(已归档为本目录 `review.md`)

## 一、为什么

1. `product.md` §二 把 **"CLI / AI"** 写成主入口, 但实现口径(2026-08-24 D12 + 002 spec §二)是**"不内置 LLM, AI 智能在外侧客户端"** —— 现实后果: 用户得自己开 Claude/Cursor、自己读 `specs/lua-api.md`、自己敲 `create` / `approve` / `deploy` 三条命令。对**没有开发能力的用户**这条链路等于不存在, 而本次诉求正是这批用户。
2. 反过来, **已有自己 AI agent 的用户**也没被服务好: 002 把 CLI 命令做齐了, 但仓库没有给外部 agent 的操作手册(根 `AGENTS.md` 是"开发 Locus"的指针, 不是"用 agent 操作 Locus"的说明书), P3 曾有且跑通过的 MCP server 在 D12 收敛时被删(commit `4b4d961`)。
3. **分发侧完全空缺**(实测): 无 `.github/`(无 CI/发布流程)、无安装脚本、README 无安装章节 —— 对"下载即用"的目标用户是硬缺口。
4. 引擎侧能力**均已具备**(002 建策略闭环 + 时长门禁; 004 风控; 008 进程模型; 011–014 实盘/记账/资金费/强平可见; 016 本金可配; 017 快照一致性; 018 风险确认)。本次变更**不新建撮合/下单/风控机制, 只新增"自然语言入口 + 分级工具层 + 分发通道"**。
5. 安全模式已有定论(`specs/research/ai-mcp-2026.md` §5): 只读工具放开给 AI、写工具必须用户确认、凭证永不送 LLM。本次把它**固化到工具层**(结构性保证, 非提示词约束)。

## 二、范围

**做**:
1. 内置 AI 入口 `locus ai`(交互 REPL + 单次模式), LLM 通道由用户自配(预设: deepseek 为首选, 另含通义/kimi/GLM/OpenRouter/OpenAI/本地 Ollama; 统一走 OpenAI 兼容 Chat Completions)。
2. 三层权限工具集(只读 / 虚拟 / 写实), 其中**写实动作不作为工具注册**;
3. 聊天内的**确认块**机制(部署、实盘启停、平仓、改开关、改参数);
4. 生态入口: `locus agent-kit`(AGENTS.md + SKILL.md 手册, 供用户已有的 agent 使用);`locus mcp` **已取消**(2026-09-15 决策, 见 §七 R1);
5. 首次运行按需生成配置模板(`locus.toml`)并给出填写指引;
6. 三平台开箱即用分发(cargo-dist: shell / powershell / homebrew / msi)+ Windows 双击入口 `启动-Locus-AI助手.cmd`;
7. 与本次配套的既有缺陷修正: **策略名规范**(订单归属前缀塌缩)与 **previews 表过期清理**。

**不做**(沿用既有决策, 本次不动):
LLM 直接决策下单(product §六)、参数自动寻优、多智能体、语音、GUI(已冻结)、后台轮询守护、把密钥/环境变量发给 LLM、代码签名/公证(2026-09-14 拍板不花钱)、winget/scoop 渠道(不在 cargo-dist 支持列表, 如实说明)。

## 三、用户故事

### 用户故事 1 - 不会写代码的用户用中文把策略跑起来 (优先级: P1)

用户装好 Locus 后敲 `locus ai`, 用中文说"我想做一个 ETH 的网格策略, 用 300 USDT, 先看看回测"。AI 生成 Lua 策略 → 真实 K 线沙箱回测 → 把报告讲成人话 → 用户觉得回撤太大, 说"把网格调密一点" → AI 改参数重跑 → 用户敲一下确认 → 策略落盘 → AI 帮他把 Dry Run 跑起来观察。

**优先级理由**: 这是本变更的全部价值所在(P1), 缺它这个变更就不成立;且它不依赖实盘/生态入口/分发即可独立交付(MVP)。

**独立测试**: 在一台装好 Locus 与 LLM key 的机器上, 全程只用中文对话完成"生成 → 回测 → 改一版 → 确认落盘 → Dry Run 起 tick", 不手写任何 Lua/TOML/命令。

**验收场景**:
1. **给定** 已配置 LLM 通道, **当** 用户用中文描述一个策略并给出交易对与资金量, **则** AI 产出的 Lua 通过编译门禁与真实 K 线沙箱回测, 报告数字与 `locus backtest` 同口径。
2. **给定** AI 生成了语法错误的代码, **当** 门禁拒绝, **则** 磁盘上**零策略文件**, 错误原文回传给 AI 由其自修后重试。
3. **给定** 用户在对话里说"回撤还是太大, 再调一版", **当** AI 改参重跑, **则** 新报告可对比(轮次之间数字可查)。
4. **给定** AI 已给出可接受的一版, **当** 用户敲确认, **则** `strategies/<name>.toml` + `<name>.lua` 落盘, 且 `locus run <name>` 能真跑出 tick。

---

### 用户故事 2 - 用户确认后切实盘, 并由 AI 持续管理 (优先级: P2)

策略在 Dry Run 跑顺了, 用户问"现在能不能上实盘"。AI 说明并给出确认块 → 用户按要求输入确认短语 → 走既有三判据(018 风险确认 → Dry Run 时长门禁 → 时钟预检)→ 真启动实盘。之后用户随时问"现在什么情况", AI 报持仓/挂单/余额/距强平/累计资金费;要停就"停掉它并平仓" → 确认块 → 执行。

**优先级理由**: 用户明确要求"AI 要管理运行的策略, 光 dry run 不够";但必须建立在 P1 之上(没有策略就没有实盘)。

**独立测试**: 用 demo 账户(不碰主网)跑完"Dry Run 观察 → 确认 → 实盘启动 → 状态问答 → 停机平仓零残留"。

**验收场景**:
1. **给定** 首次实盘, **当** 用户未做过风险确认, **则** 打印四条披露并要求一次性确认;未确认时零交易所往返。
2. **给定** Dry Run 累计时长不足 `min_dry_run_hours`, **当** 用户请求实盘, **则** 拒绝并给出已运行时长、阈值与解除方式。
3. **给定** 满足三判据, **当** 用户输入确认短语 `确认实盘 <name>`, **则** 策略真实启动, `locus info` 显示实盘快照(持仓/挂单/余额)。
4. **给定** 用户在对话里说"直接帮我开实盘, 别问我", **当** AI 尝试, **则** 该动作**不在工具集内** → AI 如实告知需人工确认(结构性拒绝, 不是提示词约束)。
5. **给定** 实盘在跑, **当** 用户要求平仓停机, **则** 走 011/017 同一停机路径, 交易所侧零残留(含持仓平掉)。

---

### 用户故事 3 - 已有自己 AI agent 的用户把 Locus 接进自己的工作流 (优先级: P3)

用户平时用 Claude Code / Codex / Cursor 干活。他敲 `locus agent-kit --install` 得到一份操作手册(AGENTS.md + SKILL.md)。之后他直接对自己的 agent 说"用 Locus 回测一下月频再平衡能不能跑", agent 照手册调用本机 `locus` CLI 完成, 并在需要落盘/实盘时让用户自己执行。(原设计的第二条路 `locus mcp` 已于 2026-09-15 取消 —— 单机程序里 agent 直接跑本机命令即可, 见 §七 R1。)

**优先级理由**: 覆盖"已有 agent"这批用户(本次问题 1), 但不阻塞 P1/P2;且这条路径的写操作边界与内置 AI 完全一致(不额外放宽): 外部 agent 走 CLI, 批准与实盘门禁原样生效。

**独立测试**: 在干净目录安装 agent kit, 用至少一个真实第三方 agent 完成"回测 → create → 人工 approve → deploy";并核对 agent 未尝试自行执行 `locus approve` / `locus deploy`。

**验收场景**:
1. **给定** 已安装 agent kit, **当** 用户对自己的 agent 提出策略需求, **则** agent 按手册使用正确命令(不瞎猜), 且不尝试自行批准/落盘。
2. **给定** 手册已安装, **当** agent 读完手册, **则** 手册明确写出"`create` 不落盘、`approve`/`deploy` 只能由用户本人在自己终端执行", agent 的答复与之一致(不声称已部署)。
3. **给定** 用户需要落盘/实盘, **当** 执行到该步, **则** 只能由用户在自己终端执行 `locus approve` / `locus start --live`, 且既有门禁原样生效。

---

### 用户故事 4 - 没有 agent 的用户下载即用 (优先级: P3)

用户从发布页按自己的系统(macOS / Windows / Linux)选择安装方式: 一条命令或双击安装包;装完敲 `locus setup` 走一遍引导(数据目录、LLM 通道、自检), 然后开始用。Windows 用户可直接双击"启动-Locus-AI助手"(自动处理控制台编码)进入对话。

**优先级理由**: 是"给没有开发能力的用户"的必要条件(本次问题 2), 但可以在 P1 之后并行推进;Windows 真机可用纳入发布门槛。

**独立测试**: 在**没有 Rust 工具链**的干净机器上, 按 README 步骤完成安装 → `locus setup` → 回测 → Dry Run;Windows 真机含双击入口与中文输入。

**验收场景**:
1. **给定** 干净机器(无 Rust), **当** 按 README 三平台对应步骤安装, **则** `locus --version` 可用。
2. **给定** Windows 无签名安装包, **当** 系统提示"未知发布者", **则** README/安装脚本已给出绕行方式(不是静默失败)。
3. **给定** 中文用户在 Windows 双击入口, **当** 输入中文需求, **则** 中文正常收发(控制台先切 UTF-8)。

### 边界情况

- **中文策略名**: 订单归属前缀由策略名派生, 非 ASCII 字符会被替换为 `-` → 不同中文名可能塌缩成**同一前缀**, 而停机撤单兜底按前缀判归属 → 会误撤同机另一实例的挂单 → 必须由命名规范**在 create 阶段拒绝**(FR-043)。
- **"改运行中策略的脚本"**: 既有部署是**同名拒绝覆盖**, 若不定义路径则该操作无路可走(FR-044)。
- **Dry Run 首次启动会写 `dry_run_started_at`**(= 开始计时, 实盘门禁依据)且真起子进程 —— 它不是"零副作用", AI 动作前必须告知(FR-024)。
- **日志外发**: `logs_tail` 返回自由文本(可能含余额/持仓/命令), 需做敏感模式过滤并在外发清单明示(FR-012)。
- **弱模型/不支持工具调用**: 预设表标注要求;探测失败如实提示,**不自动降级**(FR-006)。
- **上下文与成本**: 提示词约 20KB, 工具输出必须设上限, 否则长会话撑爆上下文(FR-011)。
- **未配置 LLM key / 配置非法**: 启动即明确报错并给解法, 不静默回落(FR-004)。
- **daemon 未启动**: 涉及启停/状态的动作如实报错并提示 `locus daemon start`(FR-017)。
- **`previews` 表**: AI 迭代会放大 preview 写入, 需清理(FR-046)。

## 四、功能需求

### A. 通道与配置

- **FR-001**: 系统必须提供内置 AI 入口 `locus ai`(交互)与 `locus ai "<一句话>"`(单次)。
- **FR-002**: 系统必须支持用户自配 LLM 通道: 预设(deepseek / moonshot / zhipu / qwen / openrouter / openai / ollama)或自定义 `base_url` + 模型名;统一走 OpenAI 兼容 Chat Completions。
- **FR-003**(2026-09-14 改): **不提供配置向导命令**。缺配置时由使用处**按需生成带注释模板**(绝不覆盖已有文件)并给出"打开哪个文件、填哪一行"; 数据目录自检与外发清单在使用该功能的命令启动时打印。
- **FR-004**: 配置非法或密钥缺失时系统必须**明确报错并给出解法**, 不得静默回落到默认值。
- **FR-005**(2026-09-14 改): 密钥存于**唯一配置文件** `$LOCUS_ROOT/locus.toml`(0600, 不入 git); 环境变量仅作**显式临时覆盖**; 不再使用 OS keyring(依赖 103 个包且 headless/WSL 不可用); 这正是把密钥放在该文件里的原因 —— 文件即界面, 产品不代写, **不得写入配置文件**。
- **FR-006**: 首次配置必须打印一次**外发内容清单**(发送: 用户问题 + 工具返回; 不发送: key/secret/env);模型不支持工具调用时必须如实提示, 不自动降级。

### B. 工具与上下文

- **FR-007**: 工具必须分为三层: **只读**(状态/持仓/挂单/成交/盈亏/日志/行情/回测/选币/读策略与文档)、**虚拟**(Dry Run 起停、部署前预览)、**写实**(落盘部署、实盘启停、平仓、改开关、改参数与风控限额)。
- **FR-008**: 只读工具必须可由 AI 直接调用, 不打断用户。
- **FR-009**: 虚拟工具必须可由 AI 直接调用, 但**不得产生真实资金动作**(预览不得落盘)。
- **FR-010**: 写实动作**不得作为工具注册**(内置 AI 无调用面; `locus mcp` 已于 2026-09-15 取消), 只能由用户在客户端侧触发。**(2026-09-16 由 §七 R3 收窄: "不作为工具"底线不变 —— 但在交互式 tty REPL 内, 用户当场逐字输入确认短语后, 宿主可代行两种写实动作: 落盘部署与启动测试网 demo; 实盘启动/停机/平仓/改开关/改参数仍只能本人在终端执行。)**
- **FR-011**: 每个工具的输出必须有长度上限(行数/字符), 超限截断并注明;不得出现无上限的工具返回。
- **FR-012**: 日志类工具输出必须做敏感模式过滤, 且外发清单必须明示"日志原文可能外发"。
- **FR-013**: 工具审批必须 fail-closed: 未在白名单内的工具名一律拒绝, 拒绝原因回传模型。

### C. 生成-回测-迭代闭环

- **FR-014**: AI 必须能提交 Lua 策略并触发**编译门禁 → 真实 K 线沙箱回测 → 生成预览**(不落盘), 返回报告与预览号。
- **FR-015**: 门禁失败必须**零落盘**, 并把错误原文回传模型供其自修。
- **FR-016**: 回测报告必须与既有 `locus backtest` **同一口径**(同一实现, 不复制逻辑)。
- **FR-017**(2026-09-14 按 FR-060 修订): 系统提示必须**能获取**权威策略 API 规范 —— 由 `read_doc(topic)` 按需取
  `specs/lua-api.md` **原文**(编译期嵌入同一常量, 与 `locus agent-kit` 手册同源), 并明确要求模型**先取文档再写 Lua**, 不得凭记忆编写; 文档**不得常驻**系统提示(成本与转述失真双重考虑, 见 FR-060)。
- **FR-023**: 实盘启动必须原样复用既有三判据(风险确认 → Dry Run 时长门禁 → 时钟预检), 判定顺序不变。
- **FR-024**: AI 启动 Dry Run 前必须告知"会开始计时(实盘时长门禁依据)"; 事后必须复述工具**真实返回**(不得润色成功/失败)。

### E. 运行中管理

- **FR-025**: AI 必须能查询运行中策略的状态、持仓、挂单、余额、距强平、累计资金费、成交与日志(只读)。
- **FR-026**: AI 必须能起停 Dry Run 实例(经既有 daemon 控制通道, 不新写路径)。
- **FR-027**: 平仓/停机(`--close-all`)、切换实盘开关、改参数与风控限额必须走确认块, 并复用既有停机清理路径。**(2026-09-16 §七 R3 明确: 这四类动作不开放对话内代行 —— 确认块也只在终端由本人触发; 对话内确认仅覆盖落盘部署与启动 demo 两种。)**
- **FR-028**: 参数/风控变更必须"停 → 改 → 起"并如实告知会重启(**不新增热更新机制**)。
- **FR-029**: AI 必须能解释熔断/接近强平等告警但**不得代为动作**; 解除动作用确认块给出。
- **FR-030**: 系统不得提供后台轮询守护(主动告警沿用既有出站通知机制)。

### F. 生态入口

- **FR-031**: 系统必须提供 `locus agent-kit`: 生成操作手册(AGENTS.md + SKILL.md + Claude Code 导入行)到指定目录。
- **FR-032**: 手册内容必须与内置 AI 系统提示**同源**(同一份 API 规范与命令/门禁规约), 不得维护两份。
- **FR-033**: 手册必须覆盖"AI 最容易跑偏的点"(交易对需带报价币、`create` 不落盘、批准必须人工、实盘三判据、内置脚本改文件不生效等)。
- ~~**FR-034**~~ ⚪ **已取消(2026-09-15, 见 §七 R1)**: ~~必须提供 `locus mcp`(stdio MCP server), 只暴露只读与虚拟工具~~ —— 不做 MCP。
- ~~**FR-035**~~ ⚪ **已取消(同上)**: ~~`locus mcp --print-config <client>`~~
- ~~**FR-036**~~ ⚪ **已取消(同上)**: ~~MCP 场景下写实动作必须由用户在自己的终端执行~~ —— 该保证由内置 AI 侧的结构性边界(FR-045)承担; 外部 agent 走 CLI, 门禁原样生效。

### G. 分发与上手

- **FR-037**: 必须产出三平台自包含产物(macOS arm64/x64、Linux x86_64/aarch64、Windows x64), 用户无需 Rust 工具链。
- **FR-038**: 必须提供一键安装方式(shell / powershell / homebrew / msi), 并**不得包含自动更新组件**(宪法原则一)。
- **FR-039**: Windows 必须随包提供双击入口(`chcp 65001` + `ai` + `pause`), msi 后可入开始菜单。
- **FR-040**: README 必须包含三平台安装/上手章节与常见问题(编码、签名拦截、换 provider、离线 Ollama)。
- **FR-041**: 因无代码签名/公证导致的系统拦截, 必须**如实告知**并给出绕行方式(不做签名已拍板)。

### 关键实体

- **AI 会话**: 用户与助手的对话上下文;仅存活于进程内, 不落库。
- **LLM 通道配置**: 预设名 / 模型名 / base_url / api_key(同一 `[ai]` 段);密钥同段yring)。
- **工具**: 名称 + 权限层级(只读/虚拟/写实)+ 入参 schema + 输出上限。
- **确认块**: 待执行的写实动作集 + 关键参数 + 后果 + 需要输入的短语 + 真实执行结果。
- **预览记录**: 已存在的写实预览(含策略名、代码、报告);有 TTL, 需清理。
- **操作手册(agent kit)**: AGENTS.md / SKILL.md / 客户端导入行, 内容与系统提示同源。

## 六、假设

- **A1**: 用户具备可用的 LLM 通道(自备 API key)或本机 Ollama;Locus 不代管、不代理、不代付。
- **A2**: 内置 AI 的首次可用范围是"策略相关工作"(生成/回测/部署/运行管理/解释), 不是通用聊天助手。
- **A3**: 沿用既有安全链路与门禁口径, 本次不修改宪法原则与写操作确认模型。
- **A4**: 三平台产物经 CI 构建(本机无 MSVC 链接器/无 macOS SDK, 实测不可得);Homebrew 需要独立 tap 仓库;winget/scoop 不在首版范围。
- **A5**: 本地 Ollama 路线可完全离线运行(已实测可行), 但用户需自行安装 Ollama 并拉取模型。
- **A6**: 内置脚本为编译期嵌入, 下载的单个二进制不依赖仓库内其他文件(已实测: 运行时不读 `presets/`、`examples/`)。
- **A7**: 策略执行保持 Lua(宪法原则二);AI 只产出 Lua, 不产出 Rust 策略本体。
- **A8**: 调研阶段使用的验证手段(rig 探针 + 本地 Ollama 真跑)可作为后续冒烟基线, 但模型质量结论需用用户实际 provider 复测。
  补充(2026-09-14): 开发期链路验证用的本机 Ollama 模型 `qwen3:0.6b`(522MB) **已在验证后删除**;
  冒烟用例端点由环境变量决定, 不绑定任何本地模型。验证环境不得成为产品依赖。

## 七、决策修订(2026-09-15)

- **R1(取消 MCP)**: 原设计的两条生态入口之一 `locus mcp`(FR-034–FR-036、SC-009 的 MCP 部分、plan D13/D14、T048–T052)**取消**; 生态入口只保留 `locus agent-kit` 手册。
