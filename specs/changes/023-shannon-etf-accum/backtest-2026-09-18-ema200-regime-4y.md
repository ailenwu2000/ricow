## 三、读数

1. **4h / 1h 上判据同时改善收益与回撤**(两组都是干净对照):
   - 4h: 期末总值 89,149 → **118,408**(+58.52pp), 回撤 66.64% → **40.06%**, 成交 636 → 130, 手续费 2,169 → 571。
   - 1h: 94,139 → **123,595**(+58.91pp), 回撤 58.07% → **36.95%**, 成交 2,533 → 347, 手续费 4,556 → 725。
   - 机制与上一轮诊断对得上: **网格把仓位钉在 50:50, 上涨里被 +2ATR 卖单削掉(BULL 不卖正好治它)**;
     BEAR 不买则避开 2022 崩盘里的"越跌越买"。期末币数与现金**同时**更高(4h: 267.65 → 290.01 枚,
     55,787 → 82,259 USDT), 不是"用更多仓位换收益"。
2. **交易密度大幅下降**: 成交笔数降到 1/5(4h)、1/7(1h), 手续费降到 1/4~1/6 —— 这是"少动"的直接结果。
3. **1d 组反而更差, 但不可直接归因于判据**: 2022 全年 BEAR → D2-A(熊市禁建仓)**把首次建仓推迟了约一年**
   (锚 106.9077 → 27.0391), 两组不同起点、样本仅 18 笔成交; 且该组"满仓/敞口对齐"基准按各自首次成交价
   起算 → 基准也不同(满仓 +31.38% vs +406.09%)。**该组只能当"日线主序列上判据会把入场推后"的观察, 不能当结论。**
4. **判据本身在三组粒度上完全一致**(93 次切换、同窗口同状态) → 判据确实只依赖日线, 未受主序列粒度污染 ✓。

## 四、过程中修掉的 2 个真问题(都会静默歪曲结论)

1. **预热不足时会把"请求窗口的开头"当预热吃掉** —— `--start 2022-01-01` + 603 天日线预热, 而 SOL 现货
   自 2020-08 才有: 引擎 `skip` 固定按 603 天算, 于是 on-4h **只有 8,196 根(窗口少 95 天)**, 与 off-4h
   的 8,766 根不可比。修法(`crates/ricow/src/commands/backtest.rs`): 预热"取到多少算多少" ——
   实际预热 = min(请求预热, 早于窗口起点的 bar 数), 并打 `WARN multiframe`(实测 `requested=3618 actual=3047`)。
2. **`--end` 闭区间多吃一根** —— 文档语义是"不含", 但交易所 `endTime` 是闭区间, 会把恰好落在窗口终点的
   那根 bar 也取回(on-4h 8,767 根 vs off-4h 8,766 根)。修法: 按 `open_time < end_ms` 裁剪。
   (修后两组都是 8,766 根、首根 open 相同 ✓; `off-*` 三组仍**逐位复现**上一轮的 +78.30% / +88.28% / +44.99%,
   证明"判据关"路径行为零漂移。)

## 五、代价与边界(如实标注)

1. **D1-B(锚不动)的代价可量化**: 虚拟账本在 BULL 里长期不回到 target(I1 被打破), 期末"有效倍数"
   从配置的 2.0 漂到 **1.395(4h)/1.294(1h)/1.704(1d)** → 下单量随之缩水。这是 D1-B 的必然结果,
   如要消除需改成"被拦时按市价整本重算 + 锚 := 市价"(即计划里的 D1-A)。
2. **实盘/模拟盘仍未接线**(用户 D4-A): `set_tf_klines` 只在回测装配层被调用 → 实盘下 `ctx:atr_tf` /
   `ctx:ema_tf` / `ctx:close_tf` 恒为 `nil` → **这条策略在实盘会完全不动**(既有 023 遗留, 本次未扩大)。
3. **历史短的标的在默认 `ema200` 下完全不动**(D3-A 的必然结果): 例如 QQQB 只有 ~79 天日线 → 判据永不就绪
   → 零下单。要跑这类标的需 `--param regime_filter=off` 或换判据周期。
4. **基准列不可跨开/关直接比**: "满仓/敞口对齐"都按**各自首次成交价**起算(用户既定纪律), 因此只与自身组相关;
   跨组可比的是"策略%"(期末总值 ÷ 5 万 − 1)与期末构成。
5. **样本**: 单一标的(SOL)、单一窗口(2022–2025, 含 2022 崩盘与 2023 +920% 两个极端年), 不能外推为通用规律。
6. 观察: `rebase_book` 函数在策略 Lua 里**定义但从未被调用**(既有遗留, 与本次改动无关)。
