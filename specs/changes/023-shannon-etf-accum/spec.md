# 023 香农 ETF 指数增加策略 —— 规格

> 状态: 已确认方案(2026-09-17 用户拍板); 实施中。
> 完整技术方案见 `plan.md`(与 `.hermes/plans/2026-09-17_221854-shannon-etf-accum.md` 同源)。
> 分支: `feat/shannon-atr-grid`。

## 一、需求(用户原话归纳)

1. 买入 bStock ETF(默认 `QQQBUSDT`), 交易对可配置。
2. 间距 = `atr_mult × ATR(atr_interval, atr_period)`, 三档可配; 本次回测扫 `atr_mult ∈ {2, 3, 4.5}`、`atr_interval=1h`、`atr_period=14`。
3. 建仓: 1m K 线 `EMA10` 上穿 `EMA20`(金叉)时市价买入。**EMA 仅用于建仓**。
4. 本金可配置; 测试本金 **10000 USDT**, 建仓买 `现金 × target_ratio`(默认 50% = 5000 USDT)。
5. 记录最后一次成交价作为**平衡价**, 并记录该笔是买入还是卖出(`last_side`, 需可观测/可断言)。
6. 建仓后: 平衡价上下 `atr_mult × ATR` 各挂一张**香农再平衡限价单**(精确回到 `target_ratio` 的量), 行情插针触及即成交。
7. 每次成交后**实时更新平衡价**并撤余单、按新平衡价重挂; 任意时刻挂单 ≤ 2 张。
8. ATR 每根高周期 bar 只算一次(引擎侧按桶缓存)。

### 追加需求(2026-09-18, 用户定稿后实施)

9. **建仓后不再使用金叉/死叉**(用户原话: "买入后, 有了平衡价格, 就不再使用金叉和死叉") ——
   改为在平衡价 `±2ATR` 挂限价单(上卖下买), 量 = 虚拟账本回 target 的量。`enable_cross` 缺省
   `false`(Lua 与 CLI 注入两处一起改), 交叉通道仅作历史对照保留。
10. **日线趋势判据**(用户逐字口径): 用**上一根已收盘日线**的 close 与其 `EMA200` 比较 ——
   `close > EMA200×1.03` = BULL(可以买, **不卖**); `close < EMA200×0.97` = BEAR(可以卖, **不买**);
   带内(含等号) = RANGE(两侧正常)。定案细则(用户 2026-09-18 拍板):
   - D1-B: 被拦的一侧**只是"不挂那张单"**, 锚与虚拟账本**都不动**; 但该侧上一轮挂单必须撤销;
   - D2-A: 熊市禁买**含首次金叉建仓**(2022 这类整年熊市会整年不建仓, 属已知代价);
   - D3-A: 判据未就绪(通道未装 / 可见日线不足 period 根)→ **不下单**(不猜值);
   - D4-A: 本次只做回测链路, 实盘/模拟盘的高周期通道接线不在此范围;
   - D5: 预热 = 3×(period+1) 天`ta` 的 EMA 用首值种, 种子残差 `(1−2/(n+1))^k`: 201 天 13.5% /
     603 天 0.25%; SOL 现货自 2020-08-11 起 → 2022-01-01 起算实际拿到约 508 天(残差 ≈0.7%)。
   参数: `regime_filter = off|er|ema200`(内置缺省 `ema200`)/`regime_interval = "1d"` /
   `regime_ema_period = 200` / `regime_band_pct = 0.03`。判据走**高周期通道**(新 API
   `ctx:close_tf` / `ctx:ema_tf`), 缓存键由 `pair` 扩为 `pair|tf`(同一 pair 可同时装 4h ATR
   与日线判据两套序列)。

## 二、目标(用户原话)与可验证口径

| 目标 | 可验证口径 |
|:--|:--|
| 长期收益优于满仓持有 | (策略总价值变化% − **敞口对齐基准**(半仓买入持有)%) = 策略行为净贡献; 与满仓对照仅作参考(默认 50:50 下 `G(0.5) > G(1) ⟺ μ < 0.75σ²`, 期望为负, 见 plan §一) |
| 短期回撤更小 | 策略最大回撤 vs 满仓最大回撤(比值 ≈ `target_ratio` 属机械结果, 如实标注) |
| 波动中不断增加 ETF 份额 | 份额变化%(`coin_change_pct`), 需扣除价格下跌带来的机械增持(`Q ≈ E/(2P)`) |

## 三、验收(见 plan §八)

1. `cargo test --workspace --locked` 全绿(基线 339 passed / 12 ignored)。
2. 9 组真实数据回测(3 标的 × 3 乘数, 3 个月窗口/数据不足按实际, 本金 10000): 每组给出实际窗口、成交笔数、**跳过占比**、`rejected_count`、策略总价值/最大回撤/份额变化/期末现金 vs 满仓 vs 敞口对齐基准。
3. 目标逐条对照(只用实测数字, 不用机制宣称); 跳过 >80% 的组不作结论依据。
4. Dry Run 闭环 + demo 链路零残留(含挂单自愈)各一份实测记录。
5. 窗口诚实性: 3 个月样本只够冒烟与方向对照, 不下"长期"结论。
