>

## 一、市场 K 线指标叠加

### 动机

市场页 K 线是裸蜡烛图（无均线、无成交量），与任何主流行情界面相比都缺基本要素；
用户判断"趋势/放量"只能自己拿计算器。K 线数据本身已经带 `volume`（`ricow_core::Kline`），
缺的只是画出来。

### 需求

- FR-1: 市场页 K 线主图叠加 **MA7 / MA25 / MA99** 三条均线（简单移动平均，收盘价口径）。
- FR-2: 主图下方叠加**成交量柱**（同一图表实例的独立价格轴，占底部约 20% 高度）：
  收盘 ≥ 开盘 = 涨色，否则跌色（中国行情惯例: 涨红跌绿，复用主题变量）。
- FR-3: 周期切换（15m/1h/4h/1d）后指标随之重算；数据不足 99 根的窗口，MA99 缺失处**断线**
  （不画、不补 0、不用前值冒充 —— 缺口就是缺口）。
- FR-4: 指标**不新增后端端点、不新增依赖**：全部在前端由 `klines` 序列现算（零构建链路不变）。

## 二、回测图表补强

### 动机

回测已有权益曲线与买卖点，但缺三样主流产品的标配：
(1) 与"买入持有"的**基准对照**（指标卡里有 `benchmark_return_pct`，图上却看不到过程）；
(2) **回撤过程**（只有 `max_drawdown_pct` 标量，看不出回撤发生在何时、持续多久）；
(3) **平仓盈亏明细**（只有聚合胜率，无法逐笔核对）。

### 需求

- FR-5: 图表新增**基准线**：口径与 023 指标卡 `benchmark_return_pct` **同源** ——
  以**首次成交价**买入、同本金（`entry_equity`）满仓持有到期末；建仓前不画（空白段而非 0）。
  窗口内从未成交 → 无基准线（与指标卡 `None` 一致）。
- FR-6: 图表新增**回撤（水下）曲线**：逐点回撤 = (该点权益 − 历史峰值) / 历史峰值，
  0 在高位、向下为负；由**后端用全分辨率净值曲线**算完再抽稀（与标量 `max_drawdown` 同口径，
  避免前端对抽稀后的曲线重算导致口径不一致）。
- FR-7: 新增**平仓盈亏明细表**：逐条列出平仓事件的时刻与已实现盈亏（涨红跌绿着色），
  含与指标卡的一致性副标（行数 = 胜+负笔数，求和 = 已实现盈亏）。
- FR-8: 引擎的平仓事件记录**保最近 1000 条**并同时给出**总条数**；超限时界面必须明说
  "仅显示最近 1000 条（共 N 条）"，不许静默截断（诚实性硬约束）。

## 三、诚实性与纪律（不可协商）

- FR-9: 无平仓事件时明细表显示"本次回测没有平仓事件"，不渲染 0 行空表。
- FR-10: 前端零持久化存储（禁 localStorage/sessionStorage）；指标/明细数据一律经
  `textContent` / DOM API 注入，不拼 HTML；不出现任何交易所写动作（面板只读不变）。
- FR-11: 既有前端纪律扫描（`web/assets.rs`）与 `ALL_JS` / `index.html` 双向对齐测试保持全绿；
  本变更**不新增 JS 文件**（改两个既有文件 + CSS），故无需改清单。

## 非目标（显式不做）

- **行情实时化（WS → SSE）**：用户已定路线，另起 040。
- **逐笔 round-trip 交易配对**（开→平 配成一条"交易"）：口径在合约对冲/组合模式下有歧义，
  本变更只做**引擎自己的平仓事件**（与胜率/已实现盈亏同源，可机械核对）。
- **指标参数可配 / 指标开关面板**：固定 MA7/25/99 + 成交量常显（YAGNI；需要时再做）。
- **前端构建工具链 / TS 化**：035 已明确拒绝。
