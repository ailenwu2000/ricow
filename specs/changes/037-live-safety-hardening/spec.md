## 一、问题与目标

对标商用框架(NautilusTrader / LEAN / Hummingbot)的**架构级**差距: 商用框架把"订单/持仓状态"作引擎级一等公民, ricow 下放给 Lua 脚本。由此产生三个资金安全缺口:

1. **P0-A 启动不与交易所对账挂单**: `command.rs:1042-1056` 启动发现本实例归属挂单**只打 warn**, 不撤销不接管。进程崩溃/强杀/断电后重启, 遗留挂单仍挂在交易所, 而策略 `on_init` 会**再下一张同样的单** → 敞口翻倍。
2. **P0-B 无引擎级订单登记**: 无订单状态机、无在途订单跟踪; `orders` 表**只写不读**; 下单**传输失败(结果未知)**时不落任何记录, 事后无法回答"这一单到底提交成功没有"。
3. **P0-C 跨策略敞口不可见**: daemon 支持跑 N 个策略进程, 但**没有任何地方**能看到总名义敞口/各标的净头寸 —— 多策略场景下的盲区。

## 二、需求与验收

### FR-1 启动接管遗留挂单 (P0-A, 资金安全)

- **FR-1.1** 实盘/demo 启动时, 若交易所该交易对存在**本实例归属**(`is_owned`, `clientOrderId` 带 `<策略名>-` 前缀)的挂单, 逐个**撤销**。
- **FR-1.2** 非归属挂单(用户手工单/其他实例)**只上报不撤**(沿用既有 `plan_cleanup` 口径)。
- **FR-1.3** 撤销后**复查**; 若仍有本实例残留: **live 拒绝启动**(错误含残留单号与可执行指引), demo 只警告继续。理由: 与"时钟预检拒绝启动"同口径 —— 无法建立安全前置时不进实盘。
- **FR-1.4** 全过程如实落事件流(新 kind `orphan_canceled`)与 `outcome.orphan`; 不静默。
- **FR-1.5** 无配置面(固定工程不变量, 与 `order_guard` 同口径: 平台不做投资判断, 但安全不变量不接受配置)。

### FR-2 引擎级最小订单登记 (P0-B, 资金安全)

- **FR-2.1** 新增纯逻辑 `ricow_engine::oms::OrderRegistry`: 记录本次会话内本实例提交的每张订单及其生命周期状态(`Submitted/Open/PartiallyFilled/Filled/Canceled/Rejected/Unknown`)。
- **FR-2.2** **传输失败 = Unknown**: `place_order` 返回 `Err` 时登记为 `Unknown`(结果未知), 如实日志 + 事件; 停机时若仍有 `Unknown` → 收尾醒目提示用户手工核对交易所。
- **FR-2.3** **重复单号检测**: 同一 `client_order_id` 在**非终态**时被再次提交 → 计数 + warn + 事件(策略 bug 信号)。
- **FR-2.4** 会话内订单账目(`open/filled/canceled/unknown/duplicate`)计入 `RunOutcome`。
- **FR-2.5** 不引入策略可见面: 策略**看不到** registry(它只经 `ctx` 的既有只读查询)。

### FR-3 跨策略组合敞口只读视图 (P0-C)

- **FR-3.1** 新增**只读**聚合: 从本地 `positions` / `orders` 表汇总"各标的净头寸 + 挂单数"(按 strategy 维度可下钻)。
- **FR-3.2** **只展示, 不拦截**(守宪法"平台不做投资判断"); 无写动作、无新确认面。
- **FR-3.3** 数据源 = 本地库(与 026 口径一致: 本地库是唯一来源), **不直连交易所**。

## 三、明确不做(本轮)

| 项 | 理由 |
|:--|:--|
| **P0-D 单笔名义上限 / 异常速率熔断** | 需要**可配置的风险参数面**, 与宪法 D15/D17(删除 `RiskEngine` 四条静态限额、只保留固定 `order_guard`)**直接冲突** → 属宪法级决策, 必须用户显式拍板后再立项。见 §六 提议。 |
| 订单状态机完整 FSA / 改单 / 批量下单 | 属 P2 能力边界, 非本轮资金安全必需 |
| tick 级对账 / 交易所侧成交回补 | 依赖数据资产, 与本轮无关 |

- **既有回归**: `cargo test --workspace --no-fail-fast` 全绿(670 基线不减)。
- **门禁四件**: `fmt --check` / `clippy -D warnings` / `cargo deny check` / `ci_grep_gates.sh`。
- **架构守卫**: `architecture_guard` 三条用例全绿。
- **模拟验证**(用户授权): 用**内存 mock Exchange**验证启动接管与 OMS 接线(不涉 testnet; 交易流程的真机纪律不变, 本变更不新增下单语义)。

## 五、风险与回滚

| 风险 | 处置 |
|:--|:--|
| 启动接管误撤"其实还在跑的另一个同名实例"的单 | daemon 已防同名并发; 且既有**停机清理本就按前缀撤**, 风险等级不变。日志醒目记录每一笔撤销 |
| live 因残留拒绝启动, 用户卡住 | 错误信息给出逐条单号 + 手工撤单指引 + "撤销后重启" |
| OMS 登记影响主循环 | 全部纯内存、无 IO、无 await; 失败不阻断(与事件流同一旁路哲学) |
