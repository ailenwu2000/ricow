# 044 Web UI 体验补强：AI 对话 Markdown 渲染 + 日志面板搜索/过滤/跟随开关

## 一、动机

`tmp/webui_analysis.md` §四 P1 第 6、7 项：

- **AI 对话输出无 Markdown 渲染**：对话流按级别着色、纯文本。AI 回答里的代码块、表格、加粗、
  列表全部以原文呈现（`grep` 确认前端无任何 markdown 渲染逻辑）。ricow 的 AI 助手是**独有能力**
  （§附能力矩阵里标"领先"），而它的输出可读性却是全站最弱的一环。
- **日志面板无搜索/过滤/自动滚动开关**：SSE 续传（026）本身做得比主流好，但只有被动滚动 ——
  日志一长就没法定位，也没法"先停下来看几行"。小改动、大体验。

## 二、需求

### 功能需求

- **FR-1 受限 Markdown 子集（对话助手输出）**，覆盖 AI 实际会用的语法：
  围栏代码块（带语言标注）、行内代码、加粗、斜体、删除线、链接、标题（≤3 级）、
  无序/有序列表（含一级缩进嵌套）、引用块、水平线、表格、段落。
- **FR-2 只作用于助手气泡**：宿主输出（`line` 帧，含回测报告）保持原样渲染路径 ——
  报告结构化（FR-025）与术语标注（FR-024）都不受影响。理由：宿主输出是**对齐排版**的
  纯文本（`指标名: 值`、`--- 段标题 ---`），套 markdown 会把对齐打散。
- **FR-3 零 `innerHTML`**：渲染器**只**用 `document.createElement` / `textContent` /
  `createTextNode` 产出 DOM。分析文档原建议"只对渲染器产物放行 innerHTML 并改扫描白名单"，
  本变更**不采纳**：AI 输出是**不可信内容**，DOM API 路线既不需要动安全扫描的白名单，
  也不存在"转义漏一个地方就 XSS"的窗口。
- **FR-4 链接白名单协议**：只放行 `http:` / `https:`，其余（`javascript:` / `data:` 等）
  降级为纯文本；外链一律 `target="_blank"` + `rel="noopener noreferrer"`。
- **FR-5 代码块内不做术语标注**：术语浮层（FR-024）不再进 `<pre>` / `<code>` 内部
  （代码里的 `手续费` 之类的词不该变成可点术语）。
- **FR-6 日志搜索**：按关键字**不区分大小写**子串匹配，实时生效（含此后新到的行）。
- **FR-7 日志级别过滤**（**必须是诚实口径**）：日志行是文件里的**原样**文本（FR-018：不着色、
  不解析），所以"级别"只能是**行内关键字启发式**。UI 文案必须自陈这一点
  （「级别（按关键字粗略匹配）」），不得暗示精确分级。宿主的说明行（轮转 / 读不到）**始终显示**
  —— 它们解释的是"日志为什么断了一截"，被过滤掉会让用户误以为日志正常。
- **FR-8 跟随/暂停开关**：默认跟随；用户手动上滚即自动进入暂停（不抢滚动位置）；
  暂停期间新到的行只计数、不跳动，按钮显示待读条数，点击回到末尾并恢复跟随。
- **FR-9 诚实的计数**：显示"显示 M / 共 N 行"，并注明本地只保留最近 500 行
  （`LOG_DOM_MAX`，超出即丢最旧）—— 不许把"我没显示"说成"不存在"。
- **FR-10 双语**：新增控件全部走既有 `data-zh` / `data-en` 与 `R.TEXT` 双语机制，
  切语言时就地更新（含按钮上的动态文案）。

### 非功能需求

- **NFR-1 只读红线不动**：两块面板仍然是**只读**的 —— 不新增任何直连交易所的动作，
  不出现 `onclick` 等内联事件（既有扫描断言继续生效，见 D4）。
- **NFR-2 新增脚本进单一清单**：`markdown.js` 同时进 `assets.rs::ASSETS` 与 `index.html`，
  且**排在 `chat.js` 之前**；仓库既有加载顺序测试扩展覆盖。
- **NFR-3 纪律扫描不变**：`markdown.js` 同样受"禁浏览器存储 / 禁 `input.type=` /
  禁交易所写动作"扫描。
- **NFR-4 无新依赖**：手写渲染器，不引 marked.js（保"零供应链"）。

## 三、非目标

- 不做完整 CommonMark（不追求 spec 全合规）：不支持任意 HTML、引用嵌套、脚注、
  定义列表、HTML 实体表 —— 遇到不认识的语法**原样显示**，不猜。
- 不做语法高亮（Lua 高亮在策略页，与对话无关）。
- 不改日志源的读取方式（尾读 / 轮转 / 续传全不动），只在前端加过滤与滚动策略。
- 不做日志导出 / 下载。
- 不改 `LOG_TAIL_LINES`(200) / `LOG_DOM_MAX`(500)。

## 四、验收

1. `cargo test --workspace` 全绿；`node --check` 全部脚本通过（含 `markdown.js`）。
2. `e2e_web.py` 内嵌 + 磁盘两形态全绿，且**新增断言**：首页引用 `markdown.js`、
   `/markdown.js` 可取到、`chat.js` 里出现渲染入口。
3. 真机（headless Edge + CDP）：
   - 构造一条含代码块 / 表格 / 加粗 / 列表的助手消息，断言渲染出
     `<pre>` / `<table>` / `<strong>` / `<li>`，且**页面里没有 script 注入**（用
     `<img src=x onerror=...>` 之类做负例，断言它以纯文本出现、未执行）；
   - 日志面板：写入若干行后断言搜索命中数、级别过滤命中数、暂停时滚动位置不变且按钮显示待读计数。
4. 只读红线扫描断言仍生效（面板区无内联事件、无交易所写动作）。
