# 014 功能规格: 实盘资金费记账 + 强平风险可见 (合约)

**状态**: 未开始 | **日期**: 2026-09-13 | **依赖**: 012(合约实盘) / 013(回测按侧独立模型)

## 一、输入

013 把回测的合约记账校准到与真实账户一致(按侧独立钱包/强平、资金费两侧独立结算)。对照之下, **实盘侧仍缺两块**:

1. **资金费不入账**: 合约持仓每 8h 被真实扣/收资金费, 实盘引擎不记录 —— `fills` 表只有成交与手续费, 实盘报告的盈亏漏掉资金费(013 的 one-way 冒烟里资金费净额 −294.51 竟大于净盈亏 84.58, 说明长期持仓下该成本不可忽略)。
2. **强平风险不可见**: 交易所给的 `liquidationPrice` 在持仓查询里已有(012 `get_positions_directional`), 但引擎不计算"距强平还有多远", 也不告警 —— 杠杆持仓的尾部风险没有任何提示。

## 二、用户故事

- **US1**: 作为策略作者, 我要在实盘运行/停机后看到这段时间真实被扣了多少资金费, 以便与回测的 `funding_net` 对照。
- **US2**: 作为运维者, 我要在持仓接近强平价时收到告警(而不是等它爆掉), 并知道还剩多少距离。

## 三、功能需求

- **FR-001 资金费拉取**: 合约签名客户端新增 `GET /fapi/v1/income`(参数 `incomeType=FUNDING_FEE` / `startTime` / `limit`), 解析为 `FundingIncome { symbol, income, asset, time_ms, tran_id }`。
- **FR-002 资金费落库(幂等)**: 新表 `funding_fees(strategy_id, tran_id 唯一, symbol, income, asset, funding_time)`; 重复拉取不产生重复行(`tran_id` 唯一键)。
- **FR-003 增量拉取与水位**: 以 `MAX(funding_time)` 为水位只拉增量(跨进程重启自然续拉); 启动时补拉最近窗口(默认 7 天), 运行期每 30 分钟增量拉一次, 停机清理前再拉一次。
- **FR-004 资金费汇总**: 单策略资金费合计在 Rust 侧用 `Decimal` 精确聚合(不用 SQL `SUM`, 见 012 教训); `locus info` 与实盘停机输出显示"累计资金费 × 笔"。
- **FR-005 距强平距离**: 纯函数 `liquidation_distance(mark, liq, side) -> f64`(百分比, 多头 = (mark−liq)/mark, 空头 = (liq−mark)/mark); 实盘快照与成交后刷新持仓时计算, 低于阈值(**默认 15%**, 可用 `[risk]` 或 params 覆盖)时 `warn` 告警, 并如实标注 `liquidation_price` 缺失时为"未知"。
- **FR-006 只读不改**: 本变更不改变下单/撤单/平仓行为, 不引入自动减仓(强平兜底是交易所的职责); 告警只提示。

## 四、验收标准

- **SC-001**: `cargo test --workspace` 全绿; 既有 286 用例零回归。
- **SC-002**: 资金费落库幂等 —— 同一 `tran_id` 重复插入只保留一行(单测)。
- **SC-003**: 距强平距离计算正确(多头/空头/缺 liq 三类, 单测), 且阈值告警在真实数据上触发(实测: 高杠杆持仓的 liq 距离)。
- **SC-004**: demo 真实调用 `GET /fapi/v1/income` 成功(空结果也如实显示, 不伪造)。
- **SC-005**: 文档同步: `specs/testnet.md`(实测记录)、`architecture.md`(§十一 缺口)、`roadmap.md`、本档案 converge。

## 五、假设

- **A1**: 资金费数据以交易所 `income` 为准(不自行用资金费率×名义估算) —— 与"账单即事实"一致。
- **A2**: 资金费不并入 `PnlTracker`(它不是成交), 单独记账 + 单独展示, 避免污染成交口径的统计。
- **A3**: 只做合约(现货无资金费); 现货路径零改动。
