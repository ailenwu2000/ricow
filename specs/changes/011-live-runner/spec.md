# 功能规格: 实盘运行器 (live_enabled 生效)

**功能目录**: `specs/changes/011-live-runner`

**创建日期**: 2026-09-13

**状态**: 草稿 (口径 4 项已按推荐默认拍板, 见 §口径拍板; 复核时用户可推翻任何一项)

**输入**: 用户描述: "继续 (2026-09-13) —— 立实盘运行器变更: 让 `live_enabled=true` 真正生效, 真实下单/撤单/成交回执 + 引擎撤单兜底 + `stop --close-all` + `info` 持仓快照 + 下单前时钟预检 + tickSize/stepSize 对齐口径。"

> **起点事实 (2026-09-13 代码复核, 本变更的缺口依据)**:
> ① `locus run` 只有 Dry Run 一条路径 (`crates/locus_cli/src/commands/run.rs:62` → `Engine::run_dry_run`), 引擎无实盘入口;
> ② `LiveContext` 已实现 (含 004 风控前置与真实 `place_order`/`cancel_order`), 但全仓**无任何构造点**(仅 `lib.rs` 重导出) → 实盘链路当前不可达;
> ③ 账户侧接口齐备: `Exchange` trait 已含 `get_open_orders` / `get_position` / `get_balance` / `subscribe_user_events`;
> ④ demo 链路已实测: 现货/合约挂单查询闭环 + 拒单如实上报 (specs/testnet.md, 2026-09-12);
> ⑤ 实例台账 `mode` 字段与 `live` → "实盘" 显示映射已在 008 备好 (无需新数据通道);
> ⑥ 已知硬约束: 币安对签名请求**超前 >1000ms 硬拒**(specs/testnet.md §注意事项); 下单须按 `tickSize`/`stepSize` 对齐而**产品侧无对齐逻辑**; 008 收敛遗留的撤单兜底 / `stop --close-all` / 持仓快照三项以本变更为落点;
> ⑦ 逐仓钱包语义: 回测模型"逐仓、按侧独立"与引擎"按对共享钱包"不一致 (specs/backtest.md §十一) —— 实盘以交易所真实值为事实源可绕开该模型差, **模型校准不在本变更范围**;
> ⑧ 顺带发现的既有缺陷 **F1**: 合约客户端下单时硬编码 `clientOrderId = locus-f-{timestamp}` (`crates/locus_binance/src/futures_client.rs:203`), **丢弃了调用方传入的 `client_order_id`** (现货走的是传入值, `client.rs:130`) → 合约单当前无法按归属识别、也失去幂等键; 本变更的归属判定必须同时修此缺陷。(已修, 见 tasks 实施记录)
> ⑨ **实施期实测发现 (2026-09-13): 现货用户数据流的 legacy listenKey 已被币安下线** —— `POST /api/v3/userDataStream` 在主网与 demo 均返回 **410 Gone** (币安 2026-02-20 07:00 UTC 永久下线该端点及 WS-API `userDataStream.start/ping/stop`); 现货用户流只能走 **WebSocket API** `userDataStream.subscribe.signature` (demo `wss://demo-ws-api.binance.com/ws-api/v3`, HMAC key 即可)。合约 `POST /fapi/v1/listenKey` **仍可用** (实测 200)。→ 本变更的成交来源改用前者 (接口契约 `Exchange::subscribe_user_events` 不变), 详见 plan D4/R1 与 tasks 实施记录。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 部署策略真正跑实盘 (优先级: P1)

用户把一个已在回测与 Dry Run 中验证过的部署策略标记为实盘, 经显式确认后启动; 引擎以真实账户 (余额/持仓/挂单取自交易所) 初始化上下文, 行情驱动同一份 Lua 策略下发**真实订单**, 交易所回执与真实成交回写策略 (`on_fill`) 并按 `strategy_id` 落库; 停机后用户可在 `fills` 中看到真实成交。

**优先级理由**: P4 dogfood 的唯一入口; 没有它 `live_enabled` 是空承诺 (见 specs/architecture.md §十一 B)。

**独立测试**: demo 测试网 (现货、合约各自独立跑, 跑前按 specs/testnet.md 对齐时钟) 用最小实例跑真实下单闭环 (#[ignore] 需密钥); 断言交易所回执 orderId 非空、成交回写策略、落库笔数与交易所一致。

**验收场景**:

1. **给定** 已 Dry Run 验证的策略且声明实盘, **当** 用户按门禁显式确认后启动, **则** 引擎进入实盘路径, 上下文中的余额/持仓/挂单为**交易所真实值**(非虚拟资金、非本地推算)
2. **给定** 实盘运行中, **当** 策略下单被交易所接受并成交, **则** 真实成交回写 `on_fill` 并落库, `locus fills <name>` 可查
3. **给定** 实盘运行中, **当** 下单被交易所拒绝, **则** 原因如实上报(含交易所原始信息)、计入失败计数, 进程不静默吞掉
4. **给定** 实盘运行中, **当** 触发 004 风控拒单, **则** 与回测/Dry Run 同语义(Rejected ack + 计数 + `target=risk` 日志), 且**不向交易所发出请求**

---

### 用户故事 2 - 停机不留残单与裸仓 (优先级: P1)

实盘停机 (用户 stop / Ctrl-C / 管理器退出导致的管道 EOF) 时, 引擎撤销**本实例可识别归属**的挂单, 核对交易所实际状态并如实上报残留挂单与持仓; 用户显式要求时可一并市价平仓。

**优先级理由**: 实盘停机留残单或裸仓是直接资损面; 也是 008 收敛遗留的指定落点。

**独立测试**: demo 真实挂单后停机, 断言交易所侧该策略归属挂单归零 + 输出残留核对; `--close-all` 分支断言持仓归零。

**验收场景**:

1. **给定** 实盘运行中且有本实例挂单, **当** 停机信号到达, **则** 引擎撤销本实例挂单, 交易所查询证实无残留
2. **给定** 停机清理完成, **当** 交易所仍有非本实例归属的挂单或持仓, **则** 如实打印残留清单与手工处置提示 (不静默, 不谎报"已清净")
3. **给定** 用户显式使用平仓开关, **当** 停机, **则** 先撤单再平掉本策略交易对的持仓, 并如实报告成交与仓位变化
4. **给定** 未使用平仓开关, **当** 停机后仍有持仓, **则** 持仓保留(不擅自平仓)且如实提示
5. **给定** 进程被强杀后重启, **当** 上一次会话留下残留挂单, **则** 新会话能识别该归属并处置(或如实上报), 不把残留当"别人的单"忽略

---

### 用户故事 3 - 实盘可见且不可被静默开启 (优先级: P2)

用户能一眼确认"这个实例现在是不是实盘", 并看到账户真实持仓/挂单/余额; 实盘不会因为一个配置字段而被无意开启。

**优先级理由**: 实盘最怕"以为在跑模拟"; 同时补齐 008 遗留的 `info` 持仓快照。

**独立测试**: `info` 对实盘实例输出真实账户快照; 未经门禁的实盘启动被拒。

**验收场景**:

1. **给定** 存在已声明实盘的部署, **当** 未通过门禁即启动, **则** 拒绝进入实盘并给出如何确认的提示 (门禁形态见 §口径拍板 1)
2. **给定** 实盘实例运行中或已停止, **当** 用户执行 `info <name>`, **则** 显示模式=实盘 + 交易所真实持仓/挂单/余额快照
3. **给定** 账户接口查询失败, **当** 输出 `info`/停机核对, **则** 如实标注查询失败, 不以陈旧值或本地推算冒充
4. **给定** 实盘实例, **当** 查看 `list`/`status`/`info`, **则** 三处模式标记一致 (复用 008 台账 `mode` 字段)

### 边界情况

- **时钟预检**: 实盘启动前与交易所时间比对, 超出容差即拒绝启动并给出可执行的对齐步骤(现货/合约分别对齐各自 demo 时间, 见 specs/testnet.md §注意事项); 该环境下"超前"是硬拒方向、"滞后"有 5s recvWindow 容差
- **下单参数对齐**: 价格/数量不满足 `tickSize`/`stepSize`(及最小名义值)时的处置口径见 §口径拍板 3
- **归属判定**: 挂单只有能证明属于本实例才撤; 无法证明 → 不撤, 如实上报(宁可留残单也不误撤用户手工单)
- **已有持仓启动**: 启动时上下文含真实持仓, 策略不得假定从空仓开始(脚本需能处理非零初始仓)
- **部分成交**: 停机兜底必须覆盖"部分成交后剩余挂单"与"已成交部分的成交回写"
- **重复停机**: 多个停机信号只执行一次清理(幂等)
- **用户事件流断线**: 断线后"收不到成交"不得静默继续(会误判仓位); 必须如实停机或恢复, 具体策略在 plan 阶段定
- **交易所拒单/限频**: 明确区分"策略逻辑错"与"交易所拒绝", 后者如实记录并继续运行(不静默重试风暴)
- **不做(范围外, 明确)**: 回测钱包模型逐仓校准 (specs/backtest.md §十一 遗留)、出站通知(003)、AI 策略入口(002)、主网实盘 dogfood 由用户自行执行

## 功能需求 *(必填)*

### 功能需求

- **FR-001**: 系统必须提供实盘运行路径, 使声明实盘的部署策略经显式确认后以真实下单链路运行; 策略本体与回测/Dry Run 用**同一份 Lua 脚本**, 不新增 Rust 策略本体
- **FR-002**: 实盘启动前必须以交易所账户为**唯一事实源**初始化上下文(真实余额/持仓/挂单), 不得以虚拟资金或本地推算值替代
- **FR-003**: 实盘成交必须来自交易所真实回执/用户事件流, 不得由本地虚拟撮合产生
- **FR-004**: 实盘持仓查询必须支持按方向的定向查询(合约 hedge LONG/SHORT), 与回测 `pos_size`/`pos_entry` 语义一致(现 `LiveContext` 用默认实现返回 None)
- **FR-005**: 停机必须撤销**本实例可识别归属**的挂单; 无法证明归属的挂单不得擅自撤销
- **FR-006**: 停机必须如实上报残留挂单/持仓与手工处置提示, 不得静默或谎报清净
- **FR-007**: 用户显式请求平仓时, 停机必须撤单后平掉本策略交易对持仓, 并如实报告成交与仓位变化
- **FR-008**: 系统必须在实盘启动前做时钟预检, 超出交易所容差即拒绝启动并给出可执行的对齐步骤
- **FR-009**: 实盘路径必须复用 004 的 RiskEngine 前置检查(同一装配函数), 不重复实现风控
- **FR-010**: 实盘下单参数必须由引擎按交易所过滤器(`tick_size`/`step_size`/最小名义值)**自动对齐**; 对齐掉的量/价必须可观测(日志含原值→对齐值), 不足最小值即拒单并如实报错(见 §口径拍板 3)
- **FR-011**: `info` 必须显示实盘实例的真实持仓/挂单/余额快照; 查询失败如实标注
- **FR-012**: 实盘实例必须在实例台账 `mode` 中标记为实盘(复用 008 已有字段), `list`/`status`/`info` 显示一致
- **FR-013**: 实盘启动必须有显式确认门禁: 配置声明实盘 **且** 命令行动作显式要求实盘(双条件), 缺一即按 Dry Run 运行且输出说明原因, 不得因配置字段被动开启(见 §口径拍板 1)
- **FR-014**: 实盘运行的策略必须能区分"实盘 / 模拟"语境 —— 具体通道在 plan 阶段定, **优先复用已有 config/ctx 通道, 不新造数据通道**
  > 落地 (D10): 复用 `ctx:config_bool("<key>")` + TOML `params`(零改动, 引擎不注入任何额外字段); 说明见 `specs/lua-api.md` §一 on_stop 段
- **FR-015**: 实盘覆盖市场 = **现货首批**(交付与验收路径); 合约(USDT-M)实盘需先补 `FuturesClient → Exchange` 适配层(fapi WS 盘口/用户流, 当前不存在), 列为同变更 Phase 2, 是否并入 011 由复核拍板(见 §口径拍板 2)
- **FR-016**: 实盘运行中的错误必须区分"如实上报并继续"与"异常停机"两类, 并给出非零退出码供管理器识别(与 008 既有口径一致)

### 关键实体 *(涉及数据时填写)*

- **实盘实例**: 部署策略 + 真实账户会话(余额/持仓/挂单均为交易所值); 与 Dry Run 实例的区别仅在下单/账户事实源
- **订单归属标识**: 区分"本实例下单"与外部挂单的**天然键**(订单号前缀或等价物, 不新造表/列)
- **停机核对结果**: 撤单结果 + 残留挂单/持仓清单 + 手工处置提示 + 平仓开关下的仓位变化

## 口径拍板 (2026-09-13; 4 项取默认, 复核时可推翻)

> 本轮确认表单用户未作答(超时), 以下按"最简 + 有代码依据"取默认值, 每项附依据与推翻成本。

- **拍板 1 实盘门禁 = 配置声明实盘 且 命令行显式开关(双条件)**
  依据: product.md §十 "Dry Run 默认, 确认后切实盘"; 仅凭 TOML 字段即上真金与"用户明确要上实盘"不符; `approve` 一次性 token 通道当前**无 CLI 入口**(architecture.md §七), 复用它等于先做 002 的入口 → 超出本变更范围。
  形态: TOML `live_enabled = true` **且** `locus run|start <name> --live`; 缺 `--live` 时按 Dry Run 运行并**显式打印原因**(不静默降级)。
  推翻成本: 低(门禁判定是一处函数)。

- **拍板 2 市场范围 = 现货首批闭环; 合约实盘后置(Phase 2, 是否并入 011 待复核)**
  > 实况 (2026-09-13 实测): 合约 `POST /fapi/v1/listenKey` **仍 200 OK**(listenKey 机制未下线) → 合约 Phase 2 的成交来源不受影响; 反而**现货**的 legacy listenKey 先被下线(见起点事实 ⑨), 现货改走 WebSocket API 订阅后已交付。
  依据(本轮复核推翻"两市场同批"的原判断): `Exchange` trait 的**唯一实现是现货**(`crates/locus_binance/src/spot.rs:99`), 合约仅有 `FuturesClient`(裸 REST, 未实现 `Exchange`); 合约 WS 盘口/用户流未实现 → 合约实盘需**新建适配层**(含 fapi WS), 属新子系统而非接线; 成交回写依赖的用户事件流现货已有(`subscribe_user_events`), 合约无。
  推翻成本: 中(把 Phase 2 拆为 012 即可, 现货交付不受影响)。

- **拍板 3 参数对齐 = 引擎侧自动对齐**
  依据: 属"放开现有接口即可解决"—— `Market` 已有 `tick_size`/`step_size`(`crates/locus_core/src/types.rs:19/22`), 现货/合约 exchangeInfo 解析已落地, 且已有 `validate_quantity`(min_qty + stepSize 整数倍校验, `crates/locus_binance/src/client.rs:408`); 零新机制。
  取整方向: 数量按 `step_size` **向下**取整(不超预算); 价格按 `tick_size` 取到**不劣于原始意图**的一侧(买单向下、卖单向上), 偏差至多 1 tick; 对齐后不足 `min_qty` 或 `min_notional` → **拒单**并如实报错(带交易所数值)。发生对齐时 `warn` 日志含原值与对齐值。
  > 已补 (T001, 2026-09-13): `Market.min_notional` + 现货 `NOTIONAL`/`MIN_NOTIONAL` 与合约 `MIN_NOTIONAL` 解析; **真实数据核对**: demo 现货 ETHUSDT `minNotional = 5.00000000`(合约过滤器字段名为 `notional`, 实测 ≈ 50 USDT)。
  推翻成本: 低(备选口径 = "引擎不干预, 原样提交由交易所拒")。

- **拍板 4 归属判定 = 订单号带策略名前缀, 兜底只撤本策略单**
  依据: 天然键已存在(`OrderRequest.client_order_id` 由调用方给、交易所回传 `OrderInfo.client_order_id`), 不新造表/新文件; 且顺带修 **F1**(合约客户端丢弃传入 id, `crates/locus_binance/src/futures_client.rs:203`)并让 `info`/`fills`/停机兜底可归因。无法证明归属的挂单一律不撤, 只如实上报(宁可留残单也不误撤手工单)。
  推翻成本: 低。

## 假设
