**功能目录**: `specs/changes/032-web-ui-console`

**创建日期**: 2026-09-26

**状态**: 草稿

**输入**: 用户描述: "Web UI 左侧增加按钮,点击后可以配置:币安 api key、demo key(可选)、ai key;显示所有现货和合约(默认 false);过滤功能,默认只显示 bstock 相关的现货和合约,可以修改配置显示所有;策略管理:从内置策略复制、新建空白策略、用 AI 修改策略、调整回测标的/参数、回测、dryrun;运行策略:内置和用户策略都可运行,指定标的、调整参数、查看运行情况/收益/日志、停止策略;浏览现货和合约列表,查看某个现货或合约,K 线方便就加。" 参考实现: `tmp/Vibe-Trading`。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 在页面上配置全部密钥 (优先级: P1)

小张第一次使用 ricow,不想在终端向导里粘贴密钥。他打开 Web UI,点左侧"设置",在页面上分别填入币安主网 key/secret、测试网 demo key/secret(可留空)、AI 服务商 key,保存后刷新页面,每个密钥只显示"已配置 + 尾 4 位"提示,不回显全文。配好后对话、策略运行等功能立即可用,无需重启服务。

**优先级理由**: 其余全部功能(AI 改策略、demo 启停、行情私有接口)都依赖密钥;没有设置页,新用户连第一步都跨不过去。

**独立测试**: 启动 Web UI → 设置页填三个密钥并保存 → 检查本地配置文件被正确写入且文件权限仅本机可读 → 刷新页面只见脱敏提示 → 用配置好的 AI key 在对话里发问成功。

**验收场景**:

1. **给定** 未配置任何密钥的全新数据目录, **当** 用户在设置页填入币安 key/secret 与 AI key 并保存, **则** 保存成功提示出现, 本地配置文件对应字段更新, 对话渠道的密钥检测不再报缺失
2. **给定** 已配置密钥, **当** 用户重新打开设置页, **则** 每个密钥字段只显示"已配置 · 尾号 xxxx", 页面任何位置(含浏览器本地存储)都不存在密钥全文
3. **给定** demo 凭据留空, **当** 用户保存, **则** 其余密钥保存成功, 系统明确提示 demo 未配置(仅影响测试网启动)
4. **给定** 错误或过期的 token 访问密钥读写接口, **则** 一律 401, 响应体不含任何密钥信息

### 用户故事 2 - 浏览现货/合约并查看 K 线详情 (优先级: P1)

小张想找可交易的 bStock 标的。他点左侧"市场",默认看到过滤后的列表(只有 bStock 现货与美股永续),上方有"显示全部"开关;打开后显示交易所全部在售现货与合约,还能按代码搜索。点进某个标的,能看到实时订单簿与 K 线图(可切周期),用于判断走势。

**优先级理由**: 选标的是回测与运行策略的前置动作;没有列表与 K 线,用户只能凭记忆敲交易对。

**独立测试**: 打开市场页 → 默认列表与命令行交易对命令的过滤结果一致 → 切换"显示全部"后数量明显增多且选择被持久化 → 点开 BTCUSDT 看到订单簿买卖盘与蜡烛图 → 换周期后图表刷新。

**验收场景**:

1. **给定** 默认配置(过滤开启), **当** 用户打开市场页, **则** 列表只含 bStock 现货与美股永续, 页面明确标注当前为"过滤视野"及标的总数
2. **给定** 过滤视野, **当** 用户打开"显示全部"开关, **则** 列表立即展示全部在售现货与合约, 且该选择持久化(重启 Web 与终端命令都读到同一视野配置)
3. **给定** 市场列表, **当** 用户在搜索框输入代码片段, **则** 现货与合约两组列表同步按代码过滤
4. **给定** 任一标的详情页, **当** 页面加载, **则** 展示实时订单簿买卖盘与最近 K 线蜡烛图(默认 1h);切换周期(如 15m/4h/1d)后图表加载对应数据
5. **给定** 网络异常或交易所接口暂时失败, **当** 拉取行情失败, **则** 页面给出可读错误与重试入口, 不白屏

### 用户故事 3 - 管理策略:复制、新建、编辑、AI 改写、回测 (优先级: P1)

小张在内置网格策略基础上想做自己的版本。他在"策略"页看到内置策略与用户策略分组列表;点"复制"后起个新名,进入编辑器看到清单参数表单与 Lua 代码;他手改几行,又点"AI 修改",用一句中文指令(如"把网格间距改成 ATR 的三倍")让 AI 重写代码,AI 返回后他逐行看过、点保存才落盘。改参数、换回测标的与周期后点"回测",页面展示回测报告,满意后保存策略。他也可以从空白模板新建一个策略。

**优先级理由**: 策略生产闭环(产生→验证→保存)是平台核心价值;当前 Web 只能只读看清单。

**独立测试**: 复制内置策略 → 改名落盘成功且磁盘出现新策略文件 → 故意写语法错误保存被拒并看到编译错误 → 用 AI 指令改写 → 校验通过后保存 → 发起 90 天回测看到完整报告。

**验收场景**:

1. **给定** 内置策略列表, **当** 用户点"复制为新策略"并输入合法新名, **则** 新策略以用户策略身份落盘(代码+清单), 列表中立即出现;输入与内置标识重名或与既有策略互为前缀的名字时被拒绝并说明原因
2. **给定** 策略编辑器, **当** 用户保存含编译错误的 Lua, **则** 保存被拒绝并返回编译错误信息(含定位), 文件不被破坏
3. **给定** 已配置 AI key, **当** 用户输入修改指令并点"AI 修改", **则** 页面在原代码基础上返回改写后的完整代码并先经编译校验;**AI 返回的代码不自动落盘**, 必须用户点保存;AI key 未配置时引导去设置页
4. **给定** 编辑器中的参数表单与标的选择, **当** 用户调整参数/标的/周期/天数并发起回测, **则** 页面显示任务进行态, 完成后展示与命令行回测同一口径的指标报告;回测期间可离开页面再返回查看结果
5. **给定** 一个正在运行的策略, **当** 用户尝试编辑保存, **则** 系统拒绝并提示先停止策略

### 用户故事 4 - 运行与监控策略(含实盘门禁) (优先级: P1)

小张要把策略跑起来。在"运行"页选择任一内置或用户策略,指定标的与参数后启动:可先选 Dry Run(本地模拟),再选 demo(币安测试网真实下单);运行中能看到模式、运行时长、收益、成交与实时日志;点停止可停机。验证充分后他要切实盘:页面先展示风险披露全文,他逐字输入确认短语完成首次风险确认,每次实盘启动还要再逐字输入 `确认实盘 <策略名>`,输错即拒绝。

**优先级理由**: 运行监控是策略闭环最后一环;实盘资金安全要求门禁不低于终端。

**独立测试**: Dry Run 启动 → 状态/日志可见 → 停止;demo 启动后日志中确有测试网真实请求与成交、收益数字更新;实盘启动在未输入/错输短语时被拒绝,首次实盘须先过风险披露确认。

**验收场景**:

1. **给定** 任一已部署策略, **当** 用户选择 Dry Run 模式、指定标的与参数并在确认对话框确认启动, **则** 策略被托管启动, 运行页显示运行状态、模式、运行时长, 日志实时滚动
2. **给定** 已配置 demo 凭据, **当** 用户以 demo 模式启动, **则** 子进程真实调用币安测试网(日志含测试网域名), 产生的成交与收益在页面可见;demo 凭据缺失时启动被拒并提示去设置页
3. **给定** 运行中的策略, **当** 用户点停止(可选平仓位), **则** 策略按既有停机流程退出, 状态更新为已停止
4. **给定** 用户首次使用实盘, **当** 选择 live 模式启动, **则** 必须先阅读风险披露并逐字输入指定短语完成一次性风险确认;此后每次 live 启动还须逐字输入 `确认实盘 <策略名>`, 任一短语不匹配则拒绝启动且不留确认记录
5. **给定** 后台托管进程未运行, **当** 用户从页面启动策略, **则** 系统自动完成托管进程拉起再启动策略, 无需用户去终端执行命令;拉起失败时页面给出明确原因

### 用户故事 5 - 在新导航结构中保留对话工作流 (优先级: P2)

改版后,老用户熟悉的对话式工作流(会话列表、流式问答、斜杠命令、对话渠道写操作口语词确认、右侧只读面板)完整保留为"对话"视图,与新增的设置/市场/策略/运行视图通过左侧导航切换,刷新页面后仍停留在原视图。

**优先级理由**: 不破坏既有能力(零回归),新视图与对话并存;但相对新功能它是保留项,故 P2。

**独立测试**: 切到对话视图 → 新建会话、流式问答、斜杠命令、面板数据全部与改版前一致;在各视图间来回切换不报错,刷新后回到刷新前视图。

**验收场景**:

1. **给定** 改版后的 Web UI, **当** 用户进入对话视图, **则** 会话列表/对话流/输入区/策略·交易·日志面板行为与改版前一致, 对话渠道写操作确认仍为单个口语词
2. **给定** 任一非对话视图, **当** 用户刷新页面, **则** 仍回到刷新前所在视图

### 边界情况

- 配置文件被外部程序改坏/加锁时保存密钥怎么办? → 保存失败并返回可读错误, 不覆盖坏文件, 提示用户检查文件。
- AI 修改请求超时或模型返回被截断的代码怎么办? → 返回明确超时/截断提示, 编辑器保留用户原代码不被替换。
- 回测任务耗时长(数十秒拉数据)怎么办? → 异步任务 + 进度轮询;同一时刻只允许一个回测任务, 重复发起直接拒绝。
- 策略保存时磁盘空间不足/路径无权限怎么办? → 返回写入错误, 旧文件保持可用。
- 行情列表交易所接口失败怎么办? → 展示上次成功缓存(若有)并标注时间, 同时给重试入口。
- 用户在两个浏览器标签页同时操作同一策略(一个启动一个编辑)怎么办? → 保存时以运行台账为准拒绝覆盖(409), 启动以"已在运行则拒绝"为准。
- 停止一个实际已崩溃的策略怎么办? → 如实返回台账与进程状态(沿用既有三态呈现), 不假装停止成功。

## 功能需求 *(必填)*

### 导航与整体框架(F0)

- **FR-001**: Web UI 左侧必须提供五个导航入口: 对话、市场、策略、运行、设置;点击切换视图,当前视图高亮
- **FR-002**: 当前视图必须可被 URL 表达并在刷新后恢复;各视图切换不得导致对话会话中断
- **FR-003**: 对话视图的既有能力(会话管理、流式回复、斜杠命令、三个只读面板、中英双语切换)必须零回归
- **FR-004**: 全部新增页面与接口继续只绑回环地址、沿用既有一次性 token 门禁;任何无 token/错 token 请求一律 401 且不泄露数据
- **FR-005**: 新增前端资源继续保持"无外部 CDN、无构建期网络依赖、随程序分发离线可用";第三方图表代码以本地文件形式随程序打包

### 密钥配置(F1)

- **FR-006**: 设置页必须能配置三组凭据: 币安主网 key/secret、币安测试网 demo key/secret(可选)、AI 服务商 key(含服务商/模型/接口地址等既有配置项)
- **FR-007**: 密钥读取接口只能返回"是否已配置 + 脱敏尾号提示",任何接口响应不得返回密钥全文
- **FR-008**: 页面脚本不得把密钥写入浏览器本地存储/会话存储;保存后密钥只存在于本机配置文件(权限仅当前用户可读)
- **FR-009**: 设置页保存的密钥必须与终端向导/对话渠道写入同一份本机配置,改后全局立即生效(对话、回测、策略运行)

### 市场浏览(F2)

- **FR-010**: 市场页必须分组展示现货与合约交易对,默认只显示 bStock 类标的(bStock 现货 + 美股永续),并标注当前视野与数量
- **FR-011**: 用户必须能一键切换"显示全部",该选择持久化到既有视野配置,终端与 Web 读到同一结果
- **FR-012**: 市场列表必须支持按代码片段搜索过滤(现货/合约两组同步)
- **FR-013**: 交易对详情页必须展示实时订单簿;K 线图至少支持常用周期切换(15m/1h/4h/1d),以蜡烛图呈现
- **FR-014**: 行情数据失败时必须有明确错误态与重试,不得白屏或显示伪造数据

### 策略管理(F3)

- **FR-015**: 策略页必须以统一目录展示内置示例与用户策略,按市场(现货/合约)与来源分组
- **FR-016**: 用户必须能把任一内置策略复制为自己的新策略,也能从空白模板新建;新名字必须通过既有的命名规范与前缀冲突校验,且不得占用内置保留标识
- **FR-017**: 用户必须能在页面编辑策略代码与清单参数;保存时必须过编译门禁,编译失败不得落盘并返回可定位的错误
- **FR-018**: 用户必须能用一句自然语言指令让 AI 在现有代码基础上改写策略;AI 产物必须先经编译校验再呈现给用户,且**只有用户显式保存才落盘**
- **FR-019**: 用户必须能在页面选择标的、周期、天数与参数覆盖值发起回测,并看到与命令行同一口径的回测指标报告;回测异步执行、可稍后查看结果、同时限一个任务
- **FR-020**: 正在运行的策略禁止保存覆盖,拒绝时明确提示先停止

### 策略运行(F4)

- **FR-021**: 用户必须能从运行页启动内置或用户策略,启动前可指定标的与参数;支持 Dry Run、demo(测试网)、live(实盘)三种模式
- **FR-022**: Dry Run/demo 的启动必须经页面显式确认动作;demo 模式必须真实调用币安测试网,凭据缺失时拒绝
- **FR-023**: live 模式必须保持与终端同强度的双道门禁: 首次风险披露逐字短语确认(一次性) + 每次启动逐字输入 `确认实盘 <策略名>`;短语不匹配必须拒绝且不写入确认记录;未声明允许实盘的策略不得以 live 启动
- **FR-024**: 页面启动策略时若后台托管进程未运行,系统必须自动拉起托管再启动;终端渠道的启动行为与输出零变化
- **FR-025**: 运行页必须展示每个策略实例的: 运行状态、模式、运行时长、标的、收益数据(净收益/手续费/成交笔数口径与既有面板一致)、实时日志;并能停止(可选平仓位)
- **FR-026**: 状态呈现必须如实区分"确实在跑/已停/托管未运行状态不可知/读取失败",不得伪造

### 既有规格修订(F5,治理性需求)

- **FR-027**: **修订 025 FR-016 / FR-027**: Web 渠道新增"页面直控写操作"能力(保存策略、启停 Dry Run/demo、保存密钥),其确认为页面显式交互(确认对话框/表单提交),不再强制绕道对话流;对话渠道确认(单个口语词)与终端渠道确认(逐字短语)规则均不变
- **FR-028**: **修订部署链在 Web 渠道的形态**: 用户亲手新建/编辑的策略保存时保留编译门禁,免去沙箱回测+preview+approve 前置链(用户本人即作者与确认者);AI 改写产物仍须用户显式保存;终端与对话渠道的部署链一行不改
- **FR-029**: 以上修订必须同步登记到项目宪法"安全要求"章(确认渠道由 2 个增至 3 个)与架构文档 Web 章节;本变更收敛时复核相关 living spec 与测试基线

### 关键实体 *(涉及数据时填写)*

- **凭据配置**: 币安主网 key/secret、测试网 key/secret、AI 服务商配置;存于本机唯一配置文件,页面只呈现脱敏状态
- **交易对视野**: 现货/合约两组交易对 + 是否过滤(bStock)的视野开关;过滤规则与终端共用同一份实现与配置
- **策略目录条目**: 清单(中文名/市场/说明/参数 schema)+ Lua 源码 + 来源(内置/用户);内置标识为保留名
- **策略实例**: 一个已部署策略的一次运行:名称、模式(dry_run/demo/live)、状态、标的、参数、运行时长、收益快照、日志
- **回测任务**: 一次异步回测:标的、周期、天数、参数覆盖、状态(运行/完成/失败)、报告文本

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 新用户不碰终端,仅通过 Web UI 在 5 分钟内完成三类密钥配置并成功发出一次 AI 对话
- **SC-002**: 用户在市场页 3 次点击以内(导航→市场→标的)看到任一标的的 K 线图;默认视野标的数与命令行过滤结果 100% 一致
- **SC-003**: 用户从复制内置策略到看到回测报告全程不离开浏览器,常规参数回测在发起后 60 秒内呈现完整报告
- **SC-004**: 100% 的 live 启动尝试都经过双道逐字短语门禁;错输/空输短语的启动被拒率 100%,且无确认记录残留
- **SC-005**: demo 模式完整生命周期(启动→真实测试网成交→查看收益→停止)全部在页面完成,日志中测试网域名请求可核对
- **SC-006**: 改版后既有对话视图与终端命令行为零回归:现有自动化测试全部通过
- **SC-007**: 任何接口响应与浏览器存储中检出密钥全文的次数为 0(由自动化扫描测试保障)

## 假设

- 用户在本机自用,Web 服务只绑回环地址,不做多用户/权限体系;一次性 token 仍是唯一访问凭证
- 行情浏览复用既有免 key 公开接口与既有交易对缓存,不新增数据源
- K 线首期只做只读历史展示与周期切换,不做画线/指标叠加/实时 tick 推送(留待后续)
- 策略编辑器首期用纯文本编辑区,不引入代码编辑器组件与前端构建链
- AI 改写沿用用户已配置的 AI 服务商与计费,平台不内置模型
- 实盘风险披露文本与三判据(风险确认、Dry Run 时长、时钟预检)完全沿用既有实现,本变更不放宽任何实盘条件
