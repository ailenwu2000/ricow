## 4. 本轮踩到的坑（有长期价值）

### 4.1 `R.router` 从未导出 —— 探针三条导航**从来没生效**

探针里写的是 `window.Ricow.router && (location.hash = '#runs')`。`router.js` 只导出 `navigate / parseHash / refreshTitle`，**没有 `router`** → 表达式恒短路，hash 从未被赋值。

而 058 段的断言只读 DOM 常驻元素（视图切换只是显隐），于是「切到运行视图」是**假绿**：一直停在上一段的策略详情页。改走真导出 `R.navigate` 后才真的切过去 —— 随即暴露出下面 4.2 的一串问题。

**教训**：`a && (副作用)` 这种写法一旦 `a` 为假就静默变成「什么都没做」，而读 DOM 的断言看不出来。

### 4.2 守卫挂在 `hashchange` 上 = 永远不触发的死代码

UX-16 第一版在 `strategies.js` 里 `window.addEventListener("hashchange", guard)`。但同一个 window 上的多个监听按**注册顺序**跑，而 `router.js` 排在所有视图脚本之前加载（`assets.rs` 的加载顺序契约）→ router 的监听先跑 → 已经把策略视图 `deactivate`（顺手 `closeAll()` 了弹窗）→ 轮到守卫时 `viewActive === false` → 直接 return。

静态门（fmt / clippy / 单测 / 前端扫描）**四道全绿**，只有 CDP 真点一次才现形。

**修法**：改由 router 在**切走之前**回调（`R.setLeaveGuard`），顺序由最早注册的这一方保证。守卫返回 `false` 即"先别切"；同时用 `history.replaceState` 把地址栏拨回详情页，避免"地址写着市场、画面停在策略"的错位（Esc 关窗也不会错位）。

### 4.3 `R.modal.open` 不先清场 → `#modal-root` 里摞了 3 层 dialog

被拦两次 + kill 弹窗一次 = 三层遮罩互相盖住，`querySelector` 取到的是上一层弹窗的控件 —— 于是「输入正确短语后按钮放行」「勾选平仓后输入框清空」这类断言全部失真。

**修法**：`open()` 开头先 `closeAll()`；`closeAll()` 从 `innerHTML = ""` 改成**逐个走 `close()`**（前者只摘 DOM，弹窗自己挂在 document 上的 keydown 监听会留着，关得越多漏得越多）。

### 4.4 探针自己留下的脏状态，把后续段全拦住了

053 段最后为验英文文案把 `spacing_pct` 改成 `0.07`，**之后没还原** → 页面停在脏状态 → 加了 UX-16 之后，054 / 058 的每次跳转都被守卫拦下（表象是 054 的详情页断言读到副本的摘要）。

**修法**：在 053 段收尾补一次「一键还原」，并加一条断言把"后续段的前提（没改动）"钉住；而"脏了会被拦"由 059 段**自己造脏**去验。

### 4.5 按钮文案看错一个字，断言就成了空跑

按 `textContent.indexOf("留下")` 找主位按钮，实际文案是「留在**这里**(去保存)」→ `find` 返回 `undefined` → 什么都没点上，弹窗当然没关。

**修法**：改成匹配「留在这里」，并补一条断言先确认**按钮找得到**（`stayClick === "ok"`），否则"点了没反应"和"没点上"长得一模一样。

### 4.6 `localStorage` 字面量写进注释也算命中

`palette.js` 里注释写了"不落 `localStorage`/`sessionStorage`"，被 `assets.rs` 的三条扫描断言（它们扫 `all_js()` 的内嵌副本，**注释也算**）判红 —— 3 条单测失败，同一根因。改成"不落浏览器存储"。

### 4.7 探针按 `#rn-modal-root` 定位，而该容器已按设计移除

UX-09 把弹窗挂载点统一到首页的 `#modal-root`（`plan.md` §A 明确"优先统一"），原先 runs 视图自带的 `rn-modal-root` 从骨架移除 → 058 段 7 条断言红。弹窗本身是好的（同段的 `.rn-kill-warn` / `.rn-kill-keep-daemon` 两条都 PASS）。改探针挂载点并注明原因。

## 8. 第三轮：全测试体系假绿排查（2026-10-18 补记）

用户要求"进一步深入检查**其他所有**的测试检查有无假绿"。范围不再是 059 那 38 条断言，
而是四层全部：CDP 走查 131 条 / `e2e_web.py` 297 条 / Rust 单测 1060 条 / 前端静态门 7 段 /
安全红线 5 条。

### 8.1 查出并修掉的两个真缺陷

**① 安全红线门 + 架构守卫的花括号配平漏扫（同一根因，两处各一份）**

`scripts/ci_grep_gates.sh::non_test_lines` 与
`crates/ricow_strategy/tests/architecture_guard.rs::brace_delta` 都靠"数 `{` / `}`"来跳过
`#[cfg(test)]` 块。**字符串字面量里的花括号也被数了进去**：测试块里只要有一句
`format!("{")`，深度就再也回不到 0 → 该块"永不结束" → **它后面的整段生产代码被静默吞掉**。
方向是最坏的那种：漏扫 = 假绿，而且"测试写得越多越容易失明"。

实证（临时探针文件，跑完即删）：
- 红线门：`dbg!(1)`（测试块**之前**）被抓到 ✅；`todo!()`（测试块**之后**）**漏掉** ❌
- 架构守卫：`production_lines()` 对新加的用例返回**空字符串**（整个文件被吞）

修法：数花括号前先剥掉字符串/字符字面量与行注释。修后两者都抓到了，且**原有基线全绿**
（说明之前扫到的部分没有靠这个 bug 掩盖违规）。另加 Rust 回归测试
`production_lines_survives_braces_inside_string_literals`（1060 = 1059 + 1），
同时钉住另一半："测试块本身仍然要被跳过"，免得修法做成"干脆不跳了"。

**② 前端门 A 段"红线旁边照样打勾"**

```js
for (...) { try { new vm.Script(...) } catch { fail(...) } }
pass(`${n} 份 .js 语法可编译`);   // ← 无条件
```
退出码是对的（`failed > 0` 就不绿），但日志会同时出现「[红线] xxx.js 语法错误」和
「[ok] 16 份 .js 语法可编译」—— 读日志的人会以为语法都过了。改为只在 0 错误时打这句。
实证：注入一个语法错误的临时 `.js` → 只报红线、不再出现"全部可编译"；删掉后恢复全绿。
