## 1. 走查方法

本次走查采用「代码审阅 + 真机截图」双轨：

1. **代码审阅**：通读 `crates/ricow/src/web/assets/` 下的 `index.html`、`router.js`、`app.js`、`common.js` 及五个视图文件（`chat.js`、`markets.js`、`strategies.js`、`runs.js`、`keys.js`、`settings.js`）的关键结构。
2. **真机截图**：本地启动 `ricow web`，用 headless Edge CDP 在 `1440×900` 下对六视图（对话/市场/策略/运行/密钥/设置）及命令面板、帮助抽屉、策略详情页进行截图与 DOM 指标采集。

走查时使用的数据根未配置 AI 密钥、未配置币安凭据、未保存任何策略实例，**覆盖的是典型新用户首次打开产品的冷启动场景**。大多数改进项都围绕这一场景展开。

## 2. 总体结论

当前 Web UI 在功能完整性和安全约束上已经相当成熟，但在**信息架构、状态反馈、可访问性、空状态处理**四个维度仍有明显改进空间。以下需求按优先级分组，每项均给出问题、用户影响、建议方案和验收标准。

## 3. 改进需求清单

### 3.1 全局导航与信息架构

#### UX-01：顶栏标题应随视图变化（P1）

- **问题**：顶栏 `#session-title` 在「市场/策略/运行/密钥/设置」视图下仍显示「新会话」或当前会话名，无法告诉用户当前在哪。
- **用户影响**：切到非对话视图时，用户失去位置感；窄屏下侧栏收起后尤其明显。
- **建议**：
  - 对话视图：保留显示当前会话名。
  - 其他视图：显示视图名称，如「市场 · Ricow」。
  - 策略详情等二级页：显示策略名或面包屑，如「策略 / 现货动态非对称网格」。
- **验收**：CDP 真机截图中，每个视图的顶栏标题与当前视图一致；切换视图时 `document.title` 同步更新。

#### UX-02：浏览器标签页标题应随视图变化（P1）

- **问题**：`document.title` 始终为「Ricow」。
- **用户影响**：多标签页用户无法快速定位 Ricow 标签；浏览器历史里也全是同一个标题。
- **建议**：`router.js` 在 `applyRoute` 中按视图更新 `document.title`，格式为「{视图名} · Ricow」。
- **验收**：CDP 走查断言「切换视图后 title 包含视图名」。

#### UX-03：非对话视图下侧栏会话列表应可收起或隐藏（P1）

- **问题**：左侧 `#session-list` 在所有视图都显示。会话列表是「对话」这一单一视图的概念，在市场/策略/运行/密钥/设置下占据固定宽度且语义不符。
- **用户影响**：策略/运行等需要宽屏展示表格/表单的视图被挤占空间；新用户会困惑「为什么看密钥时还要看到聊天列表」。
- **建议**：
  - 方案 A（推荐）：侧栏拆成「导航区」和「会话区」两段。非对话视图只保留导航区，会话区自动收起（宽屏下折叠为图标或隐藏）。
  - 方案 B：保持现有结构，但给会话区加独立收起钮，状态不写入浏览器存储（符合项目安全约束）。
- **验收**：在市场/策略/运行/密钥/设置视图的截图中，左侧会话列表不可见或折叠；对话视图下正常显示。

### 3.2 状态反馈与空状态

#### UX-05：市场视图加载失败应给出明确错误与重试（P1）

- **问题**：当币安 API 不可达时，市场视图只显示「加载中…」，没有超时、错误原因或重试入口。
- **用户影响**：用户无法判断是网络问题、服务未启动还是软件 bug；只能干等或刷新页面。
- **建议**：
  - 加载超过合理时间（如 10 秒）仍未返回，显示「行情源暂时不可达」及错误详情（HTTP 状态码或 fetch 错误）。
  - 提供「重试」按钮，点击后重新请求 `/api/markets`。
  - 保持现有「显示全部/过滤视野」控件可用，避免假控件。
- **验收**：模拟网络不可达（如改 hosts 或断网），市场视图在超时后显示错误提示和重试按钮；CDP 断言错误文案可见。

#### UX-06：统一空状态组件与文案（P1）

- **问题**：各视图空状态风格不一致：
  - 运行视图：表格上方有「停止全部」危险按钮，下方才有「暂无策略实例…去策略页」。
  - 策略「我的」分组：空状态是单一条横线「—」+ 底部提示。
  - 密钥：左右两栏分别显示「0 + 新增」和说明文案。
- **用户影响**：空状态没有统一心智模型，部分视图的危险操作与空状态并存造成认知负担。
- **建议**：
  - 抽象 `R.emptyState(text, cta)` 的增强版，支持图标/插图、主文案、下一步按钮。
  - 运行视图空状态时隐藏或禁用「停止全部」（没有可停止的实例）。
  - 策略「我的」分组空状态使用统一组件，文案如「还没有自己的策略。可复制一个内置模板，或新建空白策略」。
- **验收**：e2e 对每个空状态截图比对；危险操作在空状态时不应可点击。

#### UX-07：密钥页「当前生效」与「0 条密钥」状态矛盾（P2）

- **问题**：AI 通道列表显示「0」条已保存密钥，但下方显示「当前生效：deepseek · deepseek-flash · 未配置」。
- **用户影响**：新用户不理解「已保存密钥」和「当前生效通道」的区别，会以为数据错了。
- **建议**：
  - 在页头或当前生效卡片加一句说明：「当前生效通道由 ricow.toml 的 `[ai]` 段决定；左侧是保存的密钥环，点「选用这套」可把它设为生效通道。」
  - 若 `[ai]` 段只配了 provider/model 但没 key，显示「未配置密钥」而非混在列表的「0」里。
- **验收**：e2e 断言存在说明文案；状态文案不再让用户产生「0 条却有生效」的困惑。

#### UX-08：设置页内容过于单薄（P2）

- **问题**：设置页目前只有「市场视野」一个复选框 + 一个跳转到密钥页的按钮。
- **用户影响**：用户对「设置」的心智预期是集中管理偏好，但这里几乎空空如也。
- **建议**：
  - 把顶栏的「主题」和「语言」选择移入设置页（顶栏保留快捷切换，设置页提供完整选项）。
  - 增加「默认回测天数」「默认回测周期」等可持久化到 `ricow.toml` 的偏好。
  - 保留「前往密钥页」入口，但放在设置页的「账户与 API」分组里。
- **验收**：设置页至少包含 3 个可交互分组；e2e 对每个设置断言保存后生效。

### 3.3 可访问性与交互细节

#### UX-09：弹窗应补充焦点管理与 ARIA 属性（P1）

- **问题**：`strategies.js` 和 `runs.js` 各有一份 `openModal`/`modalActions` 实现。弹窗没有 `role="dialog"`、`aria-modal="true"`、焦点陷阱；Esc 监听器在按钮关闭时未移除，造成泄漏。
- **用户影响**：键盘用户和屏幕阅读器用户无法顺畅操作弹窗；Esc 监听累积可能导致异常行为。
- **建议**：
  - 将 `openModal`/`modalActions` 提取到 `common.js` 作为公共组件（消除 runs.js 与 strategies.js 的重复实现）。
  - 打开时焦点移动到弹窗内第一个可聚焦元素（或标题）。
  - `Tab` 在弹窗内循环，不跑到背后页面。
  - 关闭时焦点回到触发按钮，并移除 Esc 监听。
  - 增加 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`。
- **验收**：前端静态门不增加新红线；CDP 用键盘事件断言 Tab 不跳出弹窗、Esc 关闭后无残留监听。

#### UX-10：帮助抽屉应锁定背后滚动并管理焦点（P2）

- **问题**：帮助抽屉打开后，背后页面仍可滚动，焦点也未进入抽屉。
- **用户影响**：键盘用户可能 Tab 到抽屉背后的元素；滚动时抽屉与背景同时动，视觉混乱。
- **建议**：抽屉打开时给 `<body>` 加 `overflow: hidden`（或等效锁定），并将焦点移到抽屉内第一个可聚焦元素；关闭后恢复。
- **验收**：CDP 断言抽屉打开后 `document.body` 滚动被锁定；Tab 序列在抽屉内循环。

#### UX-11：命令面板应增加「最近使用」分组（P2）

- **问题**：命令面板列出 62 条静态结果，没有最近使用、收藏或命令历史。
- **用户影响**：常用操作每次都要搜索或滚动，效率低。
- **建议**：
  - 在面板顶部增加「最近使用」分组（可仅存于本次会话内存，不写浏览器存储）。
  - 或增加「常用操作」分组：新建会话、打开策略、打开运行、打开密钥。
- **验收**：打开命令面板后，首屏可见「最近使用」或「常用操作」分组；CDP 断言存在该分组标题。

### 3.4 信息密度与效率

#### UX-12：策略卡片描述应支持展开/收起（P2）

- **问题**：策略列表中每个卡片描述被截断为 2 行，但策略名对新手并不足够自解释。
- **用户影响**：用户需要点「详情」才能看完整说明，增加了探索成本。
- **建议**：卡片描述增加「展开/收起」按钮，点击后在当前卡片内显示完整描述（不跳转详情）。
- **验收**：CDP 点击「展开」后，卡片高度增加且完整文本可见；再次点击收起。

#### UX-13：运行视图的危险操作应根据状态显隐（P2）

- **问题**：「停止全部」按钮在空状态时仍显示且可点击。
- **用户影响**：虽然是防御性操作（点开会要求逐字短语确认），但在没有任何实例时空置显示危险按钮，视觉上干扰且不符合「只在必要时呈现」原则。
- **建议**：无运行实例时隐藏「停止全部」；有实例时显示。与 UX-06 合并实现。
- **验收**：空状态截图中无「停止全部」按钮；有实例时正常显示。

#### UX-14：首次引导条应按步骤进度展示（P2）

- **问题**：当前引导条「看起来是第一次用 —— 几步就能让它跑起来：1. 配密钥 2. 选策略 3. 先回测 4. 再试跑 5. 最后实盘」在所有视图（包括设置、密钥页）顶部固定显示。
- **用户影响**：用户在「我正在配密钥」的页面仍看到完整 5 步列表，没有「当前在第 2 步」的进度感；完成某步后也不会消失。
- **建议**：
  - 将引导条改为可折叠的进度组件，当前步骤高亮，已完成步骤打勾。
  - 当用户完成全部 5 步后自动隐藏。
  - 提供「不再提示」按钮（仅本次会话生效，不写浏览器存储）。
- **验收**：CDP 截图显示当前步骤高亮；完成某步后该步骤变为完成态。

#### UX-15：多语言下长文案应有自适应截断（P3）

- **问题**：英文文案通常比中文长 20%–40%，但当前按钮/标签大多没有 `text-overflow: ellipsis` 或自适应宽度。
- **用户影响**：切换到英文后可能出现按钮被撑大、布局错位。
- **建议**：在关键按钮、顶栏元素、表格表头增加 `max-width` + `overflow: hidden` + `text-overflow: ellipsis`；必要时用 `title` 属性显示完整文案。
- **验收**：切换到英文后，UI 元素宽度不超出设计边界；CDP 断言关键按钮宽度与中文模式一致。

### 3.5 安全与防错

#### UX-16：参数未保存时离开详情页应提示确认（P1）

- **问题**：053 已实现参数改动提示（顶部改动清单 + 一键还原），但用户仍可点击左侧导航或浏览器返回直接离开详情页，未保存的改动会丢失。
- **用户影响**：误触导航导致参数改动丢失；返回后需要重新填写。
- **建议**：
  - 参数或代码有未保存改动时，监听 `hashchange`/`beforeunload`，给出确认弹窗「有未保存的改动，确定要离开吗？」。
  - 保存成功后取消拦截。
- **验收**：e2e 新增断言：改动参数后点击「策略」导航，出现确认弹窗；选择留下则留在详情页，选择离开则跳转。

## 4. 边界与刻意不做

- **不写浏览器持久存储**：所有改进（如最近使用、引导条折叠）若需记忆状态，应仅存于本次会话内存或后端配置（`ricow.toml`），避免使用 `localStorage`/`sessionStorage`（项目纪律已禁止）。
- **不新增独立后端接口**：UX-05/UX-08 等应尽量复用现有 `/api/config` 和 `/api/theme`、`/api/lang` 接口；如需新增字段，优先通过现有配置面写入 TOML。
- **不改动 CLI/核心交易逻辑**：本变更仅涉及 Web UI 表现层与交互层。
- **不一次性实现全部需求**：本 spec 作为需求池，开发时可按优先级拆分子变更（如 059-A 做弹窗重构，059-B 做空状态统一）。

若以「最小可用改进」发布，建议优先完成：

1. UX-01 / UX-02：顶栏标题与浏览器标题随视图变化。
2. UX-03：非对话视图下会话列表可收起。
3. UX-05：市场视图加载失败明确提示。

完成后需通过：

- `cargo fmt`、`cargo clippy -D warnings` 全绿；
