# 067 时钟预检抗抖动 + demo 真机走查固化

## 1. 问题（一手证据，2026-10-25）

### 1.1 现象 A：时钟预检把**时钟正常**的机器误拒

在币安**测试网**（demo）跑真实下单时，日志出现：

```
错误: invalid argument: 本机时钟比交易所快 3375 ms (允许上限 1000 ms); 币安会以 -1021 硬拒签名请求。
```

但同一时刻本机用同一算法（请求前后本地时刻的中点 vs 服务器时刻）量了 8 次：

| # | RTT | 中点法偏差 |
| -- | -- | -- |
| 1 | 3558 ms | −347 ms |
| 2 | 2010 ms | −532 ms |
| 3 | 3346 ms | +35 ms |
| 4 | 1973 ms | −514 ms |
| 5 | 1837 ms | −449 ms |
| 6 | 1737 ms | −399 ms |
| 7 | 1576 ms | −303 ms |
| 8 | 2054 ms | −523 ms |

⇒ 真实钟差恒在 **±600 ms 内**，RTT 却在 **1.6~3.6 s** 间剧烈波动。
那条 `+3375 ms` 与某次 RTT=3356 ms 几乎相等 ⇒ **它不是钟差，是传输延迟**。

### 1.2 机理

偏差测量的误差**只有一个来源**：服务器在**请求到达时**打戳，而本地取的是**响应到达时**的时刻。
即使改成中点法，残余误差仍是 **往返不对称 `(B-A)/2`**（A = 请求腿耗时，B = 响应腿耗时），
其量级 **≤ 往返耗时**。⇒ 高延迟链路上，**单发采样**可以差出好几秒。

### 1.3 现象 B：同一处预检的另一版实现也误拒

更早一轮（13:40 之前）日志是 `本机时钟比交易所快 1562 ms`。当时 `fetch_clock_skew`
用「响应到达后本地时刻 − 服务器时刻」**完全没减 RTT** ⇒ 把 1.5~2 s 的传输延迟
当成"本机超前" ⇒ 同样误拒。

⇒ **同一个功能，两处实现，两个误拒。** 预检是"安全前置"，误拒的代价是
**实盘/demo 根本起不来**，且错误信息把用户指向"去校时" —— 方向完全错。

### 1.4 现象 C：demo 走查无法复跑

前一轮的 demo 走查脚本是一次性的（`tmp/walk_demo.py`），且撞出四类**假红/假绿**：
日志跨轮累积、引擎日志嵌 ANSI 颜色码、脚本在"运行中"出现后 3 秒就停、
签名查询跨重试复用过期 timestamp。⇒ **每次都要人肉重写脚本**，回归价值为零。

## 2. 做什么

### 2.1 时钟预检：多组采样 + 取 RTT 最小者

- 纯逻辑放 `ricow_engine::live`（可单测）：
  - `ClockSample = (rtt_ms, skew_ms)`
  - `pick_clock_sample(&[ClockSample]) -> Option<i64>` —— **按 RTT 最小**选
  - `clock_samples_agree(a, b, tol) -> bool` —— 两组够一致就提前收手
  - `CLOCK_SAMPLE_AGREE_MS = 500`
- `commands::mod.rs::fetch_clock_skew` 采**最多 3 组**，两组一致即提前收手（省一次往返）。
- 拆出 `fetch_server_time(market, mode)`：现货/合约各自取自己的服务器时间
  （demo 走 demo 端点；现货/合约 demo 服务器时间实测差 1.5~1.9 s，混用会白做）。
- 日志回显采样：`时钟预检采样 (取 RTT 最小者) rtts_ms=[...] skews_ms=[...]`。

### 2.2 demo 真机走查固化成可复跑脚本

`scripts/demo_walk.py`（进主仓）：

1. 自举写探针策略（**两处都写**：目录清单 `strategies/spot/<id>.toml` + **根目录实例配置
   `strategies/<id>.toml`** —— 运行路径真正读的是后者，只写前者会被静默拒启动）；
2. 真实浏览器（Playwright + 系统 Edge）走 Web UI「新建实盘(demo)」全流程；
3. **直接签名查询 demo 测试网 `openOrders` 拿铁证**（订单确实到达交易所）；
4. 勾选平仓停止 → 二次查询确认**干净撤单**；
5. 解析引擎账目（`submitted` / `canceled` / `下单失败`）；
6. 浏览器运行期异常（区分 favicon 噪声 / 404 / **5xx**）。

退出码：`0` 全绿 / `1` 有 FAIL / `2` 环境故障（预检不通过，不误导成产品缺陷）。

### 2.3 脚本里被修掉的四类假红/假绿

| 坑 | 判据 | 解法 |
| -- | -- | -- |
| 签名 URL 跨重试复用 | `timestamp` 过期 → 币安 `-1021`（HTTP **400**） | 每次重试**重新取时间戳并重新签名**（`http_get_json` 收"可调用对象"） |
| 币安错误码只在 body 里 | 只看状态码 = 没取证 | HTTPError 分支 `e.read()` 抓 body |
| 引擎日志嵌 ANSI 颜色码 | `submitted\x1b[0m...\x1b[0m=1` ⇒ 正则匹配不到 ⇒ **假红** | 读日志先剥 ANSI |
| 日志跨轮累积 | 命中上轮旧标记就把本轮刚起的运行停掉 ⇒ **假绿 + 假红** | 启动前记 `pre_len`，只扫本轮新增（**不删日志文件**，Windows 下 daemon 持句柄会锁） |

另外：浏览器 console 的 "Failed to load resource: 404/500" **不带 URL** ⇒ 挂
`page.on("response")` 记录 `status>=400` 的 URL，否则不可诊断（`favicon.ico` 404
是浏览器固定行为 —— 本服务所有端点都在 token 门后 —— 单独识别、不计 FAIL）。

### 2.4 刻意不做

| 项 | 理由 |
| -- | -- |
| 把 demo 的时钟预检降级成"只警告继续" | 预检不过 ⇒ 签名请求会被 -1021 硬拒 ⇒ 订单必失败。让它**带着明确原因失败**比"跑起来然后下单报错"好。**修测量**才是正解 |
| 放宽 `MAX_AHEAD_MS`（1000ms） | 那是**币安的真实拒签边界**，不是 ricow 的口味。放宽等于把拒签推迟到下单那一刻 |
| 给 `fetch_clock_skew` 写"联网"单测 | 纯逻辑已抽到 `ricow_engine::live` 并单测；取数层要真网，按项目惯例不写假 mock |
| 脚本进 CI / 夜间跑 | demo 测试网**要凭据**、且 RTT 抖动明显 ⇒ CI 里是 flaky 源。留在仓库做**人工/发版前**回归 |
| 顺带修 `/api/markets` 的 5xx | 本轮观察到的 500 是**合约端点不可达**导致的，且 066 已按"三份各自成败"修过降级路径；本轮不改（无复现证据） |

## 3. 验收判据

1. **时钟预检抗抖动**：多组采样取 RTT 最小者；实测 `rtts=[4038,471,449] skews=[-1275,231,249]`
   ⇒ 取 **+249 ms**（真值），不再出现 +3375 ms 那种"等于 RTT"的读数。
2. **纯逻辑有单测**：`pick_clock_sample` / `clock_samples_agree`，且断言按 **RTT** 选
   （不能是"偏差看起来最合理"）。
3. **demo 走查可复跑**：`scripts/demo_walk.py` 退出码 0，且**铁证**是
   "对 demo 测试网签名查询 `openOrders` 返回我们下的那一单"。
4. **停机后干净撤单**：二次查询 `openOrders` 返回 `[]`。
5. **引擎账目自洽**：`submitted=1` / `canceled=1` / `下单失败=0`。
6. **浏览器零真实异常**：无 5xx、无 pageerror（favicon 404 除外）。
7. **门禁六件全绿**（fmt / clippy `-D warnings` / `cargo test --workspace` /
   `ci_grep_gates.sh` / `web_frontend_check.mjs`）。
8. 整仓基线**整仓实跑读出**并同步两处镜像（`specs/roadmap.md` + `specs/architecture.md` 第九节）。
