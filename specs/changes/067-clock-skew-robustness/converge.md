# 067 收敛记录 —— 时钟预检抗抖动 + demo 真机走查固化

## 1. 结论

两件事都落地并**真机实证**：

1. **时钟预检不再误拒时钟正常的机器** —— 改成"多组采样 + 取 RTT 最小者"，

2. **demo 测试网真实下单闭环已固化成可复跑脚本** `scripts/demo_walk.py`，

## 2. 验证（全部真跑，无推定）

### 2.1 时钟预检

- **修复前**（同一台机器、同一算法、8 次采样）：偏差恒在 **±600 ms** 内，
  RTT 在 **1.6~3.6 s** 波动；被拒那次读出 **+3375 ms ≈ 当时的 RTT** ⇒ 是延迟不是钟差。
- **修复后**（同一次启动内 3 组采样）：
  ```
  时钟预检采样 (取 RTT 最小者) rtts_ms=[4038, 471, 449] skews_ms=[-1275, 231, 249]
  时钟预检通过(按 demo 服务器): 本机比服务器 +249 ms
  ```
  取 RTT 最小那组（449 ms）⇒ **+249 ms**。另两组（4038 ms / 471 ms）分别是
  **往返不对称打出来的假读数**，单发采样就会撞上其中之一。
- **单测**（`ricow_engine::live`）：`pick_clock_sample` 3 条 + `clock_samples_agree` 1 条。
  关键一条是 `test_pick_clock_sample_ignores_skew_magnitude` ——
  **锁住"按 RTT 选"而不是"按偏差看起来合理选"**，否则将来有人会改成后者，
  就会选中一个恰好接近 0 的坏样本。

## 3. 过程中撞到的真问题（都已修 + 有回归护栏）

| # | 现象 | 根因 | 判据 / 护栏 |
| -- | -- | -- | -- |
| 1 | demo 运行"运行中"却 `submitted=0` | 引擎 **035 静默兜底心跳 30 s** 用最后一次 orderbook 驱动 `on_tick`；**orderbook 为空则跳过** ⇒ 行情 WS 没连上就永远不下单 | 探针策略必须**真下单**；脚本按"本轮新增日志"判定，不按上一轮遗留标记 |
| 2 | 脚本读不出 `submitted=1`（引擎日志明明写着） | 引擎日志**嵌 ANSI 颜色码**，`submitted\x1b[0m\x1b[2m=\x1b[0m1` ⇒ 正则匹配不到 ⇒ **假红** | 读日志先剥 ANSI |
| 3 | step7 命中**上一轮**的提交标记，把本轮刚起的运行停掉 | 日志**跨轮累积** ⇒ **假绿 + 假红** | 启动前记 `pre_len`，只扫本轮新增；**不删日志文件**（Windows 下 daemon 持句柄会锁） |
| 4 | 签名查询返回 **HTTP 400** | `http_get_json` 重试时**复用同一个已签名 URL** ⇒ `timestamp` 过期 ⇒ 币安 `-1021` | 每次重试**重新取时间戳重新签名**（URL 改成"可调用对象"） |
| 5 | 只看到 "400 Bad Request"，查不出原因 | 币安错误码（`-1021` 等）**只在响应体里** | HTTPError 分支 `e.read()` 抓 body |
| 6 | console 报 404/500 但**定位不到端点** | 浏览器 console 文本**不带 URL** | 挂 `page.on("response")` 记录 `status>=400` 的 URL |
| 7 | 脚本改用共享的 `http_get_json` 后签名查询开始 400 | 重构时**把 `X-MBX-APIKEY` 头丢了** | 头必须带；Binance 的错误码/消息只在 body 里 |
| 8 | 预检 `/api/v3/time` 报 400 | 该公开端点**不接受任何参数**，多带 `timestamp` → `-1101` | 裸打，不带参 |

## 4. 判据表（写下来是为了下次照着挑）

| 场景 | 正确判据 | 反例（会假绿/假红） |
| -- | -- | -- |
| 选时钟采样 | **RTT 最小** | "偏差看起来最合理" / "偏差绝对值最小" |
| 读引擎日志 | 先剥 ANSI | 直接 `submitted=(\d+)` |
| 判"本轮下过单" | 只扫 `pre_len` 之后的新增 | 扫整个文件（命中上一轮） |
| 断"订单到了交易所" | 对测试网**签名查询** `openOrders` | 只看引擎自报 `submitted` |
| 断"撤干净了" | 停机后**再查一次** `openOrders` == `[]` | 只看引擎 `canceled=1` |
| 断"浏览器无异常" | 按 `status>=400` 的 **URL** 分类 | 只看 console 文本（不带 URL） |
| 断"网络可用" | 预检 + **每次重试重新签名** | 复用过期签名 URL（-1021） |
| 断"启动成功" | 运行行**进入运行中** **且** 本轮日志有提交标记 | 只看 daemon 报"已启动"（子进程可能在预检就死了） |

## 5. 刻意不做（重申）

- **不把 demo 的时钟预检降级成"只警告继续"** —— 预检不过则签名必被 -1021 拒，
  让它带着明确原因失败，好过"跑起来然后下单报错"。**修测量**才是正解。
- **不放宽 `MAX_AHEAD_MS`（1000 ms）** —— 那是币安的真实拒签边界，不是 ricow 的口味。
- **不给取数层写假 mock 单测** —— 纯逻辑已抽到 `ricow_engine::live` 并真单测；
  取数要真网，按项目惯例不造假绿。
- **脚本不进 CI / 夜间跑** —— demo 测试网要凭据、RTT 抖动明显 ⇒ CI 里是 flaky 源。
  留在仓库做**人工 / 发版前**回归。
- **不动 `/api/markets` 的 5xx** —— 本轮观察到的 500 由合约端点不可达导致，
  066 已按"三份各自成败"修过降级路径，本轮无复现证据 ⇒ 不动。

## 6. 遗留 / 风险

1. **demo 测试网 RTT 在 1.6~3.6 s 波动**，靠"多组采样 + 取最小 RTT"把噪声压到百毫秒级；
   但**极端抖动**（单次 RTT 十几秒）下仍可能多花一次采样时间（最多 3 组）。
2. **脚本依赖 demo 测试网可用**：预检不过 → exit 2（明确是环境故障，不是产品缺陷）。
3. 测试网账户有一笔**既有 dust 持仓 0.00005810**（低于 `step_size` 0.0001，无法自动平仓，
   非本轮所下）—— 复跑前不必清理，但**别当成"本轮漏单"**。
4. 改动**未提交**（等用户明确说"提交"）。
