# 028 功能规格: 策略自取数据 —— 数据服务 + 策略运行时

**功能目录**: `specs/changes/028-data-service`

**创建日期**: 2026-09-20

**状态**: 草稿(待实施; 已经 3 位独立审核员审核并修订, 见 §九)

**输入**: 用户 2026-09-20 描述四条 + 拍板决策 D1~D8(§八)

## 一、为什么

现状(2026-09-20 逐份核对代码):

- **引擎拥有唯一主循环**: 取 `params.pair` 一个标的 → 一条盘口流 → 每次行情更新调 `on_tick`(`crates/ricow_engine/src/command.rs:637` Dry Run / `:964` 实盘) → 引擎把返回的订单数组交给 `ctx.place_order`(`:640` / `:968`)。策略只能被动响应, 不能决定"看哪些数据、什么时候算一轮"。
- **数据源写死在引擎**: 币安现货 / USDT-M(`Exchange::get_klines`, `crates/ricow_core/src/exchange.rs:28`, 单标的、`limit` 无 `from/to`)、Nasdaq 官方日线(`ricow_engine::nasdaq`, 硬编码起始日 `2016-01-01`, 落 `us_klines` 专桶)。策略无法选源、选周期、选标的。
- **指标绑定单一主序列**: `ctx:ema(pair, n)` 等 12 个指标只能算当前 pair 的主序列, 尾窗硬编码 100 根(`crates/ricow_strategy/src/lua.rs:202`; 断言 `:1049 test_single_klines_still_capped_at_100`)—— 需要长窗口(如 EMA200)或跨标的比较时无法表达。
- **装配层替策略选数据**: 组合信号模式(`universe` 键 / `signal_klines` 预装 / `SIGNAL_TAIL=400` 尾窗, `ricow_strategy/src/backtest.rs:108` / `backtest_runner.rs:113`)在装配层替策略决定标的池与信号轨, 当前**零内置消费者**(唯一的 `bs_momentum` 已删除)。高周期通道(`atr_interval` / `regime_interval` / `warmup_bars` / `ctx:*_tf`)只存在于未合并分支 `feat/shannon-atr-grid`, 且该分支文档自述"模拟盘/实盘未接线"。

**结论**: 缺的不是数据能力, 而是**策略可调用的公共服务入口**。继续"引擎加通道 + 策略读通道", 每加一个来源 / 周期 / 标的组合都要改引擎。

**代价(实测留档)**: bStock 现货 1m 只有 ≈79 天(留档于 `specs/research/bstocks-market-data-2026-09.md` 与 023 分支回测报告), 交易量小; 想用 10 年美股日线做趋势判据时, 策略自己完全无法表达"我要 QQQ 10 年日线 + ETHUSDT 1h + 本标的盘口"。

## 二、范围

**做**: ① 引擎提供运行时(回调集合 + 订单出口)与公共服务(数据 / 行情 / 交易 / 时钟); ② 数据服务以 `(source, symbol, interval)` 为键, 任意来源 / 标的 / 周期 / 多序列并取; ③ 内置 4 个数据源(币安现货、币安合约、Nasdaq、Yahoo), 新增源不改策略与主流程; ④ 用户自写策略可用任意自认安全的 URL(仅 GET); ⑤ 回测 / Dry Run / demo 共用同一份 Lua; ⑥ 本地库为回测唯一数据源 + `ricow data pull`; ⑦ **退役**装配层信号预装与 `us_klines` 专桶(§八 D7/D8)。

**不做**: ① 不为已部署的旧策略做兼容层(D2: 旧策略不管, 本计划不处理); ② 不做选币 / 研究 / 图表入口; ③ 不做公网访问、多用户、云端数据托管; ④ 不引入第三方 SDK 依赖、不新增 crate、不改任何 `Cargo.toml` 依赖项; ⑤ 不做 `http:post`(无用户故事支撑, 需要时再加); ⑥ 不取分支的 `--start/--end` CLI 增量(长窗口用现有 `--days` 表达, 避免无关范围)。

## 三、用户场景与测试 *(必填)*

### 原话 → 需求追溯

| 用户原话 | 落点 | 验收 |
|:--|:--|:--|
| ① 提供 mlua 运行环境 + 公共服务(如 ws 行情), 而不是"通过事件对接" | US2 / F3(F3 行情服务)/ FR-001、FR-023、FR-024 | SC-005 |
| ② 完整策略流程都在 mlua 策略里 | US1、US2 / F0、F1 | SC-001、SC-005 |
| ③ 第三方美股长 K 线 / 多标的 / 多周期 / 多来源 | US1、US2 / F1、F2 | SC-001、SC-005 |
| ④ 项目给策略提供 API, 逻辑结构都在策略里 | US1、US2 / F0~F5 | SC-005、SC-011 |

### 用户故事 1 - 策略自己决定用哪条 K 线 (优先级: P1) 🎯 MVP

**独立测试**: 一个最小 Lua 策略取 `yahoo/QQQ/1d` 与 `binance_spot/ETHUSDT/1h` 两条序列, 回测里出信号、Dry Run 里按同一条日线信号下单 —— 同一份脚本零改动。

**验收场景**:
1. **Given** 本地库有 QQQ 日线, **When** 策略取该序列, **Then** 拿到按时间升序的 bar 与句柄指标, 且看不到任何未收盘 bar。
2. **Given** 本地库缺该序列, **When** 跑回测, **Then** 非零退出码 + 打印 `ricow data pull ...` 补齐命令, 不联网、不静默空序列。
3. **Given** 同一条脚本, **When** 分别跑回测与 Dry Run, **Then** 零改动; 序列口径(来源 / 周期 / native 或 resampled)在日志可见。

### 用户故事 2 - 策略自己决定用 ws 实时信息还是某周期 K 线 (优先级: P2)

**独立测试**: 三个最小策略分别只用盘口订阅、只用 1h K 线、只用定时器, 在 Dry Run 与 demo 下各自按预期触发。

**验收场景**:
1. **Given** 策略只订阅 1h K 线, **When** 运行, **Then** 每根 1h 收盘后触发一次, 盘口 tick 不驱动策略。
2. **Given** 策略订阅多个标的盘口, **When** 盘口更新, **Then** 回调带 symbol 与买卖价, 任意已订阅标的可查询现价。
3. **Given** 策略声明每日固定时刻动作, **When** 时刻到达, **Then** 触发一次(回测按虚拟时钟推进, 不等待真实时间)。

### 用户故事 3 - 用户策略可自取任意 URL 数据 (优先级: P3)

**独立测试**: 用户策略用 `http:get` 取一个自选公开端点(JSON/CSV), 解析后参与决策; 失败时拿到可判别错误。

**验收场景**:
1. **Given** 用户策略请求任意 URL, **When** 网络可达, **Then** 返回响应体(带状态码与耗时), 有墙钟超时与响应体上限, 请求入日志。
2. **Given** 请求超时或非 2xx, **When** 策略调用, **Then** 返回可判别错误, 不中断策略进程, 不伪造数据。
3. **Given** 内置策略, **When** 取数, **Then** 只走平台数据服务(`http.` 零出现, 由扫描断言保证)。

### 边界情况

- 数据源限速 / 不可达 / 响应格式变化: 如实报错, **不回落**到其他源或近似数据。
- 增量回补失败(Dry Run / 实盘): 序列标记 `stale` 且策略可见, 不静默用旧数据。
- 停机时仍有 in-flight HTTP 请求: 由宿主线程收尾, 不阻塞停机流程, 结果丢弃并记日志。
- 跨源 symbol / 时间戳 / 时区: 序列键存**源原生 symbol**(不做跨源翻译); `open_time/close_time` 统一毫秒 UTC; 日界由策略显式声明(见 FR-006 / FR-014)。
- 源不支持的周期: 由引擎重采样(只保留完整桶)并标注 `resampled`, 或按 FR-014 报错。
- 序列长度不足 / 预热不够: 句柄指标返回 `nil`, 策略自行判断, 引擎不猜值。
- 跨源对齐: 可见性一律按 bar **收盘时间**判定。
- 重复订阅同一序列 / 同一序列被多个指标使用: 引擎侧只拉一次、指标按周期桶只算一次。
- 回测窗口外的数据请求: 预热段允许(供指标种子), 但预热段不产 tick、不产订单、不进报告。
- 策略滥用 URL(超大响应 / 慢响应 / 高频): 受墙钟超时、响应体上限、内存上限共同约束。

## 四、功能需求 *(必填)*

### 运行时与订单出口 (F0)

- **FR-001**: 回调集合 = `on_init` / `on_bar` / `on_quote` / `on_timer` / `on_tick` / `on_fill` / `on_stop`(`on_tick` 保留为"每次盘口更新"的回调, 与 D5 一致); 每个回调可选, 未定义即跳过; `on_order_update` 现状为 no-op, 本变更不改。
- **FR-002**: 订单出口协议 = ① 回调**返回值**为订单数组(沿用现状语义, `on_tick`/`on_bar`/`on_timer`/`on_quote` 均可); ② 主动出口 `ctx:place_order(req)`; ③ 主动撤单 `ctx:cancel_order{...}`。
- **FR-003**: 撤单粒度: `ctx:cancel_order{pair=, order_id=|client_order_id=}` 精确撤单; 无参(或仅 `pair`)形式 = 撤**本实例归属**的全部挂单(订单号前缀判定), 非归属挂单只上报不撤。
- **FR-004**: 引擎**不再**替策略决定标的与周期 —— 可验证判据: 单 pair 主循环与装配层信号预装(`universe`/`signal_klines`/`SIGNAL_TAIL`)退役(SC-007), `params.pair` 不再是策略取数的前置条件。
- **FR-005**: `on_bar(series, bar)` 的 `series` 携带 `source` / `symbol` / `interval` / 口径(`native|resampled`), 策略据此区分多条序列。
- **FR-006**: `on_timer{secs=N}` 与 `on_timer{at="HH:MM"}`; 时区由策略显式声明(缺省 UTC), 日界口径随声明; 回测按虚拟时钟、实盘按真实时钟。
- **FR-007**: 沙箱约束: 无 `os`/`io`/`require`/`loadstring`/`pcall`; 内存 64MB; **指令预算每回调独立 1M**(同一轮触发多个回调时单轮上限 = 回调数 × 1M, 如实写明); HTTP 调用受墙钟超时约束且**不计入**指令预算。

### 数据服务 (F1)

- **FR-008**: 策略必须能按 `(source, symbol, interval)` 取任意序列: `data:history` 取历史、`data:subscribe` 收增量、`data:series` 拿句柄。
- **FR-009**: 句柄方法覆盖与 `ctx:*` 相同的 12 个指标(`ema`/`sma`/`wma`/`rsi`/`macd`/`boll`/`atr`/`adx`/`stoch`/`cci`/`roc`/`mom`)加 `last`/`close`/`klines(n)`。
- **FR-010**: 句柄指标与 `ctx:*` 指标在**同一输入长度**下逐位一致(硬约束)。窗口更长时的差异属预期(EMA 种子), 必须在文档与本条注明。
- **FR-011**: 序列窗口 = 策略声明(`n`, 默认 300, 下限 `max(最大指标周期+1, 2)`, 上限 5000); 超上限报错; `ctx:klines` 的 100 根硬编码 cap 退役, 与此统一。
- **FR-012**: 同一策略可并持多条序列(上限 32, 超出报错); 每 tick 快照成本不随序列数线性放大(句柄只持尾窗)。
- **FR-013**: 可见性无前视: 任意时刻只能看到 `close_time <= 当前时间` 的 bar; 单点实现 + 单测。
- **FR-014**: 周期口径: 源支持则取原生周期; 源不支持则重采样(只保留完整桶, 首尾半桶与缺口桶丢弃), 并在元信息标注 `native|resampled` 与桶口径; 重采样实现单点(供 strategy 与 engine 共用)。
- **FR-015**: 复权口径: `yahoo` 源保留 `adjclose`; 策略可声明用哪个价(缺省 `close`), 元信息可见, 报告标注所用口径。
- **FR-016**: 取数失败可判别且不回落; Dry Run / 实盘增量回补失败时序列标记 `stale` 并让策略可见。

### 数据源适配 (F2)

- **FR-017**: 数据源 = trait + 注册名; 新增源 = 1 个实现文件 + 1 处注册, **不改策略、不改引擎主流程**。
- **FR-018**: 内置 4 源: `binance_spot` / `binance_futures`(由既有 `Exchange::get_klines` 适配, `from/to` 按 1000 根分段循环 + 去重)、`nasdaq`(复用既有解析, 窗口改 `from/to`)、`yahoo`(v8 chart, 免 key)。
- **FR-019**: 未知来源名必须报错并列出可用来源。
- **FR-020**: 周期标签 → 毫秒表**唯一定义**(`ricow_core`), 现有 `ricow_binance` 两处散落表收敛到它。
- **FR-021**: 序列键存源原生 symbol(`binance` 大写无连字符 / `yahoo` `-` 分隔), 引擎不做跨源翻译、不猜。
- **FR-022**: 源级限速 + 串行化 + 同键并发去重。

### 行情服务 (F3)

- **FR-023**: 策略可自行订阅任意标的实时盘口(多标的), 回调 `on_quote(symbol, bid, ask)` 按标的区分; 盘口增量 diff 合并语义不变(按价格合并、`size=0` 删档); 断线重连复用现有守护。
- **FR-024**: 策略可查询已订阅标的的现价 / 最优买卖价; 未订阅或不可用返回 `nil`(不猜值)。

### 交易与账户 (F4)

- **FR-025**: 主动下单与撤单可用(FR-002/FR-003); 多标的由 `req.pair` 天然支持; 撤单只撤本实例归属单。
- **FR-026**: 固定下单频率护栏(100 单/秒, 计数对全部 pair 共享)与"平台不做投资判断"边界保持不变, 并有回归用例。

### 用户策略自取 URL (F5)

- **FR-027**: 用户策略可发起 `http:get(url, opts)`(**仅 GET**), **不限制域名**; 由宿主实现(独立线程 + 独立 runtime + 墙钟超时默认 10s + 响应体上限默认 5MB), 不暴露文件 / 进程能力; 请求目标与结果摘要入策略日志; 不消耗指令预算。
- **FR-028**: 内置策略**不得**使用该通道(只走平台数据服务), 由扫单断言保证; 用户策略的数据来源合规性由用户自行负责。

### 本地数据与命令 (F6)

- **FR-029**: 本地库统一为 `data_klines` 单表(键 `source|symbol|interval|open_time`), 写入幂等, 配套水位查询; **`us_klines` 专桶与 `insert_us_klines`/`get_us_klines` 退役**(D8)。
- **FR-030**: 提供 `ricow data pull --source/--symbol/--interval/--start/--end`: 增量补齐、输出根数与区间、未知源报错列可用源。
- **FR-031**: 回测**只读本地库**, 缺数据失败并给补齐命令; Dry Run / 实盘允许增量回补。
- **FR-032**: `nasdaq` 源统一落 `data_klines`, 去掉硬编码起始日 `2016-01-01`, 交易日历读取点一并改走新表。

### 三条路径一致性与门禁 (F7)

- **FR-033**: 同一份 Lua 必须能在回测 / Dry Run / demo 三处运行(SC-001 覆盖 demo), 差异只在账户事实源与清理语义。
- **FR-034**: 实盘全部既有门禁与语义一条不改: 风险确认 → Dry Run 时长门禁 → 时钟预检 → 二次确认; 停机顺序 停消费 → `on_stop` → 撤单兜底 → (可选)平仓 → 残留复查; `on_stop` 语义不变。
- **FR-035**: **退役**装配层信号预装(`universe` 键 / `signal_klines` 预装 / `SIGNAL_TAIL`)—— 同一件事改由策略经 `data:series` 表达; **保留**组合回测的多标的同一账本撮合能力、`ctx:*` 只读 API、`build_interval_ticks`(D7)。

### 文档与 AI 面 (F8)

- **FR-036**: 同步 `specs/lua-api.md`(新章节 + 旧 API 定位)、`specs/architecture.md`、`specs/backtest.md`(§一可见性 / §二 bar 顺序)、`specs/product.md`(保留清单 / 网络条款 / 数据源表)。
- **FR-037**: `ricow agent-kit` 手册与内置 AI 提示词同步; `ricow_engine::strategy::extract_code` 的回调识别集扩为 `on_init/on_tick/on_bar/on_quote/on_timer`(否则只写新回调的策略会被判"未提取到 Lua 代码")。
- **FR-038**: 网络条款全树同口径修订: `specs/constitution.md` + `specs/product.md` + `README.md`/`README_zh.md` §7 + `specs/architecture.md`; 并同步 README 两份 FAQ("回测要下载 K 线")、"唯一策略样板"表述、`website/index.html` + `website/zh.html`; `specs/roadmap.md` 补 027/028 档案状态登记并改写保留清单。

## 五、关键实体 *(涉及数据时填写)*

- **SeriesKey**: `(source, symbol, interval)` —— 序列唯一标识; `source` ∈ 注册名; `symbol` 为源原生写法; 元信息含 `native|resampled`、`warmup`、`stale`、价格口径(`close|adjclose`)。
- **Bar**: `open_time` / `close_time`(毫秒 UTC) + `open/high/low/close/volume` + 可选 `adjclose`。
- **Source**: 注册名 + 能力声明(支持周期、历史深度、限速); 实现者负责取数与解析。
- **data_klines**: 单表缓存, 键 `source|symbol|interval|open_time`。
- **Subscription**: 策略在 `on_init` 登记的序列订阅 / 盘口订阅 / 定时器集合; 引擎据此装配。

## 六、成功标准 *(必填)*

- **SC-001**: 同一份 Lua 脚本**零改动**在回测 / Dry Run / demo 三处取到同一条第三方日线并出信号(三处实测记录, 命令与输出留档)。
- **SC-002**: 新增一个数据源 = 1 个实现文件 + 1 处注册(引擎主流程改动 0 处、策略改动 0 处); 以"真实新增一个源"验证。
- **SC-003**: 无前视用例通过率 100%。用例清单: 单源单周期 / 跨源(日线 + 1h)/ 跨周期 / 缺口日 / 预热段边界。
- **SC-004**: 回测可复现: 同一策略 + 同一本地库, **断网**状态下重复两次结果逐位一致。

- **SC-007**: 退役完成: `universe|signal_klines|SIGNAL_TAIL|us_klines|insert_us_klines|get_us_klines` 在代码中零命中(历史档案除外), `ctx:klines` 100 根硬编码 cap 分支移除。
- **SC-008**: 句柄指标与 `ctx:*` 在同一输入长度下逐位一致(实测比对记录)。
- **SC-009**: 测试基线不倒退: `cargo test --workspace` 计数不低于基线, fmt/clippy 三门禁通过; 6 个内置脚本迁移后回测与基线逐位比对(差异逐条解释)。
