# 053 · 改参数必须提示「未保存」+ 给出改动前后对比

> 起于用户一句追问(2026-10-12):「**AI 修改策略以后, 修改后的参数反映在哪里, 需要点击保存吗?**」
> 这句话本身就是缺陷证据 —— 界面没有任何"你还没保存"的提示, 用户只能靠问。
> 顺带按用户要求「**你必须真跑**」用真实 DeepSeek 密钥跑通了 N3 多轮改参 + 影响评估,
> 并据实测结果修掉了 `ai-assess` 提示词的一处**会让 AI 把设计误判成数据错误**的缺口。
> 变更编号 053(`specs/changes/` 目录最大 052; `T053` 是 019 里的任务号, 不是变更号)。

## 一、缺陷: 改了参数, 界面一声不吭

`strategy_editor.js::updateDirty()` 只比较**代码编辑器**内容:

```js
const dirty = codeEl.value !== st.savedCode;   // ← 参数表单完全不在判据里
```

后果:

- 手动改参数输入框 → 无提示(`renderParams` 建控件时**没有绑任何 `input` 监听**);
- AI 改参数(`fillParamInputs`)→ 也无提示 —— 而它恰恰是最该提示的场景;
- **回测还能用表单值跑出结果**(`/api/backtest` 的 `params` 覆盖), 于是用户合理地以为
  "已经改好了"。刷新页面或切走才发现没落盘。

保存本身是对的: `POST /api/strategies` 带 `overwrite:true` 才写实例 TOML。**缺的是"告诉你还没存"**。

## 二、修法: 基线 + 行内对比 + 汇总面板 + 一键还原

判据统一为**与基线比字符串**(改了又改回去不算改动, 与 `savedCode` 同一口径):

| 落点 | 做法 |
|:--|:--|
| `strategy_form.js::paramEntry` | 登记项多带 `name` / `base`(渲染时的字符串基线) / `diff`(行内容器); 绑 `input` + `change` 两个事件(下拉与复选框只发 `change`) |
| 同上 `paramDiffs()` | 返回真变了的项(**含交易对** —— 它同样只在保存时落盘) |
| 同上 `renderParamDiff()` | 刷两处: 参数行**行内**「原 X → 改为 Y」+ 卡片顶部**汇总清单**(参数多时行内会滚出视野) |
| 同上 `onRevertParams()` | 一键还原到基线(代码另有「撤销」按钮, 各管各的 —— 混成一次撤销会让人以为代码也退回了) |
| `strategy_editor.js::updateDirty` | 代码 **或** 参数任一改过即脏; 两侧各一条提示; 都改时代码那条明说「代码与参数都有未保存修改」 |
| `markParamBaseline()` | 保存成功后推进基线 —— 否则保存完还亮着未保存提示 |

**为什么用字符串比而不是转数字**: ① `1` 与 `1.0` 对用户是同一个值; ② 用户正在输入 `0.` 时
`Number()` 得 NaN, 会把"还在打字"判成改动; ③ 非法输入会在 `readParam` 抛错, 而标脏不该抛错。

**为什么「改动对比」面板放在 `#sg-params` 外面**: `renderParams` 每次 `innerHTML = ""` 会把它
一起抹掉 —— 与 052 的引导卡是同一个坑(已在代码注释里写明)。

## 三、真跑发现的第二个问题: AI 把**设计**误判成**数据错误**

用户给了真实 DeepSeek 密钥后跑通了整条链路(见第五节)。`ai-assess` 的第一次真实输出里有这么两句:

> 「两次的**基准收益不一样**(−0.1558% → 1.6514%)。同一个回测窗口下, 买入持有的基准按理应该相同,
>  所以这两次的数据口径/取数可能并不完全一致, 我不能把差异 100% 归因到参数上。」
> 「**夏普: −9.0614 → −737.0421**, 数值上明显更差 … 仅凭这两份指标我**解释不了**」

第一句是**错的**。查 `ricow_strategy/src/backtest.rs:1491-1495` 确认: 基准收益的口径是
「**从首次成交价同时点、同本金**满仓买入持有」—— 不是从窗口起点起算。改前 108 笔成交(激活早)、
改后 3 笔(激活晚), 两次首次成交时点不同, **基准本就不同, 这是设计**。

**反证**: 让两组都用同一份回测配方(`start_price` 极大 = 立即激活 + `initial_buy_amount` 非 0)
再跑一次, 基准就变成 −0.0063% vs −0.0024%(几乎一致) —— 差异确实来自成交时点, 不是数据问题。

第二句虽然诚实(没编原因), 但把**失真后的比率**当成"重大恶化"排在显眼处。年化波动率 0.41%
这种量级下, 夏普/索提诺会被极小的分母放大到难以解释的量级。

**修法**: 把这两条口径知识写进 `AI_ASSESS_PREAMBLE`(不是模型该自己推的东西), 并加单测锁住:

1. 基准从**首次成交**起算, 不是窗口起点; 两次成交时点不同 → 基准不同是设计, 别据此怀疑数据;
2. 成交笔数很少或波动率接近 0 时, 比率指标会失真 → 以成交笔数与净盈亏绝对额为主判据,
   比率照实报出但不拿它下结论, 解释不了就明说解释不了。

## 五、真跑记录(DeepSeek, 密钥走环境变量, 未落盘未提交)

策略 `zz_ai_live` = 从内置「现货动态非对称网格」(`paired_grid`) `copy_from` 而来, 清单 11 项参数。

**第一轮**(用户只说意图, 不点名参数、不给数值):「我更看好震荡行情, 想做得保守一点, 别一次压太多钱」
→ AI 自己决定动 `spacing_pct 0.01→0.015`、`order_amount 10→6`、`min_pair_profit 0.002→0.004`,
逐项给了理由与风险; 并**主动标注** `start_price` 填的 3000 是占位值、要按回测窗口起点价替换。

**第二轮**(带 1146 字符 `history`):「但这样赚得太慢了, 单笔可以大一点, 间距别再拉大了」
→ 在上一轮基础上 `order_amount 6→12`、`spacing_pct 0.015→0.012`, 理由直接引用上一轮的值。
**多轮确实生效**(不是每轮重置)。

**回测**: 改前 108 笔 / 改后 34 笔(同配方可比口径)。**评估**: 成交笔数、换手率、净盈亏逐项对比,
净盈亏下降**直说**了, 结尾照常提醒"只是一段历史窗口"。

**额度**: 全程 2 次改参 + 2 次评估 ≈ 几万 token; 账户余额 ¥486.66(用户原本以为不多, 实测充裕)。

## 六、一条不是为了挑刺、但必须记下的观察

AI 第一轮给的 `start_price = 3000` 是**占位值**(它自己标注了)。照它给的值跑, 成交只有 **3 笔**
(价格没跌破 3000 → 长期不激活); 换成回测配方后同样这组参数跑出 34 笔。

这不是缺陷 —— 清单里就写着 `start_price` 必填、"回测请设为窗口起点价"。但它说明一件事:
**N3 的「自动评估影响」跑出来的数字, 质量取决于用户有没有先填对必填项**。提示词已经让 AI 主动
标注占位值, 前端后续若要再加保险, 最小改动是评估面板在成交数为 0/极少时提示一句"策略可能没激活"。
