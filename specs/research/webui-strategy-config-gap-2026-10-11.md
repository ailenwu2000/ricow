# Web UI「复制新建策略」的配置断层 —— 现状取证与解决方案 (2026-10-11)

> 起因（用户原话）：**通过 Web UI 复制新建一个策略的时候，「AI 修改」里面如何帮助用户修改这个策略的配置？
> 目前感觉用户完全不知道该怎么配置。**
>
> 本文只做**取证 + 方案**，不含实现。所有断言都带 `文件:行` 证据，可自行复核。

---

## 一、结论先行

用户「不知道该配什么」**不是文案问题，是数据在复制那一刻就丢了**。

策略的「参数有哪些 / 叫什么 / 是什么意思 / 默认多少」这四件事，**全在清单（manifest）里，不在 Lua 代码里**。
而复制流程**只搬 Lua、不搬清单** —— 复制完，这四件事一起消失，页面上只剩一个「交易对」输入框。

更糟的是，用户寄希望于的「AI 修改」**被设计成只改 Lua 源码**：它的提示词明确要求「与本次修改指令无关的
原有逻辑逐字保留」，返回体只有 `code` 一个字段。用户说「把间距调大点」，AI 会去改**算间距的那几行代码**，
而不是把 `spacing_pct` 这个参数改成新值 —— 用户问「该怎么配」，得到的是「代码变了」，认知负荷反而更高。

**三条修法，从核心到兜底：**

1. **复制时把清单一起落盘** —— 把参数说明还给用户（**核心，建议先做**）
2. **从 Lua 静态提取参数键** —— 连没有清单的裸脚本也能列出「有哪些旋钮」，**不需要 AI**
3. **把「AI 修改」扩成能改配置** —— 说一句「间距调大点」落到参数表单，而不是改代码

---

## 二、现状取证

### 2.1 复制这条链，清单在哪儿丢的

前端 `openCopyModal`（`crates/ricow/src/web/assets/strategies.js:1268-1293`）提交的请求体只有
`name / market / pair / code / params`，其中 **`params: {}`**、**`code = 原策略的 Lua`**。
代码注释写得很直白（`:1284`）：

> `// 副本是全新用户策略: 原样复制 Lua, 参数留空(用 Lua 内 fallback 默认), overwrite=false。`

服务端 `save_strategy`（`crates/ricow/src/web/strategy_io/mod.rs:734-797`）把这几个字段交给落盘内核
`write_strategy_files`，**该内核只写两个文件**（`crates/ricow_engine/src/strategy.rs:159-160`）：

| 写出的文件 | 内容 |
|:--|:--|
| `strategies/{market}/<name>.lua` | Lua 源码 |
| `strategies/<name>.toml` | 实例 TOML（pair + params + `script_path`） |

**清单文件 `strategies/{market}/<id>.toml` 不在其中。**
（内置清单是编译期 `include_str!` 嵌进二进制的 —— `catalog.rs:157-198` —— 磁盘上根本没有可复制的源文件。）

### 2.2 没有清单 → 目录把这条策略当「裸脚本」

`catalog::scan_user_in` 扫盘时，只有 `.lua` 而没有同名清单的，会**合成一份空清单**
（`crates/ricow/src/strategies/catalog.rs:376-394`）：

```rust
manifest: StrategyManifest {
    ...
    summary: String::new(),
    params: Vec::new(),   // ← 参数 schema 为空
    ...
},
declared: false,          // ← 诚实性标记: 未声明
```

### 2.3 空清单 → 详情页参数表单只剩一个框

`renderParams`（`crates/ricow/src/web/assets/strategy_form.js:290-333`）是**照清单画的**：

1. 先画「交易对」（`#sg-pair`）；
2. 再 `for (const p of detail.params || [])` —— 清单空 → **循环零次**；
3. 最后兜底画「其他已保存参数」：把实例 TOML 里的键**原样当标签**（`sgOtherParams`，
   `strategies.js:198`）—— 但复制时 `params: {}` 也是空的 → **这一段也零行**。

> **结果：复制完打开详情页，「参数」卡片里只有「交易对」一个输入框，其余一片空白。**
> 用户看不到这个策略有哪些参数，自然「完全不知道该怎么配置」。

### 2.4「AI 修改」只改代码，不改配置

`POST /api/strategies/{id}/ai-edit` → `build_edit_prompt`
（`crates/ricow/src/ai/provider.rs:440-463`）把**清单摘要当作只读参考**塞进提示词，并硬性约束：

> 1. 只输出**一份**改写后的完整 Lua 代码（包含完整的 on_tick 以及需要保留的 on_init 等函数）；
> 4. 与本次修改指令无关的原有逻辑**逐字保留**。

返回体是 `AiEditReply { code, warnings }`（`strategy_io/mod.rs:667-672`）—— **只有 code**，
没有 params、没有 manifest。前端 `onAiEdit`（`strategy_editor.js:238-275`）把它
`$("sg-code").value = reply.code`，**只替换代码编辑器**。

> 用户输入「把网格间距调成 ATR 三倍」，AI 会去**改写 Lua 里算间距的那几行**，
> 而不是把 `spacing_pct` 参数改成新值。**这是典型的意图误解。**

### 2.5 用户唯一的「声明参数」入口，是开发者表单

详情页里唯一能补参数的地方，是折叠的「参数清单(声明式)」（`strategies.js:587-611`），
字段是 **键名 / 中文名 / 类型 / 默认值 / 必填 / 说明 / 可选值**（`strategy_form.js:410-462`）。

要填对「键名」，用户得先读懂 Lua 里 `num(ctx, "spacing_pct", 0.01)` 读的到底是什么 ——
这是**策略作者的活**，不是「想调一下策略」的用户的活。

### 2.6 一个被浪费掉的事实：参数信息其实**纯静态就能拿到**

内置策略的 Lua 里，参数读取全是**字面量键 + 字面量兜底默认**（`strategies/spot/paired_grid.lua:229-237`）：

```lua
local spacing_pct   = num(ctx, "spacing_pct", 0.01)
local order_amount  = num(ctx, "order_amount", 10)
local accumulate_mode = cfg_str(ctx, "accumulate_mode", "u")
local fee_side      = num(ctx, "fee_side", 0.001)
```

这意味着 **「这个策略有哪些参数、默认多少、是什么类型」这件事，纯静态扫描就能从任何一份 Lua 里扫出来** ——
**完全不需要 AI，也用不着用户去读代码**。而目前仓库里**没有任何一处**用它。

（顺带：清单本身也很完整 —— `strategies/spot/paired_grid.toml:12-89` 里 11 个参数，每个都有
中文名 / 类型 / 默认值 / 说明 / 必填 / 枚举值。复制时把这些丢掉，非常可惜。）

## 三、解决方案

### 方案 1（核心，建议先做）：复制 / 模板新建时把清单一起落盘

**做什么**：复制内置（或从模板新建）时，把模板的清单（中文名 / 说明 / 参数 schema）
**一并写进** `strategies/{market}/<newid>.toml`。

**为什么**：这一步直接把「参数说明」还给用户。复制完打开详情页，看到的将是一张
**带中文名的参数表**（间距百分比 / 每笔买入资金 / 成交模式 / 单边费率…），而不是空白。
**这是把「完全不知道」变成「打开就能看懂」的唯一直接手段。**

**怎么落**（两种，推荐 (b)）：

- **(a)** 前端把 `tpl.detail` 里的 manifest 结构随 `POST /api/strategies` 一起提交，落盘时写清单；
- **(b) ★推荐** 请求只带 `copy_from=<内置 id>`，后端 `catalog::find` 取出清单再写
  —— 清单的**唯一真相在后端**，前端不搬运一份可能失真的副本。

需要处理：把清单里的 `id` 改写成新策略名，其余字段照搬；`pair` 这类保留键（`RESERVED_PARAM_KEYS`，
`strategies.js:66`）不重复声明。

**关键纪律**：清单写失败**不能留下「有一半」的状态** —— 与现有 `.lua`/`.toml` 回滚同口径
（`ricow_engine/src/strategy.rs:123-136`），要么同一次事务、要么整次复制回滚。

**顺带收益**：详情页的「适用性卡片」（`renderFit`，`strategy_form.js:195-222`）读的也是清单，
会跟着亮起来 —— 用户顺手就知道了「这个策略适合什么行情」。

### 方案 2：从 Lua 静态提取参数骨架（对「裸脚本」兜底，不需要 AI）

**做什么**：新增一个**静态扫描**（与 `lint_lua` 同一类的行扫描，`strategy_io/mod.rs:355`），
从 Lua 源码里提取所有参数读取调用，得到 `{key, 推断类型, 兜底默认}` 列表。要覆盖的形态：

| 形态 | 例子 |
|:--|:--|
| 辅助函数 | `num(ctx, "spacing_pct", 0.01)` / `cfg_str(ctx, "accumulate_mode", "u")` |
| 直接调用 | `ctx:config_f64("k")` / `ctx:config_i64("k")` / `ctx:config_str("k")` / `ctx:config_bool("k")` |

（保留键 `pair` / `script` / `script_path` 跳过。）

**为什么**：
- 对**任何**策略（用户自己粘进来的、别处拷来的裸 `.lua`）都能立刻列出「它读了哪些参数、默认多少」；
- 与方案 1 **互补**：清单没带过来时（老策略、手写脚本），这一步照样能生成一份**参数骨架**；
- 它把「键名」——用户最不可能知道的字段——**自动填好**，用户只需补「中文名 / 说明」（或让 AI 补）。

**怎么落**：
- 后端一个**纯函数** `extract_param_hints(code) -> Vec<ParamHint>`，可单测（喂一段内置 Lua，
  断言键集合与默认值**完全一致**）；
- 前端在「未声明清单」的提示条（`sgDeclHint`）上挂按钮「**从脚本识别参数**」→ 调后端 →
  预填进清单编辑器（`addManifestRow`，`strategy_form.js:410`）→ 用户核对后「保存清单」；
- 进一步：**复制时自动跑一遍** —— 复制 + 自动提取 + 自动落一份清单，用户几乎无感。
  > **落地时没走这条**：方案 1 的 `copy_from` 已经把清单带过来了，"提取"只用于**源自己就没有清单**的兜底
  > （复制裸脚本时后端直接 400 并提示去副本页点识别，不自动编造清单）。自动落盘也和
  > 「默认值两处与清单不一致」的事实冲突 —— 自动写一份可能失真的清单，比不写更糟。

### 方案 3：把「AI 修改」扩成能改**配置**，不只改代码

**做什么**：让详情页的 AI 框能同时接受两类意图：

| 用户说 | 产出落到 | 是否动 Lua |
|:--|:--|:--|
| **调参数**（「间距改成 0.02」「初始建仓加到 100U」） | **参数表单**（写实例 TOML） | **不动** |
| **改逻辑**（「加一个跌破均线就清仓」） | Lua 编辑器（现状行为） | 动；必要时同时新增清单参数 |

**为什么**：这正是用户问的「AI 修改里面怎么帮用户修改配置」。当前 AI 只会改代码，
用户说「调参」它却去改代码 —— 是**意图误解**。

**怎么落**（两种粒度，建议从轻到重）：

- **轻**：`ai-edit` 请求体增加 `mode: "params" | "code"`；AI 卡上给两个示例 chip（「调参数」/「改逻辑」）。
  `mode=params` 时 prompt 改成「把用户的话翻译成 `{键: 值}` 的 JSON，键**只能**取下面这份清单里的 key」，
  返回 `{params: {...}}`，前端**预填参数表单**。**不落盘，用户点保存才写。**
- **重**：一次调用返回结构化 `{params?, manifest?, code?}`，三处表单各自刷新，用户核对后一次保存。

**必须守住的红线**（与现有产品纪律一致）：

- AI 产物**一律先落在表单/编辑器里当草稿**，用户点「保存」才落盘（现状 `ai-edit` 就是
  「全程不写任何文件」—— `strategy_io/mod.rs:799-801`，保持）；
- 键必须是**清单里真实存在的键**，不能让模型凭空编键去写实例 TOML —— 对话侧的 `update_params`
  工具描述里就写着「只有用户明确的键才写, 不要自行推断」（`ai/tools.rs:976`），这条纪律要延续；
- 若要新增参数（清单里没有），必须**明确提示「这是一个新参数，需要同时改 Lua 才能生效」**，
  不能偷偷写一个 Lua 根本不读的键。

### 方案 4：详情页把「配置」这件事讲清楚（体验收口）

- **空参数表单时给引导卡**：不要只丢一句红字（`sgDeclHint`），而是给
  「这个策略的参数还没整理出来」+ 两个按钮：**「从脚本自动识别参数」（方案 2）/「问 AI 怎么配」（方案 3）**。
- **「其他已保存参数」挂钩术语表**：原始键名旁用 `R.glossary` 兜一层解释（至少给个 tooltip），
  别让用户面对 `fee_side` 这种裸键。
  > **落地时改成加一句来源说明**（`sgOtherParamsHint`）：`/api/terms` 里**没有** `fee_side` /
  > `spacing_pct` 这类参数键，挂上去是个**空操作**（查不到术语 → 什么都不显示）；而"这些键来自实例
  > TOML、还没被清单声明"这件事才是用户看不懂的根源，所以改为直说来源 + 指向「从脚本识别参数」。
- **帮助抽屉补一步**：`GUIDE` 第 2 步（`help.js:71`）讲「先看适用/不适用场景」，
  可补一句「复制后参数表是照清单画的；没清单就用『从脚本识别参数』」。
  > **落地时是扩写第 2 步本身**（不是新增一步）：抽屉的纪律是「不复述后端能力清单」，步骤数也不该膨胀。

## 四、建议落地顺序与验收（可证伪）

| 序 | 做什么 | 验收标准 |
|:--|:--|:--|
| 1 | 方案 1：复制带清单 | 复制 `paired_grid` → 详情页参数卡片出现 **10 行**带中文名的参数（清单里除 `pair` 外的 10 个），而不是只剩交易对；`GET /api/strategies/{new}` 的 `declared=true`、`params` 非空 |
| 2 | 方案 2：静态提取参数键 | 喂 `paired_grid.lua`，断言提取出的**键集合** == 清单声明的键集合（差集为空）；**默认值不要求逐项相等** —— 已知两处代码与清单不一致：`min_pair_profit`（代码字面量 `0` / 清单 `0.002`）、`start_price`（代码字面量 `0` / 清单标 `required` 无默认），提取按**代码里的字面量**照实报告，不替任何一侧"对齐"；裸脚本点「从脚本识别参数」能预填 |
| 3 | 方案 3：AI 改配置 | `mode=params` + 「间距改成 0.02」→ 返回 `params.spacing_pct = 0.02`，**Lua 编辑器内容一字不变**（清单外的键必须被丢弃并回 warning，不是静默接受） |
| 4 | 方案 4：引导卡 | 未声明清单时详情页出现两个按钮，点「从脚本识别参数」能预填；点「问 AI 怎么配」—— 清单仍为空时只把用户推去走第一步（后端 `mode=params` 本来就 400），清单已就绪时聚焦 AI 卡并切到调参模式 |

## 五、明确不做

- **不引入前端构建链**（宪法「少而精」）。
- **不让 AI 直接落盘** —— 保持「草稿 → 用户点保存」的两段式。
- **不为「未声明的裸脚本」自动编造中文名 / 说明** —— 静态提取只负责
  **键 + 类型 + 默认值**这些**客观事实**；中文名与说明属于作者意图，要么用户填，要么 AI 生成后**由用户核对**。

## 六、落地情况（2026-10-11，变更 052）

四条方案**全部落地**，实现档案在 `specs/changes/052-webui-strategy-config/`。逐条对照：

| 方案 | 落点 | 与本文的差异 |
|:--|:--|:--|
| 1 复制带清单 | `POST /api/strategies` 的 `copy_from` + `strategy_io::derive_manifest`；前端「复制」与「模板新建」都带 | 落盘顺序 = **先清单 → 后 `write_strategy_files` → 失败则 `rollback_manifest`**；前端只在源 `declared` 时才带 `copy_from`（裸脚本源服务端会 400） |
| 2 静态提取 | `strategies/params.rs::extract_param_hints` + `POST /api/strategies/extract-params` + 清单编辑器「从脚本识别参数」 | **无状态**（吃编辑器里的草稿，不要求先保存）；已存在的键**不覆盖**；"复制时自动跑一遍"未做（见上文方案 2 说明） |
| 3 AI 改配置 | `ai-edit` 的 `mode:"params"` + `provider::quick_params` + AI 卡分段 chip | 缺省仍是 `code`（老前端不带该字段照常）；清单外键**丢弃 + warning**，全丢 → 400 `no_params` |
| 4 引导卡 | 参数卡里的 `#sg-params-guide`（判据 = `detail.params` 过滤保留键后为空） | 「问 AI 怎么配」在清单仍为空时**只引导去第一步**，不假装能直接问；「其他已保存参数」改为加来源说明而非挂术语表（见方案 4 说明） |

**附带订正**：本文 §四第 2 行的验收原写「默认值逐项相等」，**过强** —— `paired_grid` 有两处代码与清单
本就不一致（`min_pair_profit` / `start_price`），已按"提取照实报告代码里的字面量、不替任何一侧对齐"改写。

> 复制策略时，我们只把代码搬过去了，**把「这个策略有哪些参数、每个是干什么的」那张说明书落在了原地**。
> 所以打开就是一片空白。修法：复制时把说明书一起带走；实在没有说明书，就从代码里把参数名和默认值**自动扫出来**；
> 再让「AI 修改」听懂「调参数」和「改代码」是两件事。
