## 零、给决策层的三句话

1. **工程的"卫生"已经不是问题，产品的"闭环"才是问题。** 架构分层清晰、Time Frontier 无前视铁律、AI 工具层零落盘、5 条 grep 红线、三平台 CI——这套底盘在开源零售框架里属于第一梯队，不该再投工程基建的钱。
2. **真正的缺口只有一个根因：引擎没有状态权威。** `Engine` 是零字段无状态结构体（`crates/ricow_engine/src/command.rs:30`），订单/持仓/账户的权威全在交易所，`orders` 表只写不读。**交易系统的本质是状态管理，不是策略计算**——把状态层下放给非专业用户写的 Lua，是唯一需要从架构上重新决策的事。
3. **当前阶段的第一目标不是加功能，是收窄到"可用且不会让用户莫名亏损"。** roadmap P4 的验收口径就是这个，且差距清单里只剩一项未落码（P0-D 单笔名义上限）。建议把"扩品类"（多交易对、多交易所、tick 级回测）全部推迟到 P5。

## 一、需求解读：现有代码真正在承诺什么

### 1.1 产品承诺（三层，可信度递减）

| 层级 | 承诺 | 代码兑现度 | 判断 |
|:--|:--|:--|:--|
| L1 安全与可信 | 私钥不出本机、实盘三重确认、Dry Run 默认、遗留挂单接管即拒绝启动 | **高**。`live.rs:85-99` 双条件门、`ctrl.rs:7,23` 逐字短语、`api/risk-ack` 落盘、`command.rs:1172` 拉不到过滤器即拒绝盲下单 | 可对外宣称 |
| L2 策略工程化 | 编译门禁 → 沙箱回测 → preview → 一次性 token → deploy，AI 生成即验证、样本外切分、walk-forward | **高**。`ai/tools.rs` 零落盘由 CI 强制，`054` 已把"生成完不回测"这条最伤信任的洞补上 | 可对外宣称 |
| L3 让用户放心赚钱 | 回测→实盘一致性、风险可控 | **低**。基准口径、hedge 强平、部分成交建模、限价偏乐观、真实资金费率缺失，全是"回测好≠实盘好"的系统性来源 | **不可宣称** |

### 1.2 用户的真实任务流与断点

把 product.md 的工作流与代码对照，实际用户会在这几处卡住：

```
选策略 → 配参数 → 回测 → 看懂报告 → 样本外验 → 存参数 → Dry Run 24h → 实盘 → 盯盘 → 复盘
        ↑                                    ↑                    ↑
      ①参数从哪来                        ②报告能不能信          ③出事了怎么按停
      (AI生成已覆盖)                     (B3 只核最大回撤)      (无全局 kill switch)
```

- **断点①** 已由 054 大幅缓解（`risk_profile.rs` 档位落成数字 + 杠杆静态可验）。
- **断点②** 是当前**信任链最薄的一环**：`ai-assess` 只解读回测指标，不跑回测；B3 明确"只核最大回撤，单笔仓位/网格间距/杠杆上限不核"，理由是"回测指标里没有对应数字，凑出来就是编造实测值"。这是**正确的诚实**，但等于承认报告口径不足。
- **断点③** `stop --close-all` 需逐字确认，且多策略场景下无组合级敞口视图——用户同时跑 5 个策略时，看不到总名义。

### 2.3 一个必须诚实标注的"看起来是缺口、其实不是"

- `position_lots` / `virtual_positions` 已按 `(pair, side)` 分键，逐仓钱包也是 `HashMap<String, Decimal>`（`backtest.rs:247-258`）。**多交易对不是从零做**，缺的是把已有能力贯通到实例配置层与聚合层。这是好消息——工作量比差距清单暗示的小。
- 组合信号模式（`universe`）机制完整但**当前无内置消费者**（唯一消费者 `bs_momentum.lua` 已删）。这是"保留通用能力但没产品化"的典型半成品，需决定：要么补一个内置消费者证明其价值，要么明确标注为实验特性。

## 三、项目总监结论：范围、优先级与交付节奏

### 3.1 范围判断：把"不做"钉死，避免下一轮扩散

既有文档已明确不做：跟单/社交/策略市场、云端托管密钥、MCP、公网访问、多用户账号、GUI、多交易所 fallback、Hyperliquid、tick 级回测、无代码拖拽编辑器、LLM 直连下单、横截面选币。

**建议补充钉死三条（本次新增，均与代码事实对应）：**

1. **不做 tick 级回测 / intra-bar 价格路径**。backtest.md 已列为不集成，本次确认：`038` 的 intrabar fill fidelity 是"bar 内 open/high/low 先后"近似，不是真路径回放。别再被"回测严谨性"话题反复打开。
2. **不做真实历史资金费率**。需额外数据源，与"单一数据源、YAGNI"冲突。文档已有声明，建议在 UI 上也明示，避免用户拿回测杠杆收益当真。
3. **不做多交易所**。即使交易所故障，策略也应停机而非漂移——这个取舍比 fallback 更安全，写进帮助层。

### 3.2 优先级建议（与既有差距清单对齐，只调顺序不换方向）

| 档 | 内容 | 理由 | 判定 |
|:--|:--|:--|:--|
| **P0-A（做）** | 引擎级最小 OMS：在途订单表 + `client_order_id` 幂等 + 状态机最小态（submitted/partial/filled/canceled/rejected） | 直接服务 P4 验收口径；是 G1 的最小充分解 | 立项 |
| **P0-B（做）** | 组合级敞口只读视图 + 一键 kill switch | 破窗效应最小的解法：只读视图不碰投资判断，kill switch 是操作层不是投资层 | 立项 |
| **P0-D（拍板）** | 单笔名义上限 | **这是宪法级决策，不是工程决策**。D15/D17 明确删了平台级风控。可选：ⓐ 维持现状 ⓑ 固定常量引擎级上限（不落配置）ⓒ 显式修订宪法开受控风险参数面 | ✅ **已于 2026-10-18 拍板取 ⓑ 并落码**（057-P0-D，`NOTIONAL_LIMIT_MULTIPLE = 10`） |
| **P1（做）** | 前端静态门 + CDP 走查进 CI；下单改异步（解 G2） | G2 与"100ms 事件驱动"宣传存在张力，属宣传口径风险 | 前端门禁部分 ✅ 已落码（057-G6，`ci.yml` frontend job +新建 `nightly.yml`）；下单异步（G2）仍**未做** |
| **P2（缓）** | 四个超限文件拆分 | 无外部症状，属可维护性；`strategy_io/mod.rs` 已有 13 章节注释，拆分意图最清晰，可作为拆分模板 | 排期 |
| **不做** | 多交易对、多交易所、tick 回测、GUI、MCP、参数自动寻优 | 宪法已判 | 关 |

### 3.3 关于 roadmap 两个悬而未决项（roadmap「下一步」清单）

- **第 8 项 策略门禁覆盖面收口**：`catalog::run_block` 只有 4 个调用点，公共汇聚点 `ctrl::start_daemon` 自身无闸、被 7 处调用——对话里让 AI "启动 X" 照样能起未声明副本。**且收口必须与 `restart` 绑定**：`restart` 是先 stop 后 start，闸只加 start 会出现"实例被停掉、没起来"（可能带未平仓敞口）。这是一个**要么做全套、要么不做半套**的项，建议与 P0-A 同批做。
- **第 9 项 P0-D**：见上表，等拍板。

## 四、优化计划（分四波，建议按波交付）

### Wave 1 — 状态权威（对应 G1 + roadmap 第 8 项）
**目标**：让引擎第一次持有权威状态。
- 引擎侧新增最小 OMS：in-flight 表 + 幂等去重 + 5 态状态机最小闭环
- `orders` 表从"只写不读"升级为可作对账基准
- 启动闸收口：`start_daemon` 统一门禁 + `restart` 先判后停，两处绑定
- **验收**：① 重复 `client_order_id` 只产生一笔 ② 网关断连后 in-flight 状态可恢复 ③ 未声明副本经对话启动被拒 ④ `restart` 不会留下"停掉没起来"的实例
- **风险**：DB schema 迁移 + 旧库兼容；建议新增表而非改 `orders`

### Wave 2 — 操作安全层（对应 G3/G4 + P0-Dⓑ）
**目标**：多策略场景下用户按得住。
- 组合级敞口**只读**聚合视图（名义、持仓方向、净盈亏、按策略拆分）——不设限、不告警、不拦单
- 全局 kill switch：一次动作停全部实例（复用 `supervisor` 已有 `stop_all`），并给 `--close-all` 一个更短路径
- 单笔名义上限：取 ⓑ 方案 = 固定常量、不进配置面，出厂值偏保守，超限**拒单并明确报错**
- **验收**：① 5 个策略并发时总名义正确 ② kill switch 后无残留子进程 ③ 超限单被拒且理由清楚 ④ **这三条都不得被解读为"平台替用户做投资判断"**——文档措辞要钉死

### Wave 3 — 事件循环与前端门禁（对应 G2/G6）
**目标**：让宣传口径与实现对齐，并让静态门能进 CI。
- 下单改异步提交 + 结果经用户流/轮询回收，解 `block_in_place` 阻塞
- `web_frontend_check.mjs` 进 CI（Node 运行时已在 Windows/macOS/Ubuntu matrix 上存在，额外成本低）
- `probe_web_ui.mjs` 至少进 nightly，保留"四道静态门抓不到"这一层的存在理由
- **验收**：① 事件循环 P99 延迟不再被 REST 往返拉长 ② 故意注入一个 TDZ 缺陷能被门抓到

### Wave 4 — 可维护性（对应 G7，非阻塞发布）
- 以 `strategy_io/mod.rs` 的 13 章节为模板拆 `backtest.rs` 两个 impl 块、`command.rs` 14 个自由函数按职责分文件
- 目标不是"文件变小"，而是**让"事件循环里混了几个横切关注点"这件事在目录结构上可见**
- **不做**：顺手重构、跨文件改命名。宪法已定"不顺手重构"。

## 六、刻意不做的事（写下来免得下一个人当 bug 修）

1. **不重开 tick 级回测、真实资金费率、多交易所、GUI、MCP、参数自动寻优**——宪法与 backtest.md 已判。
2. **不改"平台不做投资风控"**——本计划所有新增都限定在**操作层**（幂等、撤单、kill switch、名义上限），策略/政策层（最大回撤、仓位政策）继续由策略自管。
3. **不做 `cargo-udeps`/覆盖率/bench 门禁**（035 已显式记录未做），除非 CI 已经慢到影响交付。
4. **不改单交易对的三层绑定**（若第 5 项拍板为"不做"），即使内部 map 已 pair-keyed。
5. **不把 `/favicon.ico` 404 当缺陷**（051 起遗留，CDP 记 NOTE）。
6. **不为传 reqwest 超时升级依赖**（依赖树里两个 0.12/0.13，用 `tokio::time::timeout` 等价覆盖，054 已定）。
7. **超时不自动重试**（一次 300s，重试三遍十几分钟）。
